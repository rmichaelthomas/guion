02 / An ambitious question
Another language?
Only if it earns its place.


New syntax alone isn't enough. The question Guion is built around is practical: when should someone confidently choose it to do real work?


North-star question: when should a builder, or an assistant advising one, pick this over Python for real work? The first release has to say honestly where Python is still better.






    

  1. 

    

    Readable without guessing.
    

    You say what kind of thing a type each function takes and gives back. Everything inside it is worked out for you. You can read a Guion program and know what goes in and what comes out.
    

    Typed function boundaries, inferred locals. Option[T] for absence, Result[T, E] for recoverable failure, ? to propagate. Records, lists, maps, modules, bounded JSON, files, SQLite, TOML, HTTP.
    

    

    Margin note
    “Plain English” is the goal for learning and diagnostics. Free-form natural-language code is not the claim. Authority: language/spec.md.
    

    2. 

  2. 

    

    More than a language.
    

    One command makes a project, checks it, tidies it, tests it, runs it, packs it up, and tells you what it can do. A person, or an assistant, can ask for a report instead of text.
    

    20 subcommands in one binary. --json on check, lint, test, run, build, package, verify-package, inspect, doc, doctor and sync returns a versioned report with stable fields and codes.
    

    

    Margin note
    Report kinds and schemas are indexed in docs/agents/index.json; the table in section 03 lists each one.
    

    3. 

  3. 

    

    A claim should survive contact.
    

    Every number on this page says which program it measured, on which machine, and what it does not tell you. Then it points at the file it came from, so you can check.
    

    11 receipts, each with workload, host, interval, scope limit, and linked report and raw-sample files. A build step fails if a figure on this page is not in the file it cites.
    

    

    Margin note
    Files are copied byte for byte to the evidence page with their SHA-256.
    

    4. 












03 / The apparatus
One command.
The whole job.


Most languages leave you to put the tools together yourself. Guion ships one program that walks the whole path, from an empty folder to something you can hand to someone else.


20 subcommands behind one binary. Core commands never discover or launch Python or uv.






    

  1. guion newStart.Makes a small project: a program, a test, and a manifest.
    2. 

  2. guion checkCheck.Reads your code and says what is wrong, with the line and a code that stays the same.
    3. 

  3. guion testTest.Runs every test, each one from a fresh start.
    4. 

  4. guion runRun.Runs it. Add --json and an assistant gets a report instead of text.
    5. 

  5. guion buildBuild.Turns it into one portable file with a recorded fingerprint.
    6. 

  6. guion packageHand over.Packs the program and the runtime it needs into a folder.
    7. 



Also: fmt tidies spacing · lint flags unused code · inspect shows what a program can do · doc lists what it offers · doctor checks the machine · verify-package, install, add, sync and update handle delivery and dependencies · add NAME fetches a library from the Guion package registry after checking its hashes, and publish and yank put one there or withdraw it.

04 / Code you can inspect
Read it.
Then change it.


Real programs from the project's own examples, with what each one prints. Press the button under any of them to load it into the playground and change it.


Sources are the files in language/examples. Output, artifact size and step count were produced by compiling and running each one when this page was built.


















hello.gu
fn main() -> Int:
    let greeting = "Hello, Guion!"
    print(greeting)
    return 0

Prints Hello, Guion!





Every program starts at main. This one names a greeting, prints it, and returns 0 to say it went fine.


fn main() -> Int is the entry point and its return value is the exit status. let binds immutably; print writes one line. 342 artifact bytes · 6 steps









option.gu
fn maybe_positive(value: Int) -> Option[Int]:
    if value > 0:
        return Some(value)
    return None

fn main() -> Int:
    let absent = maybe_positive(-5)
    let present = maybe_positive(24)
    if is_some(absent):
        print(unwrap(absent))
    if is_some(present):
        print(unwrap(present))
    return 0

Prints 24





A function that might have no answer says so in its type, and returns None when it has none. The program checks before it uses the answer, so the empty case is out in the open.


Option[Int] is built with Some(value) or None; is_some tests for presence and unwrap is for after that test. Only the present value prints. 1439 artifact bytes · 32 steps


Absence is a value
A function that can come back empty says so in its type, so the reader knows to check.









records.gu
record Point:
    x: Int
    y: Int

fn translate(point: Point, dx: Int, dy: Int) -> Point:
    return Point(point.x + dx, point.y + dy)

fn main() -> Int:
    let start = Point(3, 4)
    let finish = translate(start, 2, -1)
    assert(finish == Point(5, 3))
    print(finish.x)
    print(finish.y)
    return 0

Prints 5
3





A record is a named bundle of typed fields. This one moves a point two across and one down, then checks the result against what it should be.


record Point has two Int fields; translate returns a new Point; assert(finish == Point(5, 3)) compares the result to the expected record. 1601 artifact bytes · 35 steps


















05 / Permissions, not a sandbox
A program says what it wants.
You decide.


Before a Guion program runs, you can ask what it is able to do: read files, reach a website, check the clock. When it runs, it gets only what you grant. Everything else is refused.


Static reachability of host effects, read from bytecode. Grants are explicit and enforced by the runtime. This is not an OS-level sandbox.






















By default a program can print, and read and write files inside its own project. The network and the clock are refused. Before it runs, check and inspect say plainly if it can write files.


guion run main.gu · no [network].hosts, so network.http is denied; [clock].enabled is false, so clock.read is denied.






You hand it one more folder. It can read from there, and anything it writes goes there.


guion run --file-root ./data main.gu · reads search the project or artifact root first, then added roots; writes use the last added root.






You name one website, exactly. The program can make web requests to that host and no other.


[network] hosts = ["api.example.test"] in guion.toml, or guion run --allow-http-host api.example.test for one run. The runtime checks the URL host and each redirect against the grants.






You switch the clock on. Then the program can ask what day it is.


[clock] enabled = true in guion.toml, or guion run --allow-clock. Local dates use the host process time zone.








Watch a refusal


The playground grants nothing. Ask it for a file and you will see exactly what a refusal looks like.









What guion inspect --json main.gu prints, before anything runs




main.gu
fn main() -> Int:
    let args_list = args()
    let headers: Map[Text, Text] = {}
    match read_text("notes.txt"):
        Ok(text):
            print(text)
        Err(problem):
            print(file_error_code(problem))
    match http_request_bytes("GET", args_list[0], headers, bytes_from_text(""), 1000):
        Ok(response):
            print("fetched")
        Err(problem):
            print(http_error_code(problem))
    return 0

Why this is not a sandbox

Permissions decide what the Guion runtime will do for a program. They do not stand in for an operating system's own limits. A host that needs to contain a program still has to do that itself, for example by limiting its network access. The report says so in its own fields: capability_claim is static_bytecode_reachability_not_sandbox.

07 / The other side
Where Python
still leads.


Python is mature and widely used. Here is where it is still ahead today.


Open gaps and the remaining counter-evidence.








Libraries and packages
Python has hundreds of thousands of packages and decades of libraries behind it. Guion ships 17 standard-library modules and a package manager that installs from a local path or a checksummed URL. It has no public package registry yet.
The standard-library modules are listed in the language reference.


Arrays and data science
NumPy and pandas make Python the default for numeric and data work. Guion does not have a native array type yet.
Earlier tests that reached NumPy through Python are retired and no longer cited.


A release you can use

09 / The origin
The reason
before the name.


Guion began with a north-star question: could a new general-purpose language earn a recommendation over Python for real work, through the whole experience of writing, checking, running, delivering and maintaining a program?








The name


Guion, said GUY-on.


The language is named for Guion “Guy” Bluford, the aerospace engineer, Air Force pilot and NASA astronaut who became the first African American to fly in space. The name honours what he did.


It was also chosen for its sound. Said aloud, Guion sounds like the name of a subatomic particle, alongside the muon, the gluon and the quark.


Recorded in docs/namesake.md, from the project's architect and NASA's records.






The name, and who it honours




Claim
Guion is named for Guion S. “Guy” Bluford Jr. On August 30, 1983, aboard Challenger on STS-8, he became the first African American to fly in space. He flew four shuttle missions and logged over 688 hours in space.


Holds when
The naming is recorded from the project's architect. The record of his flights and career comes from NASA's biographical data and NASA's article on his first flight.


Doesn't tell you
How NASA says his name. NASA confirms he goes by “Guy”; “GUY-on” is the project's own pronunciation, not a NASA record.
