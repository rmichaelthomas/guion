01 / An ambitious question

Another language?
Only if it earns its place.

New syntax alone isn't enough. Guion's north star is practical: when should someone confidently choose this language to accomplish actual work?

01 / EXPERIENCE
A
Readable without guessing.

Structured, typed syntax with inferred locals and explicit boundaries. Understandable is the goal; free-form natural-language code is not the claim.

Annotation / Type system

Express intent. Check boundaries.

Guion requires types at function boundaries while inferring local binding types. Its current contract includes records, collections, Option and Result. “Plain English” describes the learning ambition, not an English-sentence parser.

Annotation / Developer experience

Less toolchain archaeology.

Guion's CLI groups creation, checking, formatting, linting, running, testing, packaging, and inspection in one place. It does not imply that Python lacks good tools or that Guion wins every comparison.

Annotation / Verification

Scope matters.

The project's pre-release checks and benchmarks are meaningful within their tested targets and tasks. They do not establish broad language superiority, cross-platform support, or a completed public release.

fn maybe_positive(value: Int) -> Option[Int]:
    if value > 0:
        return Some(value)
    return None

fn main() -> Int:
    let absent = maybe_positive(-5)
    let present = maybe_positive(24)
    if is_some(absent):
        print(unwrap(absent))
    if is_some(present):
        print(unwrap(present))
    return 0

records.gu · typed structure

language/examples/records.gu UTF-8
record Point:
    x: Int
    y: Int

fn translate(point: Point, dx: Int, dy: Int) -> Point:
    return Point(point.x + dx, point.y + dy)

fn main() -> Int:
    let start = Point(3, 4)
    let finish = translate(start, 2, -1)
    assert(finish == Point(5, 3))
    print(finish.x)
    print(finish.y)
    return 0

THE CLI

From an idea to a program.

development workflow
guion new hello-guion
guion check hello-guion/src/main.gu
guion test hello-guion/src/main.gu
guion run hello-guion

Requires Guion installed. While the project is private, building from its checkout requires Rust and Cargo.

A design decisionAbilities should be explicit, not assumed.

Network, files, and clock operations require stated permissions. Guion treats the host boundary as part of understanding what a program does.

Annotation / Host API

Permissions, not a sandbox.

The current Guion runtime uses explicit access grants, including allowed network hosts, file roots, and clock access. The project's docs stress that this is not an OS-level sandbox. Precise permission contracts belong to the language specification.

04 / The origin

The reason
before the name.

Guion began with a north-star question: could a new general-purpose language earn a recommendation over Python for real work—through the full experience of writing, checking, running, delivering and maintaining a program?

22 OCT 2026

The north-star was documented.

The original design, under the working name Veritas, put usability, toolchain coherence, honest comparison and executable evidence at the center.

25 OCT 2026

Guion takes its name.

The pre-release implementation and active tooling were migrated to Guion; the Veritas-era results remain preserved under their historical name.

26 OCT 2026

Results, with boundaries.

The current repository records target validation and workload-specific performance comparisons. It still describes Guion as private pre-release.

The project's own challenge

Worth choosing.
