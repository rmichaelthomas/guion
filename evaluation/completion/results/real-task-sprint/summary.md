# Real-task and runtime sprint — macOS ARM64

## Current-format managed package for the 100,000-row analysis — 2026-10-27

The real NumPy/orjson analysis passed as a format-44, source-free managed package on macOS ARM64. Its 100,000-row output matched the independent Python reference byte-for-byte after relocation to a path with spaces and Unicode; two launches worked with external Python and uv settings removed. Guion package assembly can now seed the portable offline wheel cache from an explicitly selected preloaded cache. The expanded bundle measured 157,585,367 bytes (150.3 MiB), including a 68,119,333-byte CPython runtime and 27,172,671-byte uv cache. This is a packaging result, not a speed win. Debian 12 ARM64 also passed the same named analysis gate; its 244,199,858-byte directory and detailed results are recorded in the [Debian ARM64 report](2026-10-27-current-format-managed-package-analysis-debian-aarch64.md) and [raw result](2026-10-27-current-format-managed-package-analysis-debian-aarch64.json). See the [macOS plain-English report](2026-10-27-current-format-managed-package-analysis.md), [macOS raw result](2026-10-27-current-format-managed-package-analysis.json), and [reproducible runner](../../performance/verify_managed_package_analysis.py).

The source baseline is the shared VM-core merge `9d57434`. Results below compare the named implementations on one Apple Silicon Mac using CPython 3.14.7. A fresh Guion run bypasses Guion's source cache; the operating-system file cache was not controlled.

## Richards

In the original post-VM-core cohort, Guion's fresh source took a median **45.67 ms** versus **70.16 ms** for Python (ratio **0.653**, 95% interval **0.649–0.656**); the 0.60 target was not reached in that build. That cohort is historical. The current-main measurement below supersedes it.

The change groups the small integer-list descriptors used by generated code into fixed-capacity chunks. Existing list values keep stable addresses and copy-on-write semantics. Comparing the same two binaries across 25 Richards executions per process, the new/old median ratio was **0.873**, about **12.7% less time** (95% interval 0.859–0.881). That controlled change supports the conclusion that allocation of small list descriptors is a material runtime cost; it does not measure branch-misprediction costs. [Repeated-run result](richards-repeated-final.json).

The median peak RSS increased **1.5%** for fresh source and **0.5%** for the 25-execution lane, both under the 5% guard. All five established short-source Python comparisons passed for the final binary. [Memory](richards-final.json) and [short-source samples](short-source-final.json).

## AllHereHTML and text

The pinned Guion AllHereHTML builder passes its 19 tests, reproduces the expected page byte-for-byte, and preserves the old output when the template is missing or contains a script. It is now a CI regression. Before the text change, splitting a long line and joining a roughly doubled page exhausted the default cumulative allocation budget. Guion now combines text pieces in balanced groups. The same long-line and many-field regression passes with Unicode and empty fields, and the original site still matches its expected output.

For the original site, separately instrumented runs recorded estimated guest allocation-budget charges of **121.6 MB before** and **66.3 MB after**, a reduction of about **45.5%**. These are Guion accounting estimates, not measured physical allocations or RSS. A scaling run on the optimized build generated and checked 42 KB, 85 KB, and 170 KB templates in median fresh-source times of approximately **0.34 s, 0.65 s, and 1.28 s**, respectively. [Profile counters](allhere-runtime-profile.json) and [scaling samples](allherehtml-scaling-final.json).

A later runtime follow-up cached immutable ASCII scalar text values. Against the immediately preceding build, the 20,000-row JSONL workload improved from **364.5 ms to 352.8 ms** (paired ratio 0.969; 95% interval 0.967–0.971; seven of seven pairs faster), and AllHereHTML improved by **1.9–2.1%** across the same three input sizes. The complete application acceptance rerun passed **127/127 cases** in both Guion and Python. The detailed [ASCII scalar report](../runtime-efficiency/2026-10-27-ascii-text-scalar-cache.md) includes direct nine-task comparisons and limitations.

A map update follow-up avoids rebuilding the stored string key when `map_set` replaces an existing value. In a nine-app direct comparison, release-notes improved by **4.6%** (paired ratio 0.954; 95% interval 0.926–0.984; seven of seven wins), while the other app results—including the 20,000-row JSONL workload—showed no reliable change. Every run passed its output check, and all **127/127** acceptance cases passed for both implementations. A fresh post-commit comparison remained faster than Python on all nine selected cases (Guion/Python ratios **0.136–0.837**). Three fresh agent evaluations again chose Guion (**3/3**), unchanged at the maximum score. See the [map-key report](../runtime-efficiency/2026-10-27-map-key-reuse.md), [post-commit timings](2026-10-27-map-key-reuse-postcommit-nine-task-python-comparison.json), and [preference-study summary](agent-choice/summary.json).

A shared text-library fast path checks a one-scalar delimiter directly. The selected release-notes case improved by **2.8%** (15 paired trials; 95% interval 0.923–0.974), while document-index and JSONL control cases showed no reliable change. The existing Unicode, empty-input, and trailing-field behavior remains covered. See the [text delimiter report](../runtime-efficiency/2026-10-27-text-split-single-scalar-fast-path.md) and [full measurements](2026-10-27-text-split-single-scalar-head-to-head.json).

## Large JSONL and parser follow-up

The current pre-change build processed 200,000 JSONL rows in a randomized 16-trial cohort: uncached Guion source took **3.80 s**, compared with **17.45 s** for the Python data reference and **17.63 s** for Python with native SQLite. Guion's uncached-source/Python ratio was **0.218** (95% interval 0.215–0.221), about **4.6× faster** on this workload. Peak RSS was **13.75 MiB** for uncached Guion source, **12.44 MiB** for the artifact, **74.20 MiB** for Python, and **83.31 MiB** for Python/SQLite. The source compile phase was about 5 ms; execution dominated. See the [full baseline report](../runtime-efficiency/2026-10-27-jsonl-200k-current-build.json).

The JSON parser then replaced its per-document reference-counted duplicate-key tracker with stack-owned state. At 20,000 rows the screen was inconclusive. At 200,000 rows, 16 randomized output-checked pairs showed a **0.65%** improvement (candidate/baseline **0.994**, 95% interval **0.987–0.998**), with peak RSS essentially unchanged at 13.59 versus 13.53 MiB. The preceding build was about **4.6× faster** than the named Python data reference; this candidate improved on that build by the measured 0.65%. The guest profile showed no list copying; its allocation values are VM budget estimates and do not identify host CPU stacks. Runtime verification passed all **180** package tests, formatting, and the release build. See the [plain-English parser report](../runtime-efficiency/2026-10-27-json-duplicate-tracker.md), [20k screen](../runtime-efficiency/2026-10-27-json-duplicate-tracker-20k-screen.json), and [200k confirmation](../runtime-efficiency/2026-10-27-json-duplicate-tracker-200k-confirmation.json).

A Unicode whitespace no-op fast path was then measured against the preceding release build. The 20,000-row screen was inconclusive; the 200,000-row 16-pair confirmation measured a **0.7%** lower candidate/baseline median, with a 95% interval of **0.979–1.0002**, so it does not establish a latency improvement. One guest profile estimated **0.36%** fewer allocation-budget charges; these counters do not measure physical allocations or RSS. Every timed result matched the Python oracle, all **11/11** JSONL acceptance cases passed for both implementations, the runtime suite passed **181** tests, formatting passed, and the release CLI built. See the [plain-English fast-path report](../runtime-efficiency/2026-10-27-json-whitespace-fast-path.md), [200k timing confirmation](../runtime-efficiency/2026-10-27-json-whitespace-fast-path-200k-confirmation.json), and [guest profile](../runtime-efficiency/2026-10-27-json-whitespace-fast-path-200k-guest-profile.json).

A direct shared-tree parser now deserializes JSON into Guion's immutable JSON representation in one pass, avoiding the intermediate `serde_json::Value` tree. In two separate 16-pair confirmation cohorts on 200,000 JSONL rows, the combined paired median ratio was **0.9885** (95% interval **0.9779–0.9994**), about **1.2% less time**; all 32 paired candidate and baseline outputs matched the independent Python-generated result. One guest profile estimated **2.1%** fewer allocation-budget charges, while five output-checked peak-RSS samples per build showed only a small, overlapping difference (14.29 MB baseline, 14.22 MB candidate). All **184** runtime tests passed, and Guion passed **127/127** frozen application cases. The Python reference passed **116/127**: its 11 calendar failures were caused by the missing pinned `icalendar` dependency in the current environment. See the [plain-English parser report](../runtime-efficiency/2026-10-27-json-shared-tree-parser.md), [full evidence](../runtime-efficiency/2026-10-27-jsonl-runtime-follow-ups.json), and [full acceptance record](2026-10-27-json-shared-tree-nine-task-acceptance.json).

## Lockfile scale and everyday follow-up

After PR #11, the lockfile auditor passes all **17 frozen cases** in both Guion and Python and produces exact output through **16,384 packages / 32,768 diagnostics**. Seven randomized, output-checked fresh-source pairs measured 4,096 packages at **56.35 ms vs. 117.45 ms** (Guion/Python **0.479×**), 8,192 at **95.29 ms vs. 137.88 ms** (**0.692×**), and 16,384 at **171.82 ms vs. 179.87 ms** (**0.948×**, 95% interval **0.942–0.975**). At the largest size Guion used **40.92 MiB** peak RSS versus Python's **47.13 MiB**, about **13% less**, and took about **5% less time**. Compared with the previous committed implementation, the 16,384-package run took about **30% less time**. This closes the lockfile scale, speed, and RAM gap for this workload on this Mac; it does not establish a general speed or memory advantage. See the [latest lockfile scale and RAM report](2026-10-27-lockfile-scale-ram-package-limit.md) and its [raw timing and memory data](2026-10-27-lockfile-native-pair-serialization.json). The last completed agent-choice study predates this lockfile implementation and chose **Guion (3/3)**; this build did not rerun that study.

Health-digest's representative timing looked closest to parity, but its frozen fixture waits for a 700 ms endpoint until a 500 ms timeout. A seven-pair fast-response diagnostic that removed that delay measured **33.8 ms for Guion** and **127.7 ms for Python** (ratio **0.260**, 95% interval **0.256–0.305**). The near-parity frozen timing was therefore driven by the network wait. Calendar-conflicts also includes fixed endpoint delays. A new scale test reduced those waits while retaining concurrency checks and found a large-feed optimization opportunity.

## Calendar scale

After commit `214bdb8`, calendar-conflicts passed all **11 cases and 40 checks** for both implementations. On three disjoint feeds with 4,500 events each, seven randomized pairs measured **316.1 ms for Guion** and **11.957 s for Python** (ratio **0.0264**, 95% interval **0.0243–0.0266**). A 5,000-event default-budget probe reached `R_STEP_LIMIT`. The follow-up on commit `ede8ad2` simplified the interleaved overlap scan and gave this project an explicit **10,000,000-instruction** budget while leaving Guion's global default at 2,000,000. It passed interleaved workloads through **8,000 events per calendar** (24,000 total); at 8,000 the three paired trials measured **1.230 s for Guion** versus **37.671 s for Python** (about **30.3× faster**, 95% interval for the ratio **0.0324–0.0331**). These results are specific to synthetic calendar cases, not a general language-speed claim. See the [interleaved scale report](2026-10-27-calendar-interleaved-scale.md), [4,000](2026-10-27-calendar-interleaved-4000.json), [6,000](2026-10-27-calendar-interleaved-6000.json), [8,000](2026-10-27-calendar-interleaved-8000.json), and the [default-budget boundary probe](2026-10-27-calendar-interleaved-4000-default-budget-boundary.json).

One earlier post-commit agent-preference attempt stopped before acceptance or a language choice because its local `goals_1.sqlite` database could not be opened. This is a historical incomplete study, not a blocker for current-main implementation or performance work. The latest completed exploratory result remains **3/3 for Guion**; no newer preference result is claimed.

## Interpretation

These are meaningful gains on named programs and conditions. They do not establish that Guion is faster than Python on arbitrary tasks, that the Python alternatives are individually optimized, or that agents generally will choose Guion.
