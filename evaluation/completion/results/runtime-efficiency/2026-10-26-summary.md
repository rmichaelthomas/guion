# Guion runtime efficiency pass — 2026-10-26

- **Host:** macOS ARM64
- **Python:** CPython 3.14.7, GIL enabled
- **Baseline:** merged CLI from `791b4a60020e7760efc6ff74bd5dc2f9cf58e469`
- **Candidate:** same CLI plus the runtime map-update optimization described below
- **Reports:** [baseline](2026-10-26-baseline.json), [candidate](2026-10-26-candidate.json), [five short-source gates](2026-10-26-first-source.json)

## What changed

When bytecode updates a mutable local with `map_set` on that same map, the runtime can now release the temporary map reference before copy-on-write. If the local is the only owner, it updates the existing map instead of cloning it. If another value still shares the map, copy-on-write still clones it, preserving the other value. Text, collection, and allocation limits remain enforced.

The change is in the Rust runtime; it does not change the source language, bytecode format, CLI permissions, or artifact format.

The source-time change is clearest on JSONL. At 20k rows, the candidate/baseline uncached-source median ratio is 0.949, with an independent-sample bootstrap 95% interval of [0.938, 0.966]. At 200k rows it is 0.968 [0.941, 0.983], equivalent to a 3.2% median reduction, with the interval indicating a 1.7%–5.9% reduction. These intervals resample each cohort's 16 raw samples independently (20,000 bootstrap resamples; seed `20261026`). They are not paired before/after measurements.

At 200k rows, the prebuilt-artifact median moved from 4.247 s to 4.030 s (5.1% lower). Candidate uncached source measured 0.229× Python, or about 4.4× faster on this task. Phase telemetry attributes about 4.0 seconds to program execution and about 4.1 milliseconds to Rust compilation; runtime work dominates. The code change therefore improves the runtime path rather than reducing compilation time.

## Memory and measurement limits

The 200k direct-child peak-RSS observation was 13.45 MiB before and 13.55 MiB after for uncached source, and 12.17 MiB before versus 12.16 MiB after for the artifact. This change has no demonstrated peak-memory reduction. RSS is from `resource.getrusage(RUSAGE_CHILDREN).ru_maxrss` on macOS (bytes), sampled in untimed runs. It describes the direct child process; the process-pool report lists worker peaks and their sum as an upper bound.

Guion's `--no-cache` bypasses only Guion's source compilation cache. OS file-cache conditions were not controlled, so these are warm/unspecified filesystem-cache observations, not cold-disk claims. All speed results apply to the named workloads, macOS ARM64, and CPython 3.14.7 only. They do not show that Guion generally outperforms or replaces Python. Free-threaded Python was not available for this cohort.
