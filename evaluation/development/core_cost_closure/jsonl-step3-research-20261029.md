# JSONL speed gap: step-3 research and implementation decision

State: research complete; proposed implementation sequence, not a measured speedup. Repository HEAD at review: `c744171` (`codex/guion-core-sprint-spec`). The [cost ledger](jsonl-cost-ledger-20261029.md) contains the frozen measurements and their overhead limits. No production change is made by this document.

## What the evidence actually says

The final 200k artifact median is 2.651506 s for Guion versus 0.734498 s for the pinned Python reference, a 1.917008 s gap. The diagnostic partition assigns 1.912 s to the VM instruction body and 0.773 s to host operations, with 8.9% paired median instrumentation overhead. Actual heap interposition observes 29.09 million allocation/reallocation calls per process, and CPU sampling places at least 12.6% of samples directly in libc malloc/free/realloc. The detailed profile records 196,241 JSON copy-on-write updates. These are different kinds of evidence; their shares cannot be added.

There is also a workload mismatch below the output contract. [Guion's baseline](../core_north_star_sprint/profile-inputs/jsonl-summary-baseline.gu) keeps nested `Map[Text, Map[Text, Json]]` aggregate state and repeatedly reads JSON fields and replaces JSON objects. [Python's reference](../../completion/performance/data_reference.py) first materializes accepted rows, then updates a mutable three-item list in a native dictionary. The output is equivalent, while the intermediate work is not. The Python materialization has its own cost; this observation does not invalidate the benchmark. It does mean a whole-language defect cannot be inferred from this one ratio.

## Code-level causal map

1. **Shared JSON updates.** `crates/model/src/lib.rs` stores JSON objects as `Arc<BTreeMap<String, Arc<SharedJson>>>`. `SharedJson::as_object_mut` uses `Arc::make_mut`. `crates/runtime/src/lib.rs` implements `JsonSetLocal` with `Arc::make_mut(object).as_object_mut().insert(...)`. In the workload, `previous` and `updated` coexist, so the JSON object remains shared when updated; the profiler's copy-on-write counter corroborates this. Rust's [`Arc::make_mut` contract](https://doc.rust-lang.org/std/sync/struct.Arc.html#method.make_mut) explicitly clones shared contents before mutation. The likely causal chain is an extra object/map copy and allocation on nearly every accepted-row update. The exact time share is unmeasured.
2. **VM values and wrappers.** `crates/model/src/lib.rs` derives `Clone` for `Value`; `OptionSome`, `ResultOk`, and `ResultErr` hold `Box<Value>`. `crates/vm-core/src/lib.rs` clones values on `Load` and `Const`, charges their logical allocations, checks fuel and cancellation in the interpreter loop, and repeatedly pushes/pops `Value`. The detailed profile counts 17.82 million `Load`, 4.75 million `Const`, 1.59 million `IsOk`, and 3.56 million `Unwrap` executions. CPU samples land in the VM loop, `Value` clone/drop, stack operations, and allocator. This supports an allocation/value-traffic target; it does not assign the 29.09 million heap calls to individual opcodes.
3. **Native boundary.** The measured JSONL functions compile to zero native calls; native eligibility rejects `IsOk` and typed JSON/Result operations. Prior isolated direct-variant and bridge candidates failed the paired smoke gate and were reverted ([sprint progress](sprint-progress.md)). Repeating per-operation bridges is a poor first bet for this workload. A new execution tier must keep the common chain inside the same compiled function and reconstruct exact VM state on rare exits.

## What other language implementations teach

| Precedent | Verified technique | Guion application | Limit or risk |
| --- | --- | --- | --- |
| [CPython PEP 659](https://peps.python.org/pep-0659/) and [interpreter documentation](https://github.com/python/cpython/blob/main/InternalDocs/interpreter.md) | Specialized bytecodes and inline caches reduce generic lookup/call cost; a preallocated evaluation stack and lean frames reduce overhead. | Specialize a stable JSON/Result/Option path and common load/branch sequences, with fallback to the existing VM. | CPython's published gains cannot be transferred as a Guion speedup estimate. Guion's measured frame creation is only 31.8 ms, so copying its frame strategy alone cannot close this gap. |
| [Graal/Truffle partial evaluation](https://www.graalvm.org/dev/graalvm-as-a-platform/language-implementation-framework/PartialEvaluation/) and [HotSpot escape analysis](https://docs.oracle.com/en/java/javase/17/vm/java-hotspot-virtual-machine-performance-enhancements.html) | Keep short-lived state in registers/scalars when it does not escape; reconstruct it at deoptimization boundaries. | Lower typed `Result`/`Option` tests, unwraps, and temporary values across a whole hot function, materializing `Value` only when observable or crossing to the VM. | Requires ownership, exact budget/fuel accounting, cancellation, error and continuation maps. A single-opcode native bridge cannot deliver this optimization. |
| [Rust `Arc::make_mut`](https://doc.rust-lang.org/std/sync/struct.Arc.html#method.make_mut), [`BTreeMap::entry`](https://doc.rust-lang.org/std/collections/btree_map/enum.Entry.html), and [`serde_json::Map::entry`](https://docs.rs/serde_json/latest/serde_json/map/enum.Entry.html) | Mutation of uniquely owned data avoids copies; entry APIs update an occupied aggregate in place. | Represent aggregation state as typed, uniquely mutable data and serialize JSON only at the output boundary; separately investigate a safe unique JSON update path. | Guion must preserve alias and value semantics. Removing `Arc` or mutating shared objects in place would be wrong. A benchmark rewrite alone would improve a program, not necessarily the language core. |
| [V8 TurboFan compiler](https://github.com/v8/v8/blob/main/docs/compiler/turbofan/compiler-turbofan.md) | Inlining, escape analysis, and lowering high-level operations can eliminate transient objects. | Treat whole-function lowering and temporary-wrapper elimination as a candidate, using a small typed IR/SSA region with explicit exits. | Compile cost, code size, and short-script latency must be included in source-mode comparisons. |

## Recommended sequence and decision gates

**A. Separate workload shape from core overhead first.** Build an output-equivalent Guion variant that keeps group count/min/max in typed state, constructing JSON only for the final report. Preserve strict mode, invalid physical line numbers, allow-list behavior, ordering, and the frozen output oracle. Measure original and variant with the same pinned binary and paired 20k/200k source/artifact protocol. Record `JsonSetLocal`, `JsonTry*`, instruction count, allocator calls, and time. This is a causal experiment; keep the original workload as a permanent lane. If Guion cannot express efficient typed mutation yet, document the missing construct rather than silently treating a Rust helper as Guion speed.

**B. Target measured core allocations.** For the original workload, add narrowly scoped allocation-site attribution (for example, sampled allocation stack traces or counters around `Value` wrapper creation, `Load` clones, and JSON COW), using on/off controls. Then implement the highest-volume safe elimination: move/borrow only where liveness proves the old value dead, or carry `Result`/`Option` payload and tag in an unboxed execution representation until a materialization boundary. Preserve logical allocation quotas even if physical allocation disappears, or explicitly revise and test that contract. Reject a change if allocation calls fall but end-to-end paired time regresses.

**C. Keep common execution in one tier.** Extend native eligibility or a register/SSA execution plan for the actual `main`/JSON helper chain, not isolated `IsOk` or `is_some` bridge calls. Include tagged `Result`/`Option`, JSON access, guards, side exits, source spans, fuel, cancellation, and budget accounting. First prove exact behavior on success and error paths; then run the same paired workload. Start with a small verified region and expand only if it has a positive end-to-end result.

**D. Re-measure against the north-star gate.** Keep both original and typed-state lanes, the Python reference, and all four 20k/200k source/artifact comparisons. Report median and paired confidence bound, output hash, peak RSS, allocation count, compile/startup time, and regressions in short scripts. The closure criterion remains the previously stated paired 95% upper Guion/Python ratio below 1.0 in all four original lanes. An improved variant is useful evidence but does not substitute for that gate.

This sequence is a recommendation grounded in the audited code and external precedents, not a claim that parity is guaranteed. It avoids spending another cycle on the already rejected per-operation bridge or the small measured frame category.
