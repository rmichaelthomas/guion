# Language and command reference (current build)

For supported artifact, package, Python and host versions plus upgrade guidance, see [`compatibility-and-migrations.md`](compatibility-and-migrations.md).

The current format is 44. The runtime also reads supported earlier artifact formats; see the compatibility guide for the exact range.

## Minimal program

```guion
fn main() -> Int:
    let greeting = "Hello"
    print(greeting + ", Guion!")
    return 0
```

Function parameters and return types are explicit; local types are inferred. Use `var` for a binding that changes and `set` to update it. `let` is immutable. Function calls are statically resolved. `print` writes one line.

`List[T]` holds same-typed values. Use `[first, second]` for a literal, `values[index]` for zero-based indexing, `for value in values:` to iterate, and `len(values)` to count. Text length and indexing count Unicode scalar values; `text_chars(text)` materializes those scalars as a bounded `List[Text]` for linear scans.

`Option[T]` represents a value that may be absent. Return `Some(value)` or `None` from a function declared as `Option[T]`, test presence with `is_some`, and use `unwrap` after that check. `guion run language/examples/option.gu` demonstrates the flow.

## Local date and clock access

Import `std:time` and call `today_local() -> Date` when an application needs the current local calendar date. Clock access is denied by default. Enable it for a project with `[clock] enabled = true` in `guion.toml`, or for one run with `guion run --allow-clock`. The returned date follows the host process time zone and its daylight-saving database. The lower-level `unix_time_ms() -> Int` returns milliseconds since the Unix epoch. See the installed `language/host-api.md` for the exact capability contract.

## Commands

The default build is the Python-free core. Core commands do not discover or launch Python or uv. The Python bridge and managed Python dependency manager are available only in a build made with the explicit `python-interop` feature.

- `guion run --record TAPE ...` runs the program normally and writes a tape: every host operation the program made (file reads and writes, directory walks, HTTP, sockets and accepted connections, process, clock, environment and arguments, SQLite, random bytes) in order, with the values each left on the stack and a hash of the program. `guion run --replay TAPE PROGRAM` runs the same program with no file, network, clock, command or socket access at all, feeding every one of those operations from the tape, so the output is identical and nothing outside is touched. A replay stops with `R_TAPE_DIVERGED` at the first call that does not match, naming the operation, the function, the line, and the recorded and current arguments; a program whose hash differs from the tape is refused up front (`--replay-changed TAPE` skips that check to find the first call that differs), and a program that finishes before the tape does is a divergence too. Request headers named `Authorization`, `Cookie` and `Proxy-Authorization` are never written to a tape and are ignored when comparing calls, so a rotated token does not make a replay diverge. `[record] redact = ["secrets.txt", "api.example.com"]` in `guion.toml` keeps calls that mention those hosts or paths on the tape but not their results; a replay that reaches one stops with `R_TAPE_REDACTED`. `guion test --record DIR` writes one tape per `test_` function to `DIR/NAME.tape`, and `guion test --replay DIR` runs the tests hermetically from them: tests of code that talks to files or the network need no mock code. Recording and replaying run on the VM, not as machine code. Each `parallel_map` item keeps its own lane on the tape (`"lane":"0.2"` is the third item of the first `parallel_map` call; nested calls extend it as `0.2/1.5`), so operations are ordered within an item and not across items, and a replay gives the same output with any worker limit. A tape with lanes is format 2 (a program with no `parallel_map` still writes format 1); a divergence inside an item names its lane and ends the replay even though the program only sees an `Err` result; an item that a failing sibling stopped is replayed as stopped. A tape records what the host said, not what the program printed, and it is JSON Lines, so it can be read and diffed.
- `guion lsp` is a language server (Language Server Protocol over standard input and output, full-document sync): the compiler's errors as you type, hover (the declaration line, the comment above it, or a built-in's signature), go to definition for functions, records and enum variants in the same file, completion of names in the file, built-ins and keywords, and format document. It never runs the program. `editors/vscode/` is a small VS Code extension that starts it.
- `guion repl [run flags]` is an interactive prompt. An expression prints its value and type (`8 : Int`), a statement runs once, and `let`, `var`, `set`, `fn`, `record`, `enum` and `import` entries are kept for later lines (they are rebuilt into each program, so a kept `let` runs again every time: keep them free of side effects). A line ending in `:` continues until an empty line. Each entry runs through `guion run` with the flags you gave, so permissions mean the same thing; `import` of a file path is not supported, `std:` imports are. `:reset`, `:help`, `:quit`.
- `guion new DIRECTORY` creates a starter project and refuses an existing path.
- `guion check FILE.gu` compiles and reports the function count. When code reachable from `main` can write, rename or remove files, it adds a `writes files:` line naming the folder `guion run` will let it change (the project root). Add `--json` after the path for a versioned success report (with `writes_files`) or a structured source diagnostic with a stable code and line/column.
- `guion test FILE.gu` runs each zero-argument `Unit` function named `test_*` in its own fresh runtime instance. Add `--json` after the path for a stable JSON report on stdout with schema version, per-test status, pass/fail counts, and source traces for runtime failures. Failed tests still exit nonzero; stderr remains available for host-tool output.
- `guion run FILE.gu` compiles and executes source.
- `guion inspect --speed FILE.gu` lists each function as running in machine code (the fast path) or in the interpreter, and for the interpreter gives the reason code, a plain-English line and the source line it was blocked near. Add `--json` for the same data as JSON. Use it when a program is slower than you expect: the usual causes are a function that appends to a text variable or hands a list on to be updated (both are left in the interpreter on purpose, because it updates them in place), a function that calls one of those, and recursion under a call depth limit above 256. Recursion is machine code at the default limit of 128.
- `guion run --json FILE.gu [ARGS...]` returns a versioned JSON run report containing captured program output, exit status, or compiler/runtime diagnostics with source locations. Its `effects` list reports captured output and host operations with `started`, `returned`, `returned_error`, or `interrupted` outcomes; `omitted_effects` counts records beyond the 1,024-entry cap. Targets are capped at 256 Unicode scalar values and set `target_truncated` when shortened. HTTP targets report method and host without URL paths, query strings, or credentials. Python-assisted runs also report native image paths observed as newly resident at Python call boundaries in `python_native_images`, with the observation method in `python_native_image_observation`. On macOS, imports, `ctypes.dlopen`, or a changed dyld image count trigger a full image snapshot; a native image loaded and unloaded within one call can escape observation. Other hosts report `unsupported`. The JSON flag precedes the file path so remaining arguments pass unchanged to the program.
- `guion fmt FILE.gu` tokenizes code outside comments and quoted strings, normalizes spacing, and preserves comment and string contents. `guion fmt --check FILE.gu` reports unformatted files without writing.
- `guion lint FILE.gu` compiles first, then reports unused imports, unused locals, and unreachable statements as warnings with stable codes (`W_UNUSED_IMPORT`, `W_UNUSED_LOCAL`, `W_UNREACHABLE_STATEMENT`), and calls to deprecated functions (`W_DEPRECATED_CALL`, see below). Add `--json` for a versioned report. Compiler errors remain errors from `check`.
- `guion run language/examples/json_extract.gu` demonstrates bounded JSON parsing, exact integer access, and stable serialization.
- `guion run language/examples/float64.gu` demonstrates finite floating-point arithmetic and explicit JSON number conversion.
- `guion run language/examples/integer_division.gu` demonstrates truncating division, floor division, and divisor-signed remainder.
- `guion run language/examples/http_get.gu URL` demonstrates bounded HTTP text retrieval; grant the URL's exact hostname under `[network].hosts` first.
- `guion run PROJECT_DIRECTORY` resolves the entry file from `guion.toml`.
- `guion run [--file-root DIRECTORY] TARGET [ARGS...]` adds a file-access root for this run. Reads search the project or artifact root first, then the added roots; writes use the last added root. Packaged `./run` launchers add the caller's working directory by default, so CLI programs can read and write user files without placing them inside the installed bundle. Set `GUION_FILE_ROOT` to choose a different additional directory. Relative guest paths and parent-traversal restrictions still apply.
- Permissions are denied by default, and every denial names its fix: the `guion.toml` line and the run flag. `guion run --json` reports it as `diagnostic.grant` and lists every denial in `denials`. `guion inspect --grants [--json] TARGET` shows what the code can reach against what `guion.toml` grants.
- When a person is at the terminal, `guion run` asks once before running about the grants it can see are missing (`[y]` this run, `[a]` always, which edits `guion.toml` in place, `[N]` no), and asks about a target only known while running when it is reached. Nothing is asked under `CI`, `GUION_NO_PROMPT=1` or `--no-prompt`, with `--json`, `--sealed` or `--replay`, in `guion test`, or when stdin, stdout or stderr is not a terminal; the answer is read from the terminal, never from piped input. Agents and scripts should set `GUION_NO_PROMPT=1`.
- `temp:name` names a file in a private folder created for each run (and each test) under `TMPDIR` and removed when the run ends; `--keep-temp` keeps it and prints its path. `temp:` paths never reach the project folder. `guion run --sealed` runs with no file access and none of the project's grants, for code you have not read; it cannot be combined with grant flags.
- `guion build FILE.gu [-o FILE.gub]` writes a versioned portable bytecode artifact (default output replaces `.gu` with `.gub`). Artifact metadata records the compiler version, build host, exact source graph digest, any present dependency lock fingerprints, and effective runtime ceilings; ceilings follow the artifact when it is moved.
- `guion package PROJECT_DIRECTORY [--output DIRECTORY]` creates a current-host, source-free application directory containing the compiled artifact, matching Guion runtime, project policy, launcher, and declared resources. Core packages do not bundle Python or uv. Python-assisted projects require the optional feature and retain its pinned-runtime packaging behavior. Verified core package targets are macOS ARM64 and Debian 12 GNU/Linux on ARM64 and x86_64, all with glibc; the command refuses to overwrite an existing destination.

Linux packages include `linux-dependencies.json`, which records ELF dependencies, runtime resolutions, required glibc versions, architectures, hashes, and available distribution provenance. The report is an audit aid; it does not observe libraries opened only through runtime APIs.
- `guion verify-package PACKAGE_DIRECTORY` checks the package target and recorded SHA-256 digests for the artifact, runtime, resources, managed Python tree, pinned `uv`, Python lock, dependency and native reports, copied license files, and native images, including native files in the offline wheel cache. The package launcher skips this full-tree hash scan by default to keep short commands responsive; set `GUION_VERIFY_PACKAGE=1` to run it before launch. The reports are unsigned, so they detect accidental corruption but do not authenticate the publisher. Native dependency reports contain target-specific static load records; dynamic Python image observations are emitted on macOS through `run --json`.
- `guion sync --locked` installs the packages the manifest pins (URL, version and archive hash) that the cache lacks and verifies the result against `guion.lock`, which it never rewrites; two projects with the same manifest and lock get byte-identical trees. A package installed in a project's `.guion/packages/NAME/VERSION` can run `guion test` there and resolves its dependencies from the project's lock.
- `guion verify-package [--json] NAME VERSION` (or `ARCHIVE NAME VERSION` for archive bytes on disk) checks a published registry release without installing it: archive hash against the index and the log, the archive's manifest, and the log entry's hash, chain and signature. Failures carry `E_PACKAGE_CHECKSUM`, `E_PACKAGE_SIGNATURE`, `E_PACKAGE_LOG`, `E_PACKAGE_MANIFEST`, `E_PACKAGE_NOT_FOUND` or `E_PACKAGE_REGISTRY`.
- `guion sync PROJECT_DIRECTORY` without `--locked --offline` is reserved for projects using the optional `python-interop` feature. In a core build, use `guion sync --locked --offline` to validate native packages and explicitly migrate a legacy Python-only lock while preserving its Python metadata.
- `guion run FILE.gub` executes a compiled artifact without source.
- `guion inspect FILE.gu` or `.gub` prints artifact and function metadata, including recorded build limits when present, plus statically reachable runtime effects, and the same `writes files:` line as `guion check`. `guion inspect --json FILE.gu` emits schema-versioned function call/effect data and opaque Python declarations. This is bytecode reachability analysis for known host operations, not a sandbox, a proof of Python behavior, or a complete observation of native code and operating-system effects.
- `guion doc std:NAME` prints a shipped standard-library module's public functions (with signatures and effects) and records in the same text format; `guion doc std:NAME --json` emits the same `guion_api_report` envelope; an unknown module name exits non-zero and lists the valid ones. `guion doc --all --json` emits one `guion_std_surface` document with every shipped module's surface, modules and functions sorted by name.
- A public function is marked deprecated by a doc comment in the block of `#` lines directly above it: `# deprecated(since 0.3.0): use NAME`. There is no syntax change; the marker is a comment, and a deprecated function behaves exactly as before. `guion doc` appends `deprecated since 0.3.0: use NAME` to the function's line, and `--json` adds `"deprecated": {"since": "0.3.0", "use": "NAME"}` to that function (the field is absent on unmarked functions). `guion lint` reports `W_DEPRECATED_CALL` ("`old` is deprecated since 0.3.0: use `new`") at each call of a marked function that the file imports, including through `pub import` re-exports; a function the file declares itself is not reported. Only calls are reported, not uses of the name as a function value. The marker is how [VERSIONING.md](../VERSIONING.md) section 7 announces a removal; the earliest release it may be removed in goes in the changelog line.
- `guion doc FILE.gu` prints function, record, and optional external signatures. `guion doc --json FILE.gu` emits a versioned `guion_api_report` with source parameter names and checked types, reachable effects, standard-library availability, native package identities, and optional profile requirements.
- `guion build --json FILE.gu [--output ARTIFACT]` emits a versioned build report with artifact format, size and SHA-256, source digest, compiler version, and host target. Compile failures use the structured diagnostic format. Human-readable build output remains the default.
- `guion package --json PROJECT [--output DIRECTORY]` emits a package report with target, package schema, artifact digest, metadata digest, resource count, and whether a Python runtime was bundled. Packaging failures emit a stable diagnostic; source compile failures retain their compiler code and source location. `guion verify-package --json DIRECTORY` reports verified package identity or a structured verification failure. Both commands remain human-readable by default.
- `guion doctor` reports the current host and enabled profile. `guion doctor --json` emits a versioned report; a core build reports that Python interoperability is disabled and does not inspect Python or uv, while an optional bridge build reports interpreter and toolchain readiness.
- `guion add NAME --path DIRECTORY` adds a local native package; `guion add NAME --url HTTPS_URL --version VERSION --sha256 HASH` adds a content-verified archive. `guion update` explicitly resolves native package sources and transactionally updates the lock and managed cache. `check`, `run`, and `build` never rewrite locks.
- `guion new --lib DIRECTORY` creates a library: a `guion.toml` with a `[package]` table, `src/lib.gu`, and a `tests.gu` program for checking and testing it (a library has no `main`). Package names are lowercase, at most 64 characters, treat `-` and `_` as the same character, and cannot be standard-library module names, `std`, or begin with `guion-`; `@owner/name` is reserved. `guion check tests.gu` in a library also checks that each exported module has `pub` items and that the `[capabilities]` table (`network`, `files`, `environment`, `processes`, `clock`, `python`) covers what the library's own code uses: undeclared use is an error, unused declarations warn. Hosts that appear in URL literals (`http`, `https`, `ws`, `wss`) in the library's own functions must be listed in `network`; when the library uses the network but no listed host appears in its code, check warns that the declaration cannot be confirmed. `guion update` stops if an update widens a locked package's capabilities, printing the difference (for example `network: +hosts ["api.example.com"]`), until you rerun it with `--approve-capabilities`. A project can also keep an `[approved-capabilities.NAME]` table in `guion.toml` (same keys as `[capabilities]`); once it exists, `guion add` and `guion update` refuse a package that declares more than its entry, again naming the difference, unless given `--approve-capabilities`, which records the approval. Effects cross package boundaries: `guion doc --json` and `guion inspect --json` list each function's effects including those it reaches in packages it imports, and a `package_effects` object gives, per linked package, the union of its functions' effects and (with an approval table) `beyond_approved`; `guion check`, `build` and `run` refuse a program whose package reaches an effect its approval does not cover, naming it and the entry that would cover it.
- Registry commands use `GUION_REGISTRY_URL` (or `[registry] url` in `guion.toml`); the default is `https://guion-registry.thomasbuild.workers.dev`. `guion add NAME [--version REQUIREMENT]` picks the highest non-yanked version that satisfies the requirement (`^1.2`, `~1.2.3`, `>=1.0, <2.0`, `=1.4.0`, or `*`), checks that the index, the registry's hash log and the downloaded bytes agree and that the log entries are signed by the registry's ed25519 key, and installs it like a pinned `--url` package. It records the range as `registry = "..."` on the dependency (a caret on the chosen version when no requirement was given), and `guion update` moves the package to the highest non-yanked release in that range, with the same checks; the installed version stays eligible even if it was later yanked. `guion publish [DIRECTORY]` checks the library, packages its source and uploads it using the publisher token in `GUION_REGISTRY_TOKEN`; `guion yank NAME VERSION [--undo]` hides or restores a version for new resolution. `guion token rotate` replaces the token in `GUION_REGISTRY_TOKEN` with a new one (printed once) and `guion token revoke` withdraws it. The default registry's public key is built into `guion`; for another registry, set `GUION_REGISTRY_PUBLIC_KEY` (or `[registry] public_key`) to its 64-hex-character key (several keys, separated by commas, are all trusted, which is how a key rotation is rolled out), and installs fail closed when a log entry is unsigned or signed by a different key. Without a key configured for a non-default registry, signatures are not checked. The protocol is in `registry-protocol.md`. A published library can depend on other registry libraries (`name = "^1.0"` under `[dependencies]`); `guion publish` resolves each range, checks the library against what it picked, and ships the manifest with exact versions, URLs and hashes. Precompiled `.gub` attachments are deferred until libraries compile separately.
- `guion package --library SOURCE_DIRECTORY --output DIRECTORY` creates a reusable native library package. `guion install PACKAGE_DIRECTORY [--prefix DIRECTORY]` verifies and installs an app package into `share/guion/apps/NAME/VERSION` and creates its generated command under `bin/NAME`. The default prefix is `~/.local`; unrelated existing executables are preserved.

For optional managed Python calls, build Guion with `--features python-interop`, then declare an exact `[python].version` and a `dependencies` array in `guion.toml`. The core build never discovers or launches Python or uv.

For offline app packaging, `GUION_PYTHON_INSTALL_DIR` can point to an already installed matching CPython tree, and `GUION_PYTHON_CACHE_DIR` can point to a preloaded uv cache. Package assembly copies the specified cache into the app's portable `.uv-cache` before syncing its locked dependencies. Set `UV_OFFLINE=1` to require cache-only packaging; the command fails if a required artifact is missing. This copies the full selected cache, so use a project-scoped cache when package size matters. Without these settings, the optional Python package path may acquire the pinned interpreter and wheels during packaging.

Pure-Guion packages can include runtime data files explicitly:

```toml
[package]
resources = ["assets/schema.json", "data/lookup.csv"]
```

Resource paths must stay inside the project, name files, and avoid package-owned paths. List imported Python modules alongside data files in `[package].resources`; package execution imports them from the package root. The package writes `PACKAGE.json` with target and SHA-256 digests. Schema 2 includes integrity hashes for immutable Python offline-cache payloads. uv bookkeeping files matching `.lock`, `*.lock`, `*.http` and `*.msgpack` are excluded because offline runs update them. Schema 1 packages remain verifiable. Run the result with `./run [arguments]`. Files not listed as resources are not copied. Relocation is verified on macOS ARM64 and Debian 12-compatible GNU/Linux ARM64 for selected Python wheels. Target-specific audits attribute installed native files through wheel `RECORD`; they do not prove ownership of vendored source code, and static scans cannot observe libraries opened only through runtime APIs.

HTTP is denied unless a project manifest grants exact hosts. The first operation is text GET:

```toml
[network]
hosts = ["feeds.example.org"]
timeout_ms = 15000
max_response_bytes = 16777216
max_redirects = 5
```

`http_get(url)` returns `Result[Text, HttpError]`; errors are inspectable with `http_error_code` and `http_error_message`. `http_request(method, url, headers, body)` returns a JSON response envelope and uses the project's network timeout. `http_request_with_timeout(method, url, headers, body, timeout_ms)` sets a per-request deadline; the effective deadline is the smaller of the requested value and `[network].timeout_ms`. A nonpositive or unrepresentable timeout returns `R_HTTP_TIMEOUT`. Both request functions enforce exact-host grants, request/response byte limits and same-host redirect limits. Streaming and binary response bodies remain unimplemented.

The per-request timeout operation requires artifact format 27. A host may cap the requested deadline through its `HostPolicy`; guest code cannot raise that ceiling.

The current-format feed-digest workload in `evaluation/development/guion_feed_digest` combines bounded concurrent HTTP, managed `feedparser`, a project-local Python adapter, and Guion output handling. Its loopback-only host grant is for the local acceptance fixture; edit the exact host allowlist before using it with external feeds. The acceptance harness in `evaluation/tests/test_feed_digest.py` compares output with an independent Python baseline and checks concurrency, order stability, Unicode, malformed feeds, HTTP failures, changed input and denied hosts. The original Veritas-named project is retained separately at `evaluation/development/feed_digest` as a compatibility fixture.

Runtime errors go to stderr and return a failing process status. Output produced before a runtime error is preserved on stdout. Diagnostics include stable error codes and source line/column locations.

`print(value)` writes program output to stdout. `eprint(value)` writes program diagnostics to stderr. Both are captured independently by `guion run --json`, reported as distinct effects, and charged to the combined output limit. `eprint` requires artifact format 28.

## Current limits

The `std:text` `text_split` and `text_join` helpers combine pieces in bounded groups to reduce repeated copying for larger inputs. `text_split` with an empty delimiter returns the original text as one field; `text_join` of an empty list returns empty text. They retain Unicode-scalar behavior and remain subject to the normal instruction and allocation budgets.

Runtime resource ceilings can be set in a project's `guion.toml` under `[runtime]` and are also available on the embedding `HostPolicy`. Every field must be a positive integer; unknown fields fail with a manifest error. The default allocation limit is 268435456 bytes per invocation. Under the `guion` command line it bounds the memory the program holds (measured from the allocator when the per-allocation estimate runs out), so a long loop that frees what it allocates no longer stops; embedders without a live-memory probe keep a cumulative estimate. The command line sets no instruction limit unless `instruction_limit` is given; embedders keep the 2,000,000 default. It counts input value footprints, collection/record/text/byte/JSON construction, host results, and output rendering across nested calls. Interpreter/JIT frames, operand stacks, and scalar arithmetic temporaries are excluded so backend selection does not change this limit; integer growth has its own digit ceiling. Parallel workers share a counter and leave a portion available to handle their result. Exhaustion reports `R_ALLOCATION_LIMIT`. The estimate covers guest data at known creation points; it is not exact native heap/RSS accounting, and OS/runtime/third-party allocations may differ. Other limits such as instruction count, call depth, output, file bytes, text bytes, collection items, and integer digits remain independent.

Embedders may cancel a running invocation by creating a `guion_runtime::CancellationToken`, cloning it to a control thread, and calling `Instance::invoke_with_cancellation(export, args, token)`. VM code checks between instructions; native code checks at entry and backward branches; parallel workers stop scheduling and are joined; Python calls are terminated and reaped after cancellation is noticed (polled every 20 ms). A blocking HTTP call is observed only after it returns or reaches its configured timeout. Completed side effects are not undone, so cancellation does not mean rollback. Use a fresh token per invocation. The command-line program currently follows normal process Ctrl-C behavior rather than returning `R_CANCELLED`.

```toml
[runtime]
allocation_limit_bytes = 268435456
instruction_limit = 2000000
max_parallelism = 8
```

`max_parallelism` is the most workers `parallel_map` may be given. It defaults to 64 on every machine, whatever the core count, and can be raised to 1024. A worker waiting on the network does not use a core; for work that keeps the processor busy, `core_count()` (from `std:process`) says how many cores there are.

`try_parallel_map(list, function, Workers(at_once=50, each_ms=5000, all_ms=30000))` (`Workers` is a record from `std:process`; artifact format 76) is `parallel_map` with a result per item, `List[Result[U, TaskError]]`, and deadlines. A fault in one item is that item's `Err` and the others carry on. An item that runs past `each_ms` milliseconds becomes `Err` with `task_code` `R_DEADLINE`, and when `all_ms` passes every item still running or not yet started becomes `R_DEADLINE` while finished items keep their results; 0 means no limit. A blocking call inside an item (HTTP, a command, a socket) waits no longer than the time left, so a hung server cannot hold an item past its deadline. Deadlines use a timer the program cannot read, so they need no `[clock]` grant. An item that runs out of time contributes no output. Items with a deadline run on the interpreter, not machine code. A recording marks such an item as cut short, and a replay makes it `R_DEADLINE` too, whatever the replay's speed.

**Background work: `together:`** (artifact format 76). A `together:` block runs work in the background and ends all of it when the block ends:

```
together:
    let build = start(run_build, "release")
    let lint = start(run_lint, "")
    let built = wait(build)
    let linted = wait(lint)
```

`start(function, argument)` begins `function(argument)` on its own thread and gives a task; it only works inside a `together:` block (`E_START_OUTSIDE_TOGETHER`), and the function is a named function or one that captures nothing. `wait(task)` waits and gives `Result[T, TaskError]`; a fault in a task is its own `Err` and stops no sibling. `wait_within(task, ms)` gives up after `ms` milliseconds with `R_DEADLINE` and stops the task. **When the block ends, every task not waited for is stopped**, so "watch until I am done" is a task the block simply does not wait for. A task has exactly its parent's grants, shares its memory and instruction budgets, and shows its output when it is waited for (a task that was stopped shows none). A task belongs to its block: it cannot be returned, stored in a variable declared outside the block, or printed (`E_SCOPE_ESCAPE`), and `return`, `break`, `continue` and `?` cannot leave a block (`E_TOGETHER_EXIT`); an error that unwinds past a block still stops its tasks. A recording keeps each task on its own lane and records whether each `wait_within` gave up, so a replay makes the same choices. There is no async or await: ordinary functions stay ordinary.

**Channels and whichever comes first** (artifact format 76). Inside a `together:` block, `let results: Channel[Int] = channel(8)` makes a channel that holds at most 8 values (1 to 65,536; the type comes from the annotation). `send(channel, value)` waits while the channel is full, so a fast producer cannot get ahead of a slow consumer by more than the capacity, and gives `Result[Unit, TaskError]` (`R_CHANNEL_CLOSED` once it is closed). `receive(channel)` waits and gives `Option[T]`, `None` once the channel is closed and empty. `close(channel)` closes it, and the block closes every channel it made when it ends. A started function takes a channel as its argument (`fn produce(out: Channel[Int]) -> Int`), but a function cannot return one. With `import "std:process"`, `first_ready(tasks)` waits until any listed task is finished and gives `Ready(index, value)`: its position in the list and the result `wait` would give. `first_value(channels)` does the same for channels, and the value is what `receive` would give, taken in the same step, so two consumers of one channel never get the same value or lose one (`None` when the channel is closed and empty). Both have a `_within` form, `first_ready_within(tasks, ms)`, that gives `Option[Ready[T]]`. When several are ready at once the earliest in the list wins. A recording keeps every `send`, `receive` and choice, so a replay makes the same choices whatever the timing.

**Commands in the background** (`std:process`, artifact format 76). `start_process(command, arguments)` starts a granted command without waiting for it and gives `Result[Process, StdError]`; it needs the same `[process] commands` grant as `process_run`, with the same errors and fix-it text. `process_line(p)` gives the next line of its output as `Option[Text]` (`None` when the output ends), `process_write(p, text)` and `process_close_input(p)` feed its input, and `process_wait(p)` waits for it and gives `Result[ProcessResult, StdError]` (its `stdout` is the output not read with `process_line`). Each command gets its own process group, and **when the `together:` block that started it ends, when the program ends, or when `guion` is sent `INT`, `TERM` or `HUP`, the whole group is stopped and reaped**, so a sub-agent cannot leave orphans behind (a program that polls for signals itself with `process_signal_poll` handles them itself and still stops its commands when its block ends). Output is bounded by `[process] max_output_bytes` per command, and a `Process` cannot be returned from its block (`E_SCOPE_ESCAPE`). Supervising sub-agents is then: start each one, read its lines as they arrive, give each a deadline with `wait_within` or `try_parallel_map`, and know they are all gone when the block ends. A recording keeps every line and the exit, so a replay needs no command and no grant.

When a program exhausts `instruction_limit` the run fails with `R_STEP_LIMIT`: `instruction budget exhausted: N instructions used of M allowed; raise `instruction_limit` under `[runtime]` in guion.toml`, and the JSON diagnostic carries `used` and `limit`. `decompress_limit_bytes` (default 1073741824) bounds every gzip, zlib and tar inflate, and `[log] level` sets the default `std:log` level.

Format 68 adds `crypto_random_bytes(count: Int) -> Result[Bytes, StdError]`, `crypto_random_hex(count: Int) -> Result[Text, StdError]` and `crypto_random_base64url(count: Int) -> Result[Text, StdError]` to `std:crypto`. The `web` package (`packages/web`, installed with `guion add web --path PATH`, imported as `pkg:web/src/lib.gu`) assembles the stdlib value types into an application. `route(method, pattern, handler)` registers a handler of type `fn(Request) -> Result[Response, HttpFailure]` (Guion has no type aliases, so the type is written out) under a pattern such as `/users/{id:int}/files/{slug}`; `router(routes) -> Result[Router, HttpFailure]` is an `Err` at construction for a malformed pattern (`E_ROUTE_PATTERN`) or two same-method routes that can match one path (`E_ROUTE_CONFLICT`; there is no precedence, so use `{id:int}` beside a literal such as `new`). `router_handle(router, request)` splits the raw path on `/` first and percent-decodes each segment after, so `%2F` stays inside one parameter; `{id:int}` accepts digits only (no sign, no leading zero, at most 18 digits) and anything else is a 404, a bad percent escape or `%00` is a 400, a trailing slash is significant (`/a/` does not match `/a`, and a pattern may not end in `/`), and a known path under other methods is a 405 with `Allow`. `path_param(request, name) -> Option[Text]` and `path_param_int(request, name) -> Option[Int]` read `Request.params`. Because function values capture nothing, middleware is a record: `Middleware(before, after, config)` with named functions `before(config, request) -> Result[Request, Response]` (an `Err(response)` answers early) and `after(config, request, response) -> Result[Response, HttpFailure]`, where `config` is the layer's own `Map[Text, Text]`, built with `middleware`, `middleware_before`, `middleware_after`, `middleware_configured` or `middleware_before_configured`; `app(router)`, `wrap(app, layer)` (the new outermost layer), `app_with(router, layers)` (outermost first) and `app_log(app, logger)` build an `App`; `app_handle` returns the `Result` and `app_respond` always returns a `Response`, turning any `Err` into a 500 with the fixed body `internal_error_body()` and logging the failure through std:log or standard error. `serve(host, port, app, workers)` and `serve_for(host, port, app, workers, idle_ms)` run `workers` `parallel_map` workers on one listener (each connection is answered with `Connection: close`, reads limited to 10 s and 1 MiB) and name no handle type. A runtime fault inside a handler is not contained: `parallel_map` stops all workers and `serve` returns an `Err` with the fault's code, so handlers return `Err` rather than fault. Every function declares its effects in `guion doc --json`; `serve` reports `network.socket`, `concurrency.parallel` and file and output effects from logging.

The `web` package also keeps sessions and CSRF tokens (`session.gu`, `csrf.gu`; the package README has the full API). `session_store_open(path)` opens a SQLite database that every worker shares, holding `sha256(ID)` for each session (never the ID) and a server secret made once with `crypto_random_bytes(32)`; session IDs are `crypto_random_hex(32)`, 64 lowercase hex digits. `session_middleware(store, policy)` and `csrf_middleware(store, policy)` return `Result[Middleware, HttpFailure]` and check the policy when the app is built. The cookie is `HttpOnly`, `Secure` and `SameSite=Lax` with `Path=/` by default; `SameSite=None` without `Secure` is `E_COOKIE_SAMESITE_NONE_NEEDS_SECURE`. An ID the store does not hold, or one of the wrong length or alphabet, is replaced and never adopted; `session_rotate` (call it on login) moves the data to a new ID and deletes the old one, `session_destroy` ends a session, and a session ends after `idle_seconds` or `absolute_seconds` (default 30 minutes and 12 hours). The token is `base64url(HMAC-SHA256(secret, ID + "csrf"))`, read from `x-csrf-token` or a `_csrf` form field, compared in constant time and required on every method except `GET`, `HEAD` and `OPTIONS`; a refusal is a 403 with the body `Forbidden`. Nothing about a session reaches a log or a failure message. The session functions report `clock.read` where they read the time; the effect analysis does not model SQLite, so opening the session database reports no file effect.

`std:http_static` (artifact format 73) serves files from a directory as `Response` values: `static_serve(request: Request, root: Text) -> Result[Response, HttpFailure]` (effect `filesystem.read`), `static_content_type(path: Text) -> Text` and `static_http_date(unix_ms: Int) -> Text`. It answers GET and HEAD (other methods 405 with `Allow: GET, HEAD`) with `Content-Type` from the extension (`text/*` types carry `charset=utf-8`, unknown is `application/octet-stream`), `X-Content-Type-Options: nosniff`, `Accept-Ranges: bytes`, a weak `ETag` `W/"<size>-<mtime-ms>"` (a cheap validator, not a content hash) and `Last-Modified`. `If-None-Match` (weak comparison, `*` and lists) or, when it is absent, `If-Modified-Since` gives 304 with no body. Built-ins include `args()`, `args_from(start)`, `read_text(path)`, `write_text(path, content)`, `write_text_atomic(path, content)`, `read_bytes(path)`, `write_bytes(path, content)`, `http_get(url)`, `assert(condition)`, `len(list_or_map_or_bytes)`, `list_push(list, value)`, `list_set(list, index, value)`, `sort(list)`, `sort_by(list, key_function)`, `map_list(list, f)`, `filter_list(list, f)`, `fold_list(list, initial, f)`, `any_list(list, f)`, `all_list(list, f)`, `sort_by_int_key(list, key_function)`, `merge_sorted_by_int_key(sorted_feeds, key_function)`, `sqrt(Float64)`, `map_set(map, key, value)`, `map_has(map, key)`, `map_get(map, key)` (an `Option`; no import needed), and `parallel_map(list, function_name, worker_limit)`, plus JSON bulk conversions `json_int_column`, `json_text_categories`, `json_as_int_list`, and `json_stringify_pairs`, and format-30 streaming projection via `json_project_columns` / `json_text_categories_values`. `sort_by_int_key` requires a named pure `(T) -> Int` function, computes its key once per item, uses a stable sort, and preserves the input and its aliases. `merge_sorted_by_int_key` stably merges already-sorted lists using the same key-function contract and rejects a feed that is not sorted by that key. `list_push` appends and `list_set` replaces an existing zero-based index; both return immutable values. Assigning `list_push(name, value)` or `list_set(name, index, value)` back to that same mutable local uses copy-on-write storage and clones only when an alias must retain the old value. Assigning `json_set(name, key, value)` back to that same mutable `Json` local uses an alias-safe copy-on-write update to reduce temporary object copying. `args_from` returns the CLI argument suffix beginning at a zero-based index. Bytes are immutable, preserve all values including invalid UTF-8 and NUL, and use the `max_file_bytes` ceiling. Maps support literals with unique text keys, homogeneous values, deterministic sorted-key iteration, immutable updates, key lookup and `len`; empty literals need an expected `Map[Text, T]` type. Empty lists likewise need an expected `List[T]` type, which can come from a local annotation, return type, function parameter, enclosing collection, or typed operation. Typed `Map[Text, T]` values cross Python calls as dictionaries with string keys. Python interop also supports finite `Float64`, `Bytes` (request values use private raw-byte attachments and arrive as Python `bytes`; Python byte returns remain base64 encoded), `Json`, top-level NumPy arrays returned against a `List[T]` declaration, and source-level keyword arguments mapped to declared parameter names. NumPy boolean/numeric arrays up to 64 bits are materialized with `tolist()` and checked against the declared nested list shape and type; arrays are limited to 98,304 elements before materialization and data is copied. A `Json` bridge value preserves nested heterogeneous JSON and arbitrary-precision integers; Python cycles, non-finite values, non-string object keys and non-JSON objects are rejected. Omitted arguments are passed through as omitted so Python defaults can apply. JSON construction uses `json_null`, `json_bool`, `json_int`, `json_float`, `json_text`, `json_array`, `json_object`, `json_push`, and `json_set`; constructors and immutable updates require artifact format 20. `write_text_atomic` requires format 21 and performs atomic visibility replacement without writer locking.

`while` and `for` loops can be left early with `break` and resumed at the next iteration with `continue`; both bind to the innermost enclosing loop, work inside `if` and `match` arms and inside `parallel_map` worker functions, and outside a loop fail with `E_NO_LOOP`. They are reserved words and need no new artifact format. An unknown call name fails with `E_NAME_UNKNOWN` and, when the name is a near miss, a separate line ``help: did you mean `name`?`` per candidate (one line each, nearest first). Candidates are the functions visible to the module (its own and its imports') plus the builtins; one qualifies when its Levenshtein edit distance over Unicode scalar values is at most `max(2, len(name) / 3)`. They sort by distance, then by name, and at most three are shown. Nothing is substituted, unknown local variables get no suggestions, and `guion check --json` carries the same names in an additive `diagnostic.suggestions` array that is present only when there are candidates. `Option` constructors `Some(value)` and `None` are available inside functions declared to return `Option[T]`; use `is_some(option)` and `unwrap(option)`, which raises `R_OPTION_UNWRAP` for absence. Text and byte file operations return `Result` values; inspect errors with `file_error_code/message/line/column`. Missing paths return `R_FILE_NOT_FOUND`, permission failures return `R_FILE_PERMISSION`, and file-size policy failures remain runtime errors. `write_text` and `write_bytes` write directly; `write_text_atomic` atomically replaces a text file but does not coordinate multiple writers or promise directory-entry durability after sudden power loss. `Ok`, `Err`, and postfix `?` are available in functions with a declared `Result` return type; Result and Option values can be handled with exhaustive statement matches; see below. General Result inference remains unimplemented. `json_parse` returns `Result[Json, JsonError]`; malformed syntax and duplicate keys are inspectable through `json_error_code/message/line/column`. Resource-limit and typed access failures remain runtime errors. Other JSON operations include `json_stringify`, `json_stringify_pairs`, `json_get`, `json_index`, `json_has`, `json_len`, `json_as_text`, `json_as_int`, `json_as_float`, `json_as_bool`, and `json_is_null`. `json_stringify_pairs` streams a grouped text map into a JSON array of `{key: value}` rows in deterministic key and list order, with caller-selected field names. `json_as_float` converts a JSON number to finite `Float64`; nonnumeric or non-finite conversion fails with `R_JSON_TYPE`. `parallel_map` returns `Result[List[U], TaskError]`; inspect it using `is_ok`, `unwrap`, `error`, `task_index`, `task_code`, and `task_message`. An `extern python "module:callable" fn alias(...) -> Type` declaration calls through a supervised sidecar. A project with `[python]` uses the exact locked managed interpreter; otherwise use an explicit `GUION_PYTHON` path. Current Python conversions cover `Unit`, `Bool`, `Int`, finite `Float64`, `Text`, `Bytes`, `Json`, and recursively nested lists/maps with string keys; calls support positional and keyword arguments mapped to declared parameters, and omitted parameters are left to Python defaults. Python failures are runtime errors. The CLI grants file access within the project root and any explicit `--file-root` directories; the additional roots are still restricted to relative paths that remain inside a grant. Embedded use must grant a root explicitly. This root check is not a sandbox. Network host grants do not prevent DNS rebinding or enforce operating-system egress controls.


## Everyday forms

- `else if condition:` chains any number of times; the final `else:` is optional. Python's `elif` is `E_PYTHON_ELIF` and says to write `else if`.
- `for i in range(end):`, `range(start, end)` and `range(start, end, step)` count `Int`s without building a list. The bounds are evaluated once, before the loop; `i` is immutable in the body; `step` is a non-zero integer written in the source (`2`, `-1`; anything else is `E_RANGE_STEP`); a negative step counts down; an empty range runs zero times; `break` and `continue` work as in any `for`. `range` anywhere but a `for` header is `E_RANGE_CONTEXT`.
- `set x += e`, `-=`, `*=`, `/=`, `//=` and `%=` mean `set x = x + e` and so on, for locals and for fields (`set c.n += 1`); the two characters must touch.
- `f"text {expression} text"` builds text. A hole holds one expression of type `Text`, `Int` or `Float64` and no string literal (`E_FSTRING_TYPE`, `E_FSTRING_HOLE`); `Int` and `Float64` convert as `int_to_text` and `float_to_text` do; `{{` and `}}` are literal braces. Only the prefix `f` with a double quote is Guion; `rf`, `fr`, `F` and single quotes keep `E_PYTHON_FSTRING`.

## Closures, enums and generics

**Closures** (artifact format 74). `fn(x: Int) -> Int: x + offset` is a function value written where it is used, and `fn name(x: Int) -> Int:` with an indented body inside a function does the same and binds it to `name`. It keeps the values of the variables it uses *as they were when it was created*: a later `set` of the outer variable is not seen, and the closure cannot change them (`set` on a captured name is an error). A function can return one (`fn adder(n: Int) -> fn(Int) -> Int:` then `return fn(x: Int) -> Int: x + n`), and a closure can hold another closure or a record. `map_list`, `filter_list`, `fold_list`, `any_list`, `all_list` and calling through a variable accept closures. `try_map_list(items, f)` (format 74) calls `f` on each item as its own fault boundary and returns a `List[Result[U, TaskError]]`: an item whose call faults (an index out of range, say) is `Err(TaskError)` with `task_code`, and the other items still run. `serve` in the `web` package uses it so a handler fault answers that request with 500. `sort_by`, `sort_by_key`, `sort_by_int_key`, `merge_sorted_by_int_key` and `parallel_map` take a named function or a function value that captures nothing, such as `fn(x: Int) -> Int: 0 - x`. A function literal written in the argument that uses a local variable is `E_FN_CLOSURE` at check time; a closure that reaches the call through a variable is `R_FN_CLOSURE` when it runs. A nested `fn` cannot call itself by name. A function that uses closures runs on the VM, not as machine code. Closures are only in the Rust compiler (the self-hosted compiler in `language/self_host/` still reports `E_FN_NO_CLOSURES`), and the browser playground runs `CallFn` on closures but still has no `map_list` family (known issue 26).

**Enums.** `enum Shape:` lists variants, each a name with optional named values: `Circle(radius: Float64)`, `Rect(width: Float64, height: Float64)`, `Dot`. Make one with its variant name, `Circle(2.0)` or `Dot`. `match shape:` takes one arm per variant, written `Circle(r):`, `Rect(w, h):`, `Dot:`; `_` skips a value. A match that leaves a variant out is `E_MATCH_MISSING_VARIANT` and names it, a repeated variant is `E_MATCH_DUPLICATE`, and a wrong number of values is `E_ENUM_ARITY`. Variant fields may be `Int`, `Float64`, `Bool`, `Text` or a `List` of those (`E_ENUM_FIELD_TYPE` otherwise). Variant names are shared by the whole program, so two enums cannot use the same one, and none may be `Some`, `None`, `Ok` or `Err`. An enum is stored as a record with an Int `tag` field plus one field per variant value, so it costs one field for every value of every variant; `pub enum` exports it like a record.

**Maps keyed by `Int`** (artifact format 75). `Map[Int, T]` is a separate type from `Map[Text, T]`: write `let m: Map[Int, Text] = {}` or a literal with `Int` keys, `{3: "c", 1: "a"}`. `map_get(m, k)`, `map_has(m, k)`, `map_set(m, k, v)`, `m[k]` and `len(m)` take an `Int` key, and `for k in m` yields the keys as `Int` in ascending numeric order (`-3, 9, 10`, not `-3, 10, 9`). A `Map[Int, T]` is stored as a text-keyed map under the decimal text of each key, so it costs one conversion per access; it cannot be passed where a `Map[Text, T]` is wanted, `map_record_get` and `map_record_set` do not take it, and the host and JSON boundaries do not accept it. Only `Int` and `Text` are map key types (`E_TYPE_MAP_KEY`).

**Generic functions.** `fn first[T](items: List[T]) -> T:` declares type parameters. A call binds them from the arguments (`first([4, 5])` is `Int`), or you write them, `empty[Int]()`, when the arguments do not say (`E_GENERIC_INFER` names the call). The compiler checks and builds the function once for each set of types it is called with, so there is no cost at run time. The body of a generic function that is never called is not checked. There are no bounds on type parameters.

**Generic records.** `record Pair[A, B]:` with fields `first: A` and `second: B` declares a record with type parameters. Write the type as `Pair[Int, Text]`. A constructor call binds the parameters from its arguments, `Pair(1, "one")`, or you write them, `Box[Int]([])`, when the fields do not say (`E_GENERIC_INFER`); a record given the wrong number of type arguments, or used without any, is `E_GENERIC_ARITY`. Each set of type arguments becomes an ordinary record named `Pair<Int, Text>` in the artifact, so there is no cost at run time and no new artifact format. Generic functions may take and return generic records (`fn swap[A, B](p: Pair[A, B]) -> Pair[B, A]:`). Two instances are different types, and a generic record can be declared in one module and used from another. Limits: inference does not look through a generic-record field of another generic record (write the arguments), an empty list or map literal needs its type written, and the names `Pair<...>` appear in `guion inspect` and error messages.

## Records

Records declare an ordered set of typed fields. Construction supplies values in declaration order; access uses the field name. Values are immutable and equality is structural for values of the same declared record type.

A field can be declared `priv name: Type`: only functions in the module that declares the record can read it, assign it or construct the record, and anything else is `E_FIELD_PRIVATE`. Export functions for the record instead. (The checked templates of the `web` package rely on this for `Rendered`.)

A record held in a `var` can have a field assigned: `set b.count = b.count + 1`, and for a record inside a record `set o.inner.n = 10`. The new value must have the field's type, assigning a field of a `let` record is `E_ASSIGN_IMMUTABLE`, and a name that is not a field is `E_FIELD_UNKNOWN`. It is a change to the variable, not to the value: a copy taken earlier (`let before = b`) keeps the old field values. `set b.items = list_push(b.items, x)` and `set b = Bag(list_push(b.items, x), ...)` append in place, so building a list inside a record costs the same as building it in a plain variable.

```guion
record Point:
    x: Int
    y: Int

fn main() -> Int:
    let origin = Point(0, 0)
    let next = Point(origin.x + 1, origin.y)
    print(next.x)
    return 0
```

Record schemas and values were introduced in version-13 artifacts; format 14 added source maps, format 15 added initial build metadata, and format 16 added metadata schema versioning and source/dependency identities. Records currently cannot cross the Python interop boundary. See `language/examples/records.gu` for an executable example.

## Modules

An entry module can import another file by a relative path. Imported modules expose only declarations marked `pub`; their exported functions and records are available by name in the importing module. Private helpers stay private. The compiler rejects import cycles, path escapes, and duplicate declaration names across the graph.

```guion
import "math.gu"

fn main() -> Int:
    print(double(21))
    return 0
```

See `language/examples/modules_main.gu` and `language/examples/modules_math.gu`. Compile a project directory or entry source file with imports so Guion can resolve the full graph. Runtime errors retain the source file that produced them.

## Option and Result matching

`match` is a statement for `Option[T]`, `Result[T, E]` and your own enums. It requires exactly one arm for each variant, allows the arms in either order, and scopes each bound name to its arm. Wildcard arms, nested patterns, other matched types, and match expressions are not supported yet.

```guion
match calculation:
    Ok(value):
        print(value)
    Err(message):
        print(message)
```

See `language/examples/matching.gu` for both variants and both arm orders.

## Installing a current-host release

After extracting a Guion distribution, run `sh install.sh` to install the versioned files under `~/.local/share/guion/` and create `~/.local/bin/guion`. Pass a prefix to choose another location. The installer leaves existing unrelated `bin/guion` commands intact and does not edit shell startup files. Add the reported `bin` directory to `PATH` using the method appropriate for your shell. Installing a new distribution version updates the managed launcher and keeps prior version directories available. This installer currently targets the packaged host only.

The embedding API exposes `Runtime::vm_only()` for deterministic diagnosis and VM/JIT comparisons; `Runtime::new()` enables automatic JIT selection for eligible pure numeric functions.
