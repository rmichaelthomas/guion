# Known issues

This list covers open problems only. Rows keep their numbers. A problem that is fixed leaves this list and is recorded in the [CHANGELOG](../CHANGELOG.md) under "Resolved known issues", under the same number.

| # | Problem | Status |
|---|---------|--------|
| 22 | Function-value limits that remain after closures (artifact format 74): `sort_by`, `sort_by_key`, `sort_by_int_key`, `merge_sorted_by_int_key` and `parallel_map` take a named function or a function literal that captures nothing (a literal that uses an outside variable is `E_FN_CLOSURE` at check time; a closure passed through a variable is `R_FN_CLOSURE` when it runs); a nested `fn` cannot call itself by name; a function that forms a closure runs on the VM, not as machine code. | open |
| 23 | zstd is not supported. `std:compress` and `std:tar` cover gzip, zlib and tar only; zstd compresses and decompresses faster than gzip and usually smaller, and is a named follow-on, to be added with its own output ceiling and measured against `gzip` on the same inputs. | open |
| 32 | Templates hold `Text` and typed parameters only: there is no inheritance, macro, filter or whitespace control, and `{{ embed }}` takes a `Rendered`. The guarantee that markup cannot be written unescaped relies on `guion check` refusing a hand-written module that forges a `Rendered` (`TEMPLATE_RENDERED_FORGERY`); the language has no private fields, so the guarantee holds in a project that has a template and is checked, not for arbitrary code. See [templates.md](templates.md). | open |
| 34 | The age `tlock` stanza format (`tlock <round> <chain-hash>`) is ad hoc upstream rather than specified. `std:crypto` tlock functions and the `beacons` package match drand `tle` v1.2.0 and are pinned to it; a later `tle` that changes the stanza would break interop. | open, pinned to tle v1.2.0 |
| 35 | The self-hosted compiler in `language/self_host/` is a frozen historical artifact. It is not checked, built, tested or shipped; the CLI compiles with the Rust compiler. It cannot encode `Op::Crypto` (including the Ed25519 and timestamp codes 14 to 20), `pass`, or the `Sleep`, `TextLower`, `TextUpper`, `JsonKeys`, `JsonStringifyPretty`, `IntToTextRadix` and `TextParseIntRadix` operations, `Fs` codes 20 and 21, `Net` code 10 or `Process` code 9, so a program using them that it builds writes an artifact that fails to load with `unknown instruction tag 255`. It also does not lex the `0x`, `0o` and `0b` integer literals or the `_` digit separator, and does not know `Bytes` indexing, nested or literal `match` patterns, closures, enums or generic functions; the Rust compiler accepts all of these. See [self-hosted compiler](self-hosted-compiler.md). | by design; frozen |
| 36 | The CURBy-Q beacon has been idle since 2025-08-22: its latest pulse is a request stage, so there are no fresh pulses to verify against. | open, upstream; nothing to fix in Guion |
| 37 | NIST beacon live serialization differs from the NISTIR 8213 draft: 4-byte length prefixes, a 4-byte `statusCode`, and the raw signature appended in the `outputValue` hash input. The `beacons` README documents the real layout. | documented; the code follows the live layout |
| 38 | PS256 verification is implemented, but no live beacon chain uses it, so it has only been tested against generated vectors. | open; untested live |
| 39 | The bit operations (`int_and`, `int_or`, `int_xor` and the shifts) work on signed 64-bit `Int` operands only; there are no wider or unsigned forms. | open |
| 40 | Tape replay is relaxed by default when only program code changed: it accepts the tape when every external call matches in kind, argument hash and order. `--replay-strict` restores exact replay. The notice is on stderr in text mode and the `tape_notice` field of the `--json` run report. | by design; `--replay-strict` available |
| 41 | The browser VM runs receipt checks only when `limits.allowRaisedSteps` is set, because they need more steps than the default browser limit. | open; documented option |
| 44 | Public timestamp authorities publish no request limit: DigiCert, Sectigo and FreeTSA give none, and FreeTSA asks users not to abuse it and promises no availability; FreeTSA's signing certificate was renewed in 2026, and Sectigo's tokens carry a wrong `ESSCertID.issuerSerial` (`crypto_tsa_verify` compares the certificate hash only, so it accepts them). A service should make one request per draw, keep the response, and pin the certificate it verified. See `crates/crypto/tests/fixtures/tsa/README.md`. | documented; nothing to fix in Guion |
| 46 | `sleep_ms` and random bytes are not available in the browser VM: a page cannot block, and `crypto_random_bytes` stays native-only, so a page that generates an Ed25519 key or a timestamp nonce supplies the randomness itself. | by design; documented in browser.md |
