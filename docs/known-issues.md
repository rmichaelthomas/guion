# Known issues

This list covers open problems only. Each row has a status. When an item is fixed, its status changes to `fixed in <short commit>`.

| # | Problem | Status |
|---|---------|--------|
| 1 | Reading CSV files is about 45 times slower than pandas. | fixed in 8cdf52c |
| 2 | Calling a small helper inside a large guest loop costs microseconds per call. | fixed in ae485c5 |
| 3 | Multiplying two 512 by 512 f64 matrices is about 2.3 times slower than NumPy (it was about 25 times). | fixed in 6ea65aa (the packed kernel of 8d73df4 measured 3.03 times; the committed compute-only lane, `evaluation/development/arrays/matmul_compute.py`, 31 trials, one Apple M1 Pro, now measures 1.46 ms against NumPy's 0.64 ms per multiply, 2.26 times, under the target of 2.5; the kernel itself runs at about 45 Gflop/s on one core, close to the chip's peak, so what remains is NumPy's vendor BLAS and thread start-up). On x86_64 without FMA the scalar kernel is about 10 times slower; it is kept so results stay bit-identical |
| 4 | Element-wise array maths costs about 2 times NumPy's cost per element. | fixed in db55344 (10M `a*b+c` compute estimate 1.45 times NumPy, down from 2.1; an in-place `set r = array_add(r, b)` loop runs at 0.86 times NumPy) |
| 5 | The self-hosted compiler emits `ArraySet` where it could emit `ArraySetLocal`. | fixed in 4c19507 |
| 6 | Large files need the project to raise `max_file_bytes`, and the allocation-limit error does not say how to raise it. | fixed in c071ffd |
| 7 | `array_i64_range` can panic in debug builds on extreme operands. | fixed in 6fb8d20 |
| 8 | Temporary buffers in matmul, sort and argsort, factorize and join_index are not charged to the allocation budget. | fixed in 6fb8d20 |
| 9 | Array error messages use internal operation names. `array_clip` with low greater than high raises `R_ARRAY_SHAPE`. | fixed in be924e7 |
| 10 | The Rust and self-hosted compilers give different error codes for `Array[i128]` and `Array[Array[f64]]`. | fixed in 130013f |
| 11 | The spec says element types outside `Array[...]` should give `E_TYPE_UNKNOWN`. Both compilers give `E_TYPE_ANNOTATION`. | fixed in 130013f |
| 12 | `catalog_array_builtin` can return `Ok(None)` after it has emitted argument code. Only a test guards this. | fixed in 130013f |
| 13 | Empty text becomes missing after a CSV round trip. | fixed in 8cdf52c |
| 14 | `frame_show` misaligns wide characters and text that contains newlines. | fixed in 99f685c |
| 15 | A join fails when the `<name>_right` column name is already taken. | fixed in 99f685c |
| 16 | `column_from_codes` does not check its codes. | fixed in 99f685c |
| 17 | Very large and very small floats are written in full decimal form. | fixed in 99f685c |
| 18 | JSONL keys first seen after line 1 are dropped. | fixed in 99f685c |
| 19 | `array_mean_by` is not used by `frames`, and `group.gu` has an unused local. | fixed in 99f685c |
| 20 | Filtering a 1M-row frame after the read takes about 10 ms, 2 to 4 times pandas (measured in the speed report; the pandas part is within the noise of the method). | fixed in 48e2763: measured in-process (evaluation/development/frames/step_timing.py, 15 batches of 20 steps, M1 Pro release build) the filter-and-sum step is 5.8 ms in Guion against 4.6 ms in pandas, 1.26 times; the earlier figure came from subtracting whole-process medians |
| 21 | A single-column CSV file lost a row whose value was missing, because a blank line was skipped. | fixed in 99f685c |
| 22 | Function values cannot capture variables: only named top-level functions can be values, and a lambda or a nested `fn` is `E_FN_NO_CLOSURES`. A function that needs context takes it as an argument or in a record. | open |
| 23 | zstd is not supported. `std:compress` and `std:tar` cover gzip, zlib and tar only; zstd compresses and decompresses faster than gzip and usually smaller, and is a named follow-on, to be added with its own output ceiling and measured against `gzip` on the same inputs. | open |
| 24 | `tar_write` archives are listed by macOS `tar -tzf` in the tests. The same check on Debian 12 (GNU tar 1.34, run in the `debian:12` image on 2026-11-14) passes: a tree with a nested directory, an empty directory, a 5,000-byte file and a non-ASCII file name lists identically to macOS under a UTF-8 locale (the default C locale prints the non-ASCII name as octal escapes, which is GNU tar's display, not the archive), `.tar` and `.tgz` list the same, and the extracted files match the originals byte for byte. Archive entries carry mode 644, owner 0/0 and modification time 1970-01-01 so the same tree always produces the same bytes. | fixed |
| 25 | CPU-bound `parallel_map` jobs do not run faster with a higher worker limit: four 100,000,000-iteration jobs took 972 ms at limit 1 and 1,745 ms at limit 4 on one Apple M1 Pro (2026-11-13, median of 5). The worker count is a ceiling for waiting (network, database, held connections), not a multiplier for computing. Measured and explained in [concurrency.md](concurrency.md); the cause is not fixed. | open |
| 26 | The browser VM does not implement the `HigherOrder` host operation or the sort and `parallel_map` operations, so `sort`, `sort_by`, `sort_by_int_key`, `merge_sorted_by_int_key`, `map_list`, `filter_list`, `fold_list`, `any_list`, `all_list` and `parallel_map` fail with `R_HOST_UNSUPPORTED` in the playground. Function values themselves (`let f = double; f(21)`) work. See [browser.md](browser.md). | open |
| 27 | `guion doc --json` and `guion inspect` did not model SQLite: `std:sqlite` functions reported no effect. 0.4.0 reports `filesystem.read` for `sqlite_query` and `sqlite_begin_read`, `filesystem.write` for `sqlite_execute`, `sqlite_begin`, `sqlite_commit` and `sqlite_rollback`, and both for `sqlite_open`, which re-signs those functions (a deliberate break, stated in the changelog; VERSIONING.md section 2 allows it at 0.x). A package that opens a database now needs `files` in its `[capabilities]`. | fixed in 0.4.0 |
| 28 | `guion add --path` and `guion update` rewrite a relative path dependency to an absolute path in `guion.toml`, so a manifest with a path dependency is not portable between machines or checkouts. | open |
| 29 | The `web` middleware has no closures to carry settings. A `Middleware` is a record of named `before` and `after` functions plus a `config` map they receive first; a layer cannot be built by wrapping a function in another function (see known issue 22). | open |
| 30 | A runtime fault in a `serve` worker (an out-of-range index, a step limit) is not recoverable per request: it stops every worker and `serve` returns an `Err`, and connections in flight get no response. A handler that returns `Err` gets a 500 per request; only a fault stops the pool. Handlers return `Err` rather than fault. | open |
| 31 | `csrf_middleware` checks the token only. It does not compare the `Origin` or `Referer` header with the site's own, so a deployment that wants that defence adds a layer for it. | open |
| 32 | Templates hold `Text` and typed parameters only: there is no inheritance, macro, filter or whitespace control, and `{{ embed }}` takes a `Rendered`. The guarantee that markup cannot be written unescaped relies on `guion check` refusing a hand-written module that forges a `Rendered` (`TEMPLATE_RENDERED_FORGERY`); the language has no private fields, so the guarantee holds in a project that has a template and is checked, not for arbitrary code. See [templates.md](templates.md). | open |
| 33 | The browser VM does not host the function-value builtins the `web` package leans on (`map_list`, `filter_list`, `fold_list`, `any_list`, `all_list`, the sorts and `parallel_map`); they fail with `R_HOST_UNSUPPORTED` there. Same cause as issue 26; `web` is a server package and is not meant for the playground. | open |
