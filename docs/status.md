# Guion status

**Stage:** active development. An earlier validation cohort passed on macOS ARM64 and Debian 12 GNU/Linux on ARM64 and x86_64, all with glibc. That cohort predates artifact format 44. Named current-format managed packages now pass on macOS ARM64 and Debian 12 ARM64 and x86_64. Feed Digest passes on macOS ARM64 and both Debian architectures: ARM64 natively and x86_64 under Rosetta. Broader package coverage remains open.

## What is established

- The default core CLI embeds a self-hosted compiler and runs on the Rust runtime. It can create, check, format, lint, test, run, build, package, verify, install, inspect, and document Guion programs.
- The current language includes typed functions and records, modules, collections, `Option`/`Result`, JSON, bounded file and HTTP operations, SQLite/TOML services, Unicode helpers, and bounded parallel work. The [language contract](../language/spec.md) is authoritative about what syntax works and what remains unsupported.
- New source, artifact, manifest, lock, and local-state names are `.gu`, `.gub`, `guion.toml`, `guion.lock`, and `.guion/`. A limited set of old Veritas project names remains readable during migration; see [compatibility](compatibility-and-migrations.md).
- The Guion-identity release matrix passed on macOS ARM64 and Debian 12 GNU/Linux on ARM64 and x86_64, all with glibc. This does not establish support for other operating systems, CPU architectures, or libc variants.

## Current evidence and its limits

- The current-main checkpoint used artifact format 44 on macOS ARM64. Guion and Python each passed **127/127** frozen application cases; seven-pair timing comparisons favored Guion in all nine selected everyday tasks (ratios **0.137–0.845**). The five 21-pair short-source gates passed. Richards uncached source measured **27.46 ms vs. 72.92 ms** for CPython 3.14.7 (ratio **0.375**, 95% interval **0.370–0.379**), passing the 0.60 target. N-body, Mandelbrot, parallel CPU, and 20k/200k JSONL outputs also passed their checks. The [current-main checkpoint](../evaluation/completion/results/real-task-sprint/2026-10-27-current-main-outcome-checkpoint.md) contains medians, intervals, memory, and limits.
- Current-format concurrency now has evidence beyond CPU-only workers. The frozen app cases exercised calendar fan-out across five feeds and health checks with mixed service responses, each capped at two simultaneous requests. A runtime regression also confirms that a failing HTTP worker interrupts an in-flight sibling request and closes its socket. This closes the named current-host failure/cancellation scenarios; it does not establish a general async runtime or cross-target format-44 behavior. See the [concurrent HTTP cancellation report](../evaluation/completion/results/real-task-sprint/2026-10-27-parallel-http-cancellation.md).
- A current format-44, macOS ARM64 bridge follow-up used one typed Python call to process 100,000 JSON rows through NumPy 2.5.1 and orjson 3.11.9. A same-host 15-pair comparison did not establish a speed change after borrowed request serialization and sidecar frame-copy reductions: the candidate/pre-change ratio was **1.012** (95% interval **0.985–1.025**). Guion remains **1.129×** slower than the same package function in Python and **1.406×** slower than the standard-library reference. All reports matched byte-for-byte. This code reduces intermediate copies but has not shown a speedup or measured peak-memory reduction. See the [serialization follow-up](../evaluation/completion/results/real-task-sprint/2026-10-27-python-bridge-serialization.md) and [raw samples](../evaluation/completion/results/real-task-sprint/2026-10-27-python-bridge-serialization.json); the earlier separate cohort remains in the [initial bridge report](../evaluation/completion/results/real-task-sprint/2026-10-27-python-bridge-package-analysis.md).
- The next current-format bridge pass added private protocol-v2 raw-byte request attachments and compared the same 100,000-row task in 15 randomized output-checked pairs. Guion `Bytes` reduced the Guion median by **13.7%** versus Guion `Text` (140.59 vs. 161.60 ms; paired ratio **0.863**, 95% interval **0.859–0.879**). It came close to the same NumPy/orjson Python function at **137.93 ms**, but Guion remained **2.5% slower** (ratio **1.025**, 95% interval **1.001–1.027**), and **22% slower** than the standard-library Python reference. Outputs matched exactly. This is a targeted improvement on one payload-heavy task, not a general language-speed result; host CPU stacks and peak memory remain unmeasured. See the [plain-English report](../evaluation/completion/results/real-task-sprint/2026-10-27-python-bridge-bytes.md) and [raw evidence](../evaluation/completion/results/real-task-sprint/2026-10-27-python-bridge-bytes.json).
- The 2026-10-28 bridge follow-up removed one full-size temporary allocation while keeping Python arguments as immutable `bytes`. The parser allocation regression fell from a 10,202,573-byte peak to below its 7,651,300-byte bound for a 5,100,867-byte attachment. On the full workload, Guion `Bytes` measured 138.49 ms versus 136.05 ms for the same package-backed Python function; the paired ratio was **1.020** (95% interval **0.988–1.031**), so this run does not establish a winner. Guion remained **19.9% slower** than the standard-library reference (ratio **1.199**, 95% interval **1.177–1.225**). Every output matched exactly. See the [copy-reduction report](../evaluation/completion/results/real-task-sprint/2026-10-28-python-bridge-single-copy.md) and [raw evidence](../evaluation/completion/results/real-task-sprint/2026-10-28-python-bridge-single-copy.json).
- A no-op `Bytes` probe keeps the 5,100,867-byte transfer, sidecar startup, and NumPy/orjson imports but returns only the input length. In 15 randomized fresh-process pairs, Guion measured 89.22 ms versus 81.99 ms for direct Python; the ratio was **1.078** (95% interval **1.045–1.121**), with 14/15 pairs slower in Guion. Every output matched. This is the total pre-computation path and does not separate process startup from payload transfer; an empty-Bytes control is next. See the [probe report](../evaluation/completion/results/real-task-sprint/2026-10-28-python-bridge-startup-5mb.md) and [raw evidence](../evaluation/completion/results/real-task-sprint/2026-10-28-python-bridge-startup-5mb.json).
- Current-format managed packaging passes on macOS ARM64 for the mixed-dependency fixture and the 100,000-row NumPy/orjson analysis, and on Debian 12 ARM64 and x86_64 for the analysis. The three analysis bundles are source-free, relocate to a path with spaces and Unicode, and launch twice without external Python/uv settings while matching the independent report exactly. Their uncompressed directory sizes are 157,585,367 bytes on macOS, 244,199,858 bytes on Debian ARM64, and 274,853,607 bytes on Debian x86_64. `GUION_PYTHON_CACHE_DIR` lets package assembly seed its offline cache from a preloaded uv cache. This closes the named package outcomes on these targets, not broad Python package compatibility. See the [mixed-dependency report](../evaluation/completion/results/real-task-sprint/2026-10-27-current-format-managed-python-package.md), [macOS analysis report](../evaluation/completion/results/real-task-sprint/2026-10-27-current-format-managed-package-analysis.md), [Debian ARM64 analysis report](../evaluation/completion/results/real-task-sprint/2026-10-27-current-format-managed-package-analysis-debian-aarch64.md), and [Debian x86_64 analysis report](../evaluation/completion/results/real-task-sprint/2026-10-27-current-format-managed-package-analysis-debian-x86_64.md). The first QEMU attempt and Rosetta retry are both documented.
- A separate current-format Feed Digest package adds managed pure-Python package coverage with feedparser 6.0.14 and feedparser-sgmllib 2.1.0. Six source cases and six relocated-package cases matched the independent Python implementation byte-for-byte on macOS ARM64, Debian 12 ARM64, and Debian 12 x86_64. The packages retain the exact loopback host grant, complete license records, and no native extensions from these Python dependencies; their uncompressed directories are 172,422,430 bytes on macOS, 128,874,649 bytes on Debian ARM64, and 158,943,069 bytes on Debian x86_64. The Debian ARM64 run used the native path in the existing Colima VM without Rosetta; x86_64 used Rosetta, not QEMU. This broadens the evidence by one library and application; general package compatibility remains open. See the [macOS report](../evaluation/completion/results/real-task-sprint/2026-10-27-feed-digest-managed-package.md), [Debian ARM64 report](../evaluation/completion/results/real-task-sprint/2026-10-28-feed-digest-managed-package-debian-aarch64.md) and [raw evidence](../evaluation/completion/results/real-task-sprint/2026-10-28-feed-digest-managed-package-debian-aarch64.json), plus the [Debian x86_64 report](../evaluation/completion/results/real-task-sprint/2026-10-28-feed-digest-managed-package-debian-x86_64.md).
- The lockfile auditor now passes 17/17 frozen cases in both languages and emits exact output through 16,384 packages / 32,768 diagnostics. On this Mac, Guion measured 171.82 ms versus Python's 179.87 ms at that size, with peak RSS of 40.92 versus 47.13 MiB. This closes the scale, speed, and RAM gap for this workload; it is not a general-purpose speed or memory result. See the [lockfile report](../evaluation/completion/results/real-task-sprint/2026-10-27-lockfile-scale-ram-package-limit.md).
- The earlier target cohort has 18 passing application reports for each of nine retained regression applications across initial and follow-up variants on each of the three targets: 54 of 54 reports passed. The preserved inputs and original Veritas reports were not rewritten.
- The Guion installed-performance report is [`performance-guion.json`](../evaluation/completion/results/guion-final/performance-guion.json), with command, correctness, and comparison records in [`performance.json`](../evaluation/completion/results/guion-final/performance.json). It measures the Guion ARM64 installed artifact against pinned, GIL-enabled CPython 3.14.7 on macOS. The report retains raw paired samples and percentile intervals. The newer Debian x86_64 validation was functional and release-focused; it adds no performance comparison.
- The earlier Guion package-performance report measured the installed CLI. The newer runtime-efficiency cohort separately measured fresh uncached source and prebuilt `.gub` program artifacts through the release CLI; both were faster than pinned CPython 3.14.7 on each named workload. On 200,000-row JSONL, uncached source took a 4.025-second median versus 17.670 seconds for the Python data reference; the prebuilt program artifact median was 4.030 seconds. A focused runtime change reduced the uncached-source median from the merged baseline's 4.160 seconds by 3.2%; the candidate/baseline median-ratio bootstrap interval was [0.941, 0.983]. Peak RSS was effectively unchanged. The five 21-pair short-source gates passed again. See the [runtime-efficiency summary](../evaluation/completion/results/runtime-efficiency/2026-10-26-summary.md) and its linked raw reports. These results cover named programs and conditions only; they do not show that Guion generally outperforms or replaces Python. Free-threaded Python remains unmeasured because it was unavailable.
- The frozen independent recommendation campaign selected Python in all 18 choices for its older candidate. A later three-pair builder study recommended either language for two work classes and Veritas for one. These are separate historical studies with different questions; neither is a general adoption estimate.

- The 2026-10-25 source-run sprint added a bounded source compilation cache. Its results are historical and remain in the [dated comparison](../evaluation/completion/results/source-loop/final-comparison-20261026.json) and [readiness section](pre-release-readiness.md#source-run-and-launch-speed-sprint-2026-10-25). The later 2026-10-26 cohort above reran uncached source and supersedes that sprint's source-versus-Python comparisons for the named workloads.

## CI and release gates

GitHub Actions runs formatting, strict Clippy, workspace tests, schema checks, generated agent-reference validation, and switch-condition evidence validation on Ubuntu x86_64. That job is a source check only; it does not certify Guion's supported release targets. The full release gates run on macOS ARM64 and Debian 12 GNU/Linux on ARM64 and x86_64 with glibc. A target that did not run is reported as incomplete.

## Remaining product outcomes

The current-main checkpoint and named managed-package fixtures are complete on macOS ARM64; the 100,000-row analysis package passes on Debian 12 ARM64 and x86_64, and Feed Digest passes on macOS ARM64 and both Debian architectures. Current-format application packaging now includes both native-wheel data processing and pure-Python feed parsing. The same-package Python bridge comparison now spans parity within the latest interval, but it does not establish a Guion win; the standard-library reference remains faster. The no-op 5.1 MB probe shows a 7.8% total-path cost before application computation, with process startup and payload transfer not yet separated. Broader package usefulness, bridge efficiency, and language learnability remain open. Historical recommendation exercises remain exploratory evidence, not a measure of broad adoption. See the [north-star design](north-star-design.md), [validation report](pre-release-readiness.md), the [latest bridge-cost report](../evaluation/completion/results/real-task-sprint/2026-10-28-python-bridge-single-copy.md), the [no-op probe](../evaluation/completion/results/real-task-sprint/2026-10-28-python-bridge-startup-5mb.md), and the [Feed Digest reports](../evaluation/completion/results/real-task-sprint/2026-10-27-feed-digest-managed-package.md), [Debian ARM64](../evaluation/completion/results/real-task-sprint/2026-10-28-feed-digest-managed-package-debian-aarch64.md), and [Debian x86_64](../evaluation/completion/results/real-task-sprint/2026-10-28-feed-digest-managed-package-debian-x86_64.md).
