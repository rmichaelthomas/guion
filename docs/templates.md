# Checked templates

A template is a `NAME.gut` file that compiles to a Guion function returning `Rendered`, markup built only from escaped parts. The compile step runs in the `guion` command line before the project is compiled, so the compiler and the compiled program know nothing about templates: the artifact holds the generated functions and the escapers of the `web` package, and no template parser.

Two properties are the point:

- There is no way to switch escaping off. No tag, filter, flag or argument does it, and a `Rendered` value can only come from a template.
- A template is checked before it runs. An unknown variable, an unbalanced block, a wrong type or an interpolation in a place that cannot be made safe is an error with a code, a file, a line and a column.

## Using templates

A project that has templates depends on `web` (`guion add web`) and puts each `NAME.gut` anywhere below its entry file's directory, for example `src/templates/page.gut`. Every `guion check`, `build`, `run`, `test`, `inspect`, `doc`, `fmt`, `lint` and `package` first compiles each template to `NAME.gut.gu` next to it; import that module like any other:

```
# src/templates/page.gut
{% params title: Text, names: List[Text] %}
<h1>{{ title }}</h1>
<ul>{% for n in names %}<li>{{ n }}</li>{% end %}</ul>
```

```
# src/main.gu
import "templates/page.gut.gu"

fn main() -> Int:
    print(render_page("A & B", ["<x>", "y"]).html)
    return 0
```

The generated module imports `pkg:web/src/html.gu` publicly, so one import brings `render_page`, `Rendered` and `html_response(status, rendered)` (a `Response` with `text/html; charset=utf-8`) into scope. The generated function is pure.

Generated modules are named `*.gut.gu`, start with the line `# generated by guion from NAME.gut; do not edit; do not commit`, and the pre-pass keeps the line `*.gut.gu` in the `.gitignore` of the directory that holds them (it creates the file or appends the line, and touches nothing else). A generated module is rewritten only when its text changes and removed when its template is gone; a file with that suffix that lacks the first line is never touched. `guion fmt` and `guion lint` skip a generated file; they refuse a `.gut` file.

A project with no `.gut` files is not touched at all.

## Syntax

A header, then text with tags. Header lines come first and are dropped from the output:

```
{% import "rows.gu" %}                     user types: a path at or below the template's directory (imports go downward), `std:` or `pkg:`
{% params title: Text, rows: List[Row] %}  typed parameters of render_NAME; optional
```

| Tag | Meaning |
|---|---|
| `{{ x }}`, `{{ x.field }}` | a `Text` value, escaped for element text and for a quoted attribute value |
| `{{ attr x }}` | the same, for a quoted attribute value, plus the backtick |
| `{{ url x }}` | one URL component, percent-encoded |
| `{{ script x }}` | a JSON string literal, for an expression position inside `<script>` |
| `{{ embed r }}` | a `Rendered` value, inserted as it is; nothing else is accepted |
| `{{ embed other(a, b) }}` | the `Rendered` that the sibling template `other.gut` returns for `a` and `b` |
| `{% for r in rows %}...{% end %}` | repeat for each item |
| `{% if flag %}...{% else %}...{% end %}`, `{% if not flag %}` | a `Bool` variable or field |
| `\{{`, `\{%` | the literal characters |

Variables are parameters and loop variables; fields are read with `.`. Only `Text` is interpolated (convert an `Int` with `int_to_text` before the call). There are no expressions, filters or template-side calls: composition is function composition, and extension points are values passed in. A parameter or loop variable may be called `embed`, `script`, `attr` or `url`; `{{ url }}` is that variable, escaped like any other. Names starting `html_` or `gut_`, `list_push`, `Rendered` and Guion keywords are reserved (`TEMPLATE_RESERVED_NAME`).

## Where an interpolation is allowed

The pre-pass tracks the HTML around each tag and accepts an interpolator only where it is safe, so each rule below is also a build error:

| Position | allowed | refused with |
|---|---|---|
| element text | `{{ x }}`, `attr`, `url`, `embed` | `script`: `TEMPLATE_SCRIPT_OUTSIDE_SCRIPT` |
| quoted attribute value | `{{ x }}`, `attr`, `url` | `script`: `TEMPLATE_SCRIPT_OUTSIDE_SCRIPT`; `embed`: `TEMPLATE_EMBED_CONTEXT` |
| URL attribute (`href`, `src`, `action`, `formaction`, `poster`, `cite`, `data`, `ping`, `background`, `xlink:href`, ...) | `url` | `{{ x }}` or `attr`: `TEMPLATE_URL_CONTEXT` |
| `on*`, `style`, `srcdoc`, `srcset` attributes | nothing | `TEMPLATE_ATTRIBUTE_CODE_CONTEXT` |
| inside `<script>` | `script` | `{{ x }}`, `attr`, `url`: `TEMPLATE_SCRIPT_CONTEXT`; `embed`: `TEMPLATE_EMBED_CONTEXT` |
| inside `<style>` | nothing | `TEMPLATE_STYLE_CONTEXT` |
| HTML comment | nothing | `TEMPLATE_COMMENT_CONTEXT` |
| tag name, attribute name, `<!...>` | nothing | `TEMPLATE_TAG_CONTEXT` |
| unquoted attribute value | nothing | `TEMPLATE_UNQUOTED_ATTRIBUTE` |

A `for` or `if` body must leave the HTML in the state it found it, so every tag has exactly one context (`TEMPLATE_CONTEXT_MISMATCH`).

What each interpolator writes:

- Text and attribute: `&`, `<`, `>`, `"`, `'` become `&amp;`, `&lt;`, `&gt;`, `&quot;`, `&#39;` (attribute adds the backtick as `&#96;`).
- URL: every character except `A-Z a-z 0-9 - . _ ~` is percent-encoded as UTF-8, so `javascript:alert(1)` becomes `javascript%3Aalert%281%29` and cannot be a scheme. A whole URL cannot be passed through; write the literal start and interpolate components (`href="/items/{{ url id }}"`).
- Script: a JSON string literal (`"..."`) in which `<`, `>`, `&`, `'`, the backtick, `$`, U+2028 and U+2029 are `\uXXXX`, so the value cannot close the element, leave a quote it is pasted into, or open a template literal. Use it as an expression (`var x = {{ script x }};`), not inside another string.

## Errors

Every template error prints `FILE.gut:LINE:COLUMN: error[CODE]: message` (and the JSON form with `--json` on the commands that have one). Codes: `TEMPLATE_UNKNOWN_VARIABLE`, `TEMPLATE_UNKNOWN_FUNCTION`, `TEMPLATE_UNKNOWN_INTERPOLATOR`, `TEMPLATE_UNKNOWN_TAG`, `TEMPLATE_UNCLOSED_TAG`, `TEMPLATE_UNBALANCED_BLOCK`, `TEMPLATE_UNBALANCED_END`, `TEMPLATE_UNEXPECTED_ELSE`, `TEMPLATE_BAD_EXPRESSION`, `TEMPLATE_BAD_PARAMS`, `TEMPLATE_BAD_IMPORT`, `TEMPLATE_BAD_NAME`, `TEMPLATE_HEADER_POSITION`, `TEMPLATE_DUPLICATE_VARIABLE`, `TEMPLATE_RESERVED_NAME`, `TEMPLATE_CYCLE`, `TEMPLATE_RUNTIME_MISSING`, `TEMPLATE_OUTPUT_EXISTS`, `TEMPLATE_RENDERED_FORGERY` and the context codes above.

Type errors come from the ordinary compiler and are shown at the template position: `{{ n }}` with `n: Int`, `{{ embed body }}` with `body: Text` and `{{ r.nope }}` with no such field are `E_TYPE_ARGUMENT` or a field error at the line and column of the tag. A caller with the wrong argument count gets `E_CALL_ARITY` at the call.

## What is and is not guaranteed

A template cannot write data without escaping it for its position, and `{{ embed }}` takes only a `Rendered`. The language has no private fields, so a hand-written `Rendered(...)` would be possible; in a project that has at least one template, `guion check` refuses any hand-written module that names `Rendered(`, `html_finish` or `html_embed_rendered` (`TEMPLATE_RENDERED_FORGERY`). Reading `r.html` is allowed. A project with no templates is not scanned.

Not covered: the markup the template's author writes (it is source, like any other), SVG and MathML specifics beyond `<script>` and `<style>`, and the HTML double-escaped script corner (`<!-- <script>`). There is no inheritance, no macro language, no whitespace control and no filter syntax.
