### Task 10 — Package once, verify both targets, and close the speed goal

**Files:** distribution scripts/installer/auditors and native component manifest; xtask release/performance; `evaluation/completion/performance/{manifest.json,runner,inputs}/`; final installed acceptance tests.

**Consumes:** Task 9 product. **Produces:** one canonical core distribution per supported target and reproducible final performance evidence.

- [ ] Move core packaging/license/dependency/archive audit work needed by a source build into Rust tooling. Existing Python audit scripts may remain historical or optional external verifiers; they are not a core installer, compiler, or package dependency.
- [ ] Build matching macOS ARM64 and Debian-compatible Linux ARM64 releases from the same source state. Bundle compiler seed, standard library, target-native dependencies, timezone/Unicode data, licenses, local docs and metadata. Record actual OS/libc constraints. Signing/notarization, Windows, browser and phone deployment are outside this previously established target contract.
- [ ] Run installer and source-free application relocation from a path with spaces/Unicode, with original source and development caches inaccessible and the candidate environment unable to execute Python/uv. Verify read-only install roots plus writable caller data, changed working directory, artifact tampering, dependency mismatch and repeated launches. Inspect actual dynamic library dependencies, including libical/SQLite support assets.
- [ ] Establish the final performance manifest before timing: existing scheduler/numeric/image/parallel workloads, durable checked-in JSON analysis input generator, and actual CPU/data phases of the native applications. Preserve original required arithmetic, parsing, validation and output semantics. Retain original upstream source provenance and label translations accurately.
- [ ] Measure source-run end-to-end latency, prebuilt-artifact execution, long-lived warm execution, peak memory and package size separately. Use a release build, fixed inputs, alternating/randomized candidate order and the same host/session. Fifteen measured trials and existing 16-pair data trials are starting sample sizes; retain all samples and bootstrap intervals, with seed/method recorded.
- [ ] Compare to the pinned CPython baseline and reasonable idiomatic Python implementations, including a native-backed data approach when relevant. Compare CPU concurrency to threads, processes and a verified free-threaded CPython build; do not present a GIL-only win as the whole current-Python comparison. If that baseline is unavailable, finish other work and report the specific concurrency claim as unverified.
- [ ] G2 completion requires correct outputs and reproducible speed wins on the established scheduler/numeric/image/parallel compute set and the real data workload, with a 95% interval for the median Veritas/Python time ratio below 1 for each advertised win. Report ties and regressions. Network waits are not evidence of compute speed. If a required workload fails, profile the real installed path, repair the shared bottleneck and rerun the affected workload plus impacted correctness checks.
- [ ] Reverify hashes after execution; normal runs must not mutate immutable package contents. Keep one current final artifact per target plus the prior recovery artifact. Do not generate a new directory for every internal compile.

**Verify:** `cargo xtask release --target both` and `cargo xtask performance --installed` pass required release checks and produce complete raw reports. Clean-room language/product independence must be demonstrated; a PATH-only assertion is insufficient if another executable path still reaches Python or stage zero.
