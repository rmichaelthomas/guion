## 0.8.0 (unreleased)

- `beacons` package, part 2 (`packages/beacons`): Twine and CURBy in Guion. `twine_verify` recomputes a record's CID (DAG-CBOR then SHA3-512 over `data`), checks that the JWS payload is the SHA3-512 multihash of the DAG-CBOR of `data.content`, and verifies the JWS (RS256, PS256 or ES256; other algorithms are `E_TWINE_ALG`) under the chain's JWK; a tampered content, signature or CID is `false` or an error, never `true`. `twine_verify_links` / `twine_verify_links_in` walk back through `links[0]`; `twine_fetch_chain`, `twine_fetch_latest` and `twine_fetch_pulse` only fetch. `curby_q_chain`, `curby_rng_chain`, `curby_randomness` (the 64 bytes of a CURBy-Q randomness pulse) and `curby_rng_randomness` (CURBy-RNG, with the precommitment check). The latest CURBy-Q, CURBy-RNG and a P-256 chain pulse verify, and the bytes match CURBy's own JavaScript client; the live run is recorded in `packages/beacons/tapes` and replays offline.
- `beacons` package, part 1 (`packages/beacons`, not published to the registry): base32, varint and CIDv1 helpers (`base32_lower_encode`, `cid_v1`, `cid_parse`), and drand quicknet in Guion over the new crypto primitives: `drand_fetch` (falls back from `api.drand.sh` to `drand.cloudflare.com`), `drand_verify` (BLS check plus `randomness == SHA-256(signature)`), round arithmetic, and `tlock_seal` / `tlock_open` (refuses another chain with `E_TLOCK_CHAIN` and a future round with `E_TLOCK_TOO_EARLY`). 100 consecutive live quicknet rounds verified; the run is recorded in `packages/beacons/tapes` and replays offline.
- `guion run` writes each `print` and `eprint` as it happens instead of after `main` returns, so a program used as a stdio tool or read through a pipe delivers lines at once. `output_limit_bytes` still counts every byte. A reader that closes the pipe stops the program with the new stable code `R_OUTPUT_CLOSED`. `guion run --json`, `guion test`, `guion serve` and embedders keep buffering; `HostPolicy::with_streaming_output(true)` turns streaming on for an embedder.
- `std:io` reads the program's own standard input (artifact format 77, from 76; older artifacts still load). `stdin_read_line() -> Result[Option[Text], StdError]` gives each line without its line ending and `None` at the end; `stdin_read_all() -> Result[Bytes, StdError]` gives the rest as raw bytes, bounded by `max_file_bytes`. `[runtime] stdin_line_limit_bytes` (default 1048576) bounds a line. Typed errors: `E_STDIN_LINE_LIMIT`, `E_STDIN_UTF8`, `E_STDIN_READ`, `E_STDIN_LIMIT`. Needs no grant; `guion inspect` reports the effect `process.stdin`. `--record` keeps what was read; the browser playground refuses it with `R_HOST_UNSUPPORTED`. New instructions `StdinReadLine` (221) and `StdinReadAll` (222).
- `language/examples/mcp_server` is a Model Context Protocol server written in Guion: newline-delimited JSON-RPC 2.0 over stdio with `initialize`, `ping`, `tools/list` and an `echo` tool. It reads requests with `stdin_read_line`, answers each one as it arrives, and ends at end of input. Its `guion.toml` raises `instruction_limit` and `output_limit_bytes` because a long-running stdio tool would otherwise hit the script-sized defaults.
- `std:encoding` adds `dagcbor_encode(value: Json) -> Result[Bytes, StdError]` (artifact format 82, from 81; older artifacts still load): canonical DAG-CBOR, hand-written in `guion-crypto` with no IPLD crate. Integers use the shortest form, other numbers are 64-bit floats, map keys sort by encoded length then bytes, `{"/": "<cid>"}` is a tag-42 link and `{"/": {"bytes": ...}}` a byte string. `E_DAGCBOR_VALUE` for NaN, infinities, out-of-range integers and nesting past 128 levels; `E_DAGCBOR_LINK` for a malformed link. `Crypto` function code 9, gated on format 82. Pure, so it runs in the browser playground. Checked by recomputing the CIDs of live CURBy chain records (CIDv1, dag-cbor, SHA3-512, over the whole `data` object). Adds `serde_json` to `guion-crypto`.
- `std:crypto` adds drand timelock encryption (artifact format 81, from 80; older artifacts still load): `crypto_tlock_encrypt(round, chain_hash, public_key, plaintext) -> Result[Text, StdError]`, `crypto_tlock_decrypt(armored, round_signature) -> Result[Bytes, StdError]` and `crypto_tlock_round(armored) -> Result[Int, StdError]`. The output is armored age, byte-compatible with drand's Go `tle` (tlock v1.2.0) on the quicknet network, checked in both directions. A wrong round signature or a changed file is `E_TLOCK_DECRYPT`, a malformed file `E_TLOCK_FORMAT`, bad keys or signatures `E_CRYPTO_INPUT`. `Crypto` function codes 6 to 8, gated on format 81. Pure (the wrapper draws 48 bytes with `crypto_random_bytes`), so it runs in the browser playground. Adds `hkdf` and `chacha20poly1305` with no random-number source. The construction is in `crates/crypto/src/tlock.md`.
- `std:crypto` adds `crypto_bls12381_verify_g1` (artifact format 80, from 79; older artifacts still load): BLS12-381 min-signature verification (48-byte G1 signature, 96-byte G2 public key, RFC 9380 hash to G1 with the caller's domain separation tag), enough to check a drand quicknet round. `Crypto` function code 5, gated on format 80. Malformed or out-of-subgroup points are `E_CRYPTO_INPUT`; a signature that does not verify is `Ok(false)`. Pure, so it runs in the browser playground. Adds the arkworks crates `ark-bls12-381`, `ark-ec`, `ark-ff` and `ark-serialize` (0.5.0), pinned exactly, with no random-number dependency.
- `std:crypto` verifies signatures (artifact format 79, from 78; older artifacts still load): `crypto_rsa_verify` (PKCS#1 v1.5 with SHA-256 or SHA-512, and PSS with SHA-256), `crypto_ecdsa_p256_verify` (raw 64-byte r and s, SHA-256), `crypto_x509_rsa_public_key` (modulus and exponent from a DER certificate) and `crypto_pem_decode` (written in Guion over `base64_decode`). `Crypto` function codes 2 to 4, gated on format 79 per code. A malformed key, length, scheme or certificate is a typed `StdError` (`E_CRYPTO_INPUT`, `E_CRYPTO_SCHEME`, `E_X509`); a signature that does not verify is `Ok(false)`. Verification only, and pure, so it runs in the browser playground. Adds the RustCrypto crates `rsa`, `p256` and `x509-cert`, pinned exactly, with no random-number or C dependency.
- New pure crate `guion-crypto` and the `Crypto` instruction (tag 223, artifact format 78, from 77; older artifacts still load). `std:crypto` gains `crypto_sha512(data: Bytes) -> Bytes` and `crypto_sha3_512(data: Bytes) -> Bytes`, 64-byte digests that need no grant. The crate does no I/O and draws no randomness, builds for `wasm32-unknown-unknown`, and so runs in the browser playground too. It adds the RustCrypto crates `sha2` (already used) and `sha3`, pinned exactly.

## 0.7.0 — 2026-11-15

Additions only, plus the artifact format going from 75 to 76 (older artifacts still load; a program that uses `together:`, channels, background commands, `try_parallel_map` or `core_count` needs this runtime). Nothing is removed or re-signed.

- Record constructors take fields by name: `Box(height=2, width=1)`, or a mix with positional first, `Box(1, height=2)`. An unknown or repeated field, too many positional arguments or a missing field is an error that names it. `Workers(at_once=50, each_ms=5000, all_ms=30000)` uses it.
- Python calls inside a timed `try_parallel_map` item stop at the item's deadline (`R_DEADLINE`) instead of running to the bridge's own 15 s limit. The `python-interop` feature builds again: it had stopped compiling after values moved to shared pointers, and its tests are updated.
- Fan-out is no longer capped by cores. The `parallel_map` worker limit defaults to 64 on every machine and `[runtime] max_parallelism` can raise it to 1024; going over says which line to change: `error[R_PARALLEL_LIMIT]: worker limit 200 is above this project's limit of 64` and `raise it in guion.toml:   [runtime] max_parallelism = 200`. `try_parallel_map(list, f, Workers(at_once, each_ms, all_ms))` is `parallel_map` with a result per item and deadlines: an item past `each_ms`, or still running or not started when `all_ms` passes, is `Err` with `R_DEADLINE`, finished items keep their results, and a fault in one item stops no other. Blocking HTTP, command and socket calls inside an item wait no longer than the time left, deadlines need no `[clock]` grant, and a recording replays the same item timing out. `together:` blocks run work in the background and end all of it with the block: `start(f, argument)` begins a task, `wait(task)` and `wait_within(task, ms)` give `Result[T, TaskError]`, a task not waited for is stopped when the block ends, tasks have exactly the parent's grants and shared budgets, and a task cannot leave its block (`E_SCOPE_ESCAPE`). Channels (`channel(capacity)`, `send`, `receive`, `close`) are bounded queues between tasks, so a fast producer waits for a slow consumer; `first_ready(tasks)` and `first_value(channels)` (and `_within` forms, which need `import "std:process"`) give `Ready(index, value)`: which of several is ready first and its result, taken in one step, and a recording replays the same choices. Channels (`channel(capacity)`, `send`, `receive`, `close`) are bounded queues between tasks, so a fast producer waits for a slow consumer; `first_ready(tasks)` and `first_value(channels)` (and `_within` forms, which need `import "std:process"`) give `Ready(index, value)`: which of several is ready first and its result, taken in one step, and a recording replays the same choices. `std:process` also starts commands in the background: `start_process`, `process_line`, `process_write`, `process_close_input` and `process_wait`. Each command runs in its own process group and is stopped, with everything it started, when its `together:` block ends, when the program ends or when `guion` is interrupted. `std:process` gains `core_count()` for work that keeps the processor busy, and the HTTP client's internal thread pool follows the limit (up to 64) instead of stopping at 8.

- Denials say how to fix themselves. A denied clock, environment variable, command, HTTP host or socket names the `guion.toml` line and the run flag that would allow it. `guion run --json` carries `diagnostic.grant` (`table`, `key`, `value`, `flag`) on the error and a `denials` array that also lists denials a program handled itself. Error codes are unchanged.
- `guion inspect --grants [--json]` compares the hosts, commands, sockets, environment names and clock use the code can reach with what `guion.toml` grants, and lists each missing grant as a manifest entry and a flag. Targets computed while running are reported as such.
- `guion run` asks one plain question before the run when a person is at the terminal and a grant is missing: `[y]` this run, `[a]` always (adds the exact entries to `guion.toml`, keeping comments and order), `[N]` no. The answer is read from the terminal itself, never from piped input, and nothing is asked under `CI`, `GUION_NO_PROMPT`, `--no-prompt`, `--json`, `--sealed`, `--replay`, `guion test`, or without a terminal. A target only known while running is asked about by name at that point. `guion repl` follows the same rules; a yes lasts the session. A recording's header lists the grants that came from a question.
- `temp:` is a private folder for each run and each test, under `TMPDIR`, removed when the run ends (`--keep-temp` keeps it). `--sealed` runs with no file access and none of the project's grants.
- Fixed: `guion repl` placed its permission flags after the file name, where `run` read them as program arguments.

### Packages

- F1 (`f94c3e0`): a package that is large enough to be a framework can now be installed, checked and tested like any other. All of it is additive; nothing is removed or re-signed.
- `guion add NAME [--version REQ] [--approve-capabilities]` (and `--path`, `--url`): a project may keep an `[approved-capabilities.NAME]` table in `guion.toml`, in the same shape as a package's `[capabilities]`. A project approves nothing by default, so installing or updating a package that declares more than its entry (or any capabilities, when there is no table) is refused, and the message names the difference one line per kind of access, for example `network: +hosts ["api.example.com"]`. `--approve-capabilities` lets the install through and records the approval. This is a break from 0.3.0, where a project with no table accepted any package.
- `std:sqlite` is reported as file access: `sqlite_open` as `filesystem.read` and `filesystem.write`, statements and transactions that change the database as `filesystem.write`, queries as `filesystem.read`. The functions are re-signed (a break), and a package that uses SQLite must declare `files`.
- `guion add NAME --path PATH` writes a project-relative path to `guion.toml` and `guion.lock` instead of an absolute one, and `guion update` resolves relative paths against the project.
- `guion update` names a widening in the same form (`files: +modes ["write"]`, `processes: +commands ["git"]`) where 0.3.0 used a sentence per item. The refusal, the unchanged lock and `--approve-capabilities` are as before.
- `guion verify-package [--json] NAME VERSION` and `guion verify-package [--json] ARCHIVE NAME VERSION` check one published release without installing it: the archive hashes to what the index and the hash log say, its manifest names that package and version, and the log entry is intact, chained and signed by a key the client trusts. Failures are typed: `E_PACKAGE_CHECKSUM`, `E_PACKAGE_SIGNATURE`, `E_PACKAGE_LOG`, `E_PACKAGE_MANIFEST`, `E_PACKAGE_NOT_FOUND`, `E_PACKAGE_REGISTRY`. A registry with no configured key fails with `E_PACKAGE_SIGNATURE`. `guion verify-package DIRECTORY` for application bundles is unchanged.
- `guion sync --locked` (without `--offline`) installs whatever the manifest pins and the cache lacks, from the recorded URL and archive hash, and refuses to change `guion.lock`. Two projects with the same manifest and lock end with byte-identical package trees. `guion sync --locked --offline` is unchanged.
- A package installed under `.guion/packages/NAME/VERSION` can run `guion test` (and `check`, `run`) in place: it resolves its dependencies from the installing project's lock, so it tests against exactly the pinned set, and running it leaves the installed tree unchanged.
- F7 (`322fde8`), the `web` package (`packages/web`, not published to the registry): routing, middleware and serving, with every function declaring its effects and none naming a socket or other handle. `route(method, pattern, handler)` and `router(routes) -> Result[Router, HttpFailure]` take patterns with typed parameters (`{id:int}`, `{slug}`); `router_handle(router, request)` dispatches and fills `Request.params`, and `path_param` and `path_param_int` read them. Two routes that can match one path with the same method are `E_ROUTE_CONFLICT` at construction (no precedence rules: `/users/{id}` and `/users/new` conflict, `/users/{id:int}` and `/users/new` do not), and a malformed pattern is `E_ROUTE_PATTERN`. `{id:int}` given `abc` is a 404, an encoded slash (`%2F`) stays inside one parameter, a trailing slash is significant (no redirect) and a bad percent escape is a 400. A path that exists under other methods is a 405 with `Allow`. Function values capture nothing, so there is no `wrap(mw, handler) -> handler`: a `Middleware` is a record of a named `before(request) -> Result[Request, Response]` and a named `after(request, response) -> Result[Response, HttpFailure]`, an `App` holds the router and the layers, and `wrap(app, layer)` makes the layer outermost (outermost first in, last out; tested with three wrappers). Guion has no type aliases, so the handler type `fn(Request) -> Result[Response, HttpFailure]` is written out. `app_respond` always answers an `Err` with a 500 whose body is the fixed text `Internal Server Error`, and logs the failure through std:log (`app_log`) or standard error. `serve(host, port, app, workers)` and `serve_for(host, port, app, workers, idle_ms)` run the pattern of `docs/concurrency.md`. A runtime fault inside a handler is not recoverable per request: it stops every worker and `serve` returns an `Err`, so handlers return `Err` instead of faulting. See `packages/web/README.md`.
- F2 (`a645783`), effects across package boundaries: `guion doc --json` and `guion inspect --json` carry a `package_effects` object with, per linked package, the effects its functions can reach (through its own code, other packages it imports, and the standard library), plus `approved` and `beyond_approved` when the project keeps `[approved-capabilities.NAME]`. `guion inspect` prints a `package NAME:` line for each. With that table present, `guion check`, `build` and `run` refuse a program whose package reaches an effect the approval does not cover (`gateway: filesystem.write (files = ["write"])`); effects a package reaches by importing another package count against the importing package. Without the table nothing changes. Per-function effects already crossed packages in 0.3.0; `effects_cross_package_boundaries` now protects that.
- F8 (`b615de2`), sessions and CSRF in the `web` package, no format change. `session_middleware(store, policy)` and `csrf_middleware(store, policy)` build `Middleware` layers over a SQLite session store that every worker shares: IDs are 32 bytes from the operating system's generator (64 hex digits), the database keeps `sha256(ID)` and never the ID, the cookie is `HttpOnly`, `Secure` and `SameSite=Lax` by default (`SameSite=None` without `Secure` is `E_COOKIE_SAMESITE_NONE_NEEDS_SECURE`), an ID the server did not issue is replaced and never adopted, an ID of the wrong length or alphabet is rejected before the store is touched, `session_rotate` moves the data to a new ID and kills the old one, `session_destroy` ends a session, and a session expires after an idle and an absolute limit. CSRF tokens are `HMAC-SHA256(server secret, session ID + "csrf")`, checked in constant time on every method except `GET`, `HEAD` and `OPTIONS`; a refusal is a 403 with a fixed body. Nothing about a session reaches a log or a failure message. A `Middleware` now carries a `config` map and its `before` and `after` functions take it first (`before(config, request)`, `after(config, request, response)`), because function values cannot carry settings; `middleware_configured` and `middleware_before_configured` build a layer with settings, and `middleware`, `middleware_before` and `middleware_after` build one with an empty map.
- F9 (`5f3f552`), checked templates (no format change): `NAME.gut` files compile, in a pre-pass of `guion check`, `build`, `run`, `test`, `inspect`, `doc`, `fmt`, `lint` and `package`, to ordinary Guion modules `NAME.gut.gu` (next to the template, listed in a generated `.gitignore` line) holding `render_NAME(params) -> Rendered`; the compiler, the artifact format and the catalog do not change and no template parser reaches a compiled program. `{{ x }}` escapes for element text and quoted attribute values; `{{ attr x }}`, `{{ url x }}` (percent-encoded component) and `{{ script x }}` (a JSON string literal safe inside `<script>`) name the other contexts; `{{ embed r }}` accepts only a `Rendered`. There is no switch, filter or flag that turns escaping off. An interpolation where no escaper is safe (plain `{{ x }}` in `<script>`, in a URL attribute, in `on*`/`style`, unquoted, in a tag or comment) is a build error with a code, file, line and column; an unknown variable, unbalanced block or type error is too, shown at the template position. The `web` package gains `html.gu` (`Rendered`, the escapers, `html_response`); `docs/templates.md` has the syntax and the context table. Template errors carry 29 new `TEMPLATE_*` codes (`TEMPLATE_UNKNOWN_VARIABLE`, `TEMPLATE_CONTEXT_MISMATCH`, `TEMPLATE_SCRIPT_CONTEXT`, `TEMPLATE_UNQUOTED_ATTRIBUTE`, `TEMPLATE_EMBED_CONTEXT`, `TEMPLATE_CYCLE` and the rest, all listed in that page). In a project with a template, `guion check` refuses a hand-written module that forges a `Rendered` (`TEMPLATE_RENDERED_FORGERY`); a template holds `Text` and typed parameters only.

- F10 (`75e1312`), the publish-one-page slice, no format change: `evaluation/frameworks/publish-page` is a six-route application (create a page, view it, publish it as a static bundle, upload a cover image that is confined, resized and served with validators and ranges) that consumes `web` by path and copies none of its code, with the acceptance suite `crates/cli/tests/f10_publish_page.rs` (12 tests against a real server) and a Python twin that renders the same pages byte for byte. ### Standard library

- F3 (`74dd4b8`), no format change: `std:http_response` adds request and response values for HTTP servers. `Response` is a value (status, an ordered list of headers that may repeat a name, and a `Body` of bytes, text or a chunked stream), so a response built in one function can be returned through others, compared with `==`, and serialized for tests with `response_serialize`. `Request` carries `method`, `path`, `query` (name to list of values), `headers`, `body` and a `params` map that is empty until a router fills it. A header name that is not a token, or a value containing CR, LF, NUL or another control character, is refused at construction (`E_HTTP_HEADER_INVALID`) and again at serialization, which includes `Location` from `response_redirect`. `std:http_server` adds `http_request_value` (the only function that reads the connection-bound request) and `http_server_send_response`. A handler is `fn(Request) -> Result[Response, HttpFailure]` and names no socket. Streams are `stream_from_list(chunks)` and `stream_from_file(path)`; a streamed file is read when the response is sent, so it is held in memory then. All additive: `guion doc` effects for the existing `http_server_*` functions are unchanged, and `http_server_respond`, `http_server_reply` and `http_server_send` now build their output through the new code (same bytes; a content type with a line break is now an error instead of being sent). Artifacts and the artifact format are unchanged.
- F4 (`4179555`), no format change: `std:cookie` parses the `Cookie` header into a map (malformed pairs are dropped, never an error) and builds `Set-Cookie` values from a `Cookie` record with `HttpOnly`, `Secure`, `SameSite`, `Path`, `Domain`, `Max-Age` and `Expires`; values are percent-encoded so `;`, `,`, quotes and line breaks cannot inject attributes, and `response_add_cookie` adds the header through the `std:http_response` check. HttpOnly and `SameSite=Lax` are the defaults. `SameSite=None` without `Secure` is a typed error at run time (`E_COOKIE_SAMESITE_NONE_NEEDS_SECURE`), not a build-time error, because a cookie is a value: `cookie_same_site` and `cookie_serialize` refuse it. `cookie_parse_set` reads a `Set-Cookie` line back. All additive.
- F5 (`6914ec9`), no format change: `std:http_body` parses request bodies with explicit limits. `form_parse(body, limits)` reads `application/x-www-form-urlencoded` into `Map[Text, List[Text]]`; `multipart_parse(request, files_root, limits)` reads `multipart/form-data`, treats a part with a `filename` as a file written under `files_root` with a random name (the client name is sanitized to its final component, kept only as `original_name`, and never used as a path) and a part without one as a field. `BodyLimits` (defaults: max_headers 16, max_header_bytes 8192, max_parts 1000, max_part_bytes 8388608, max_total_bytes 16777216) is enforced exactly: over a limit is a 413 naming it, at the limit is accepted. Nothing is written until the whole body parses. A folded part header, a control character in a header and a boundary over 70 characters are 400s. `body_read_limit` and `body_read_failure` pair with `http_server_read_request`, which now names `max_body_bytes` in its 413 body (it already refused a declared oversized body before reading it). Failures are `HttpFailure` values.
- F6 (`97f29e5`), artifact format 73: `std:http_static` serves files from a directory as `Response` values. `static_serve(request: Request, root: Text) -> Result[Response, HttpFailure]` (effect `filesystem.read`) answers GET and HEAD for the file the request path names under `root`, with a content type from a documented extension table (unknown is `application/octet-stream`), a weak `ETag` of the form `W/"<size>-<mtime-ms>"` (cheap, not a content hash), `Last-Modified`, `If-None-Match` and `If-Modified-Since` giving 304 with no body (`If-None-Match` wins when both are sent), and one `Range` giving 206 with `Content-Range` or 416 with `Content-Range: bytes */N`. A suffix range (`bytes=-500`), `bytes=0-0` and an open range (`bytes=500-`) work; more than one range, another unit or a malformed range is ignored and the whole file is sent with 200. HEAD gives the same status and headers as GET, with Range honoured, and no body; other methods are 405. Every path segment is percent-decoded once and a segment that decodes to `..`, holds `/`, a backslash or NUL, or starts with `.` is a 404 (a bad escape is 400); the joined path is resolved through symbolic links and must stay inside `root`, so a link that leaves it is a 404. A directory is served as its `index.html` and is never listed. `static_content_type(path)` and `static_http_date(unix_ms)` are pure. A file body is a stream the server sends in blocks of at most 65,536 bytes, so a large file is never held in memory: `std:http_response` adds `FilePlan`, `response_file_plan`, `response_file_head`, `response_file_block`, `response_file_block_size` and `response_file_end`, and `http_server_send_response` now sends file streams (including `stream_from_file`) block by block instead of reading the file whole. New `Fs` function codes 18 (`read_range`, at most 16 MiB per call) and 19 (`confined_path`) carry the artifact format to 73; an older format that uses either is refused with `E_ARTIFACT_VERSION` and format 72 and earlier artifacts still load. Additions only against the 0.3.0 surface.

### Fixed

### Breaking

### Language

- B1: `break` and `continue` are new statements for `while` and `for` loops, and they are now reserved words at the start of a statement. Outside a loop they fail with `E_NO_LOOP`. The artifact format is unchanged.
- B2, artifact format 65: `sort(values)` for lists of `Text`, `Int` and `Float64`, and `sort_by(values, key)` with a named `(T) -> K` key function for `K` in `Text`, `Int` or `Float64`. Both are stable and total (`-0.0` before `0.0`, NaN last), `Text` compares by Unicode scalar value exactly as sorted map keys do, `sort_by` calls the key once per item, and native comparisons are charged to the instruction budget as `sort_by_int_key` is. A key of another type, such as `Bool` or `Unit`, fails at check time with `E_SORT_KEY`. `sort_by` with a two-parameter `(T, T) -> Int` function is still the comparator sort, and `sort_by_int_key` and `merge_sorted_by_int_key` are unchanged; artifacts at format 64 and earlier load and run as before. The key is a named function until function values arrive.
- B3, artifact format 66: first-class function values. `fn(Int) -> Int` is a type, `let f = double` binds a named function (own or imported) as a value, a function can be a parameter, a result, a record field or a list or map item, and `f(x)` calls it with the arity and types checked at check time. Function values capture nothing: a lambda or a nested `fn` is `E_FN_NO_CLOSURES`, and `==` on one is `E_FN_COMPARE`. Effects attach where a value is formed, so `guion inspect` and `guion doc --json` attribute a function's effects to the function that writes `let f = writer_fn` or passes `writer_fn`. A type that holds a function is `E_FN_NOT_SERIALIZABLE` at the JSON, CSV, TOML, SQLite, process, HTTP, file and `print` boundaries; it may be passed to `parallel_map` workers. New builtins `map_list`, `filter_list`, `fold_list`, `any_list` and `all_list`; `sort_by`, `sort_by_int_key`, `merge_sorted_by_int_key` and `parallel_map` also accept function values. New operations `MakeFn`, `CallFn` and `HigherOrder` (tags 198 to 200); artifacts below 66 that use them are rejected with `E_ARTIFACT_VERSION`, and format 65 and older artifacts still load and run. Recursion through a function value stops at the call-depth limit; a value that names no function is `R_FN_INVALID`. Functions that form or call function values run in the interpreter, not as machine code. In the browser VM function values work, but the higher-order builtins and the sorts need a host operation the browser VM lacks. Unknown calls named `map` and `filter` now suggest `map_list` and `filter_list`. Closures are listed in known issues.
- B9: an unknown call name still fails with `E_NAME_UNKNOWN`, and now adds up to three `help: did you mean` lines for near misses among the module's functions and the builtins (edit distance at most `max(2, len/3)`). `guion check --json` gains an additive `diagnostic.suggestions` array. Both compilers report the same names.

### Standard library

- B4, artifact format 67: `std:crypto` adds `crypto_sha256(data)`, `crypto_sha256_text(text)` and `crypto_sha256_file(path)`. The first two return the 32-byte digest of a `Bytes` or `Text` value; the file form digests the file in fixed-size blocks (a 50 MiB file peaks near 7 MiB resident on the development machine), needs the file-read grant, and returns a typed `StdError` for a missing or ungranted path. The vectors for empty input and `abc` and a comparison with `shasum -a 256` are tests. Artifacts below 67 that use them are rejected with `E_ARTIFACT_VERSION`; formats 14 through 66 still load.
- B12, artifact format 68: `std:crypto` adds `crypto_random_bytes(count)`, `crypto_random_hex(count)` and `crypto_random_base64url(count)`, each returning `Result[..., StdError]`, with `count` the number of random bytes. They draw from the operating system's cryptographic generator (`getentropy` on macOS, `getrandom` on Linux), at most `crypto_random_max_bytes()` (1 MiB) per call; 0 gives empty output, and a negative or too large count is `E_RANDOM_COUNT` and a failing source `E_ENTROPY_UNAVAILABLE`. No grant is needed. Programs that use them are not reproducible. Embedders can pin the source with `HostPolicy::with_entropy_source` for tests; it is not reachable from guest code or `guion.toml`. `std:random` is unchanged. Artifacts below 68 that use the new instruction (tag 201) are rejected with `E_ARTIFACT_VERSION`; formats 14 through 67 still load.
- B14, artifact format 69: `std:sqlite` adds `sqlite_begin_read(database)`, which opens a `BEGIN DEFERRED` read transaction. A reader no longer waits behind a writer's transaction and no longer fails with `E_SQLITE_BEGIN` while one is held; a write statement inside it returns `E_SQLITE_READ_ONLY` and the transaction stays usable. The busy deadline is now published: 2000 ms per attempt, the runtime constant `SQLITE_BUSY_DEADLINE_MS`, quoted in `language/host-api.md` and checked against the code by a test. `PRAGMA` cannot change it and write transactions still serialize. A logger is a value, not global state; each record is one JSON line with `level`, `msg` and the caller's fields in sorted key order, and `ts` first only for the `_at` and `_now` forms. The plain functions never read the clock; `log_info_now` carries `clock.read` and fails with `R_CLOCK_DENIED` without the grant (effects are enforced when the operation runs). `[log] level` in `guion.toml` sets the default level. A record below the logger's level formats nothing. New instructions `LogAppend` and `LogDefaultLevel`; artifacts below format 70 that use them are rejected with `E_ARTIFACT_VERSION`.
- B5, artifact format 71: `std:compress` adds `gzip_compress`, `zlib_compress`, `gzip_decompress(data, max_output)`, `zlib_decompress(data, max_output)`, `gzip_compress_file(source, destination)` and `gzip_decompress_file(source, destination)`; `std:tar` adds `tar_write(directory, archive)`, `tar_read(archive, destination)` and `tar_list(archive)`. Every inflate has an output ceiling, so a small input cannot expand without bound: `max_output` for the in-memory forms, capped by the new `[runtime] decompress_limit_bytes` key in `guion.toml` (default 1 GiB), which alone bounds the file and tar forms; output past it is `E_COMPRESS_LIMIT`. Multi-member gzip decompresses to the members concatenated; bytes after the last member or after a zlib stream are `E_COMPRESS_TRAILING_DATA`. The file forms stream in 64 KiB blocks (a 200 MB gzip round trip peaked at 7,045,120 bytes resident on the development machine, release build) and write through a temporary file renamed on success. `tar_write` gzip-compresses archives named `.gz` or `.tgz`, refuses symbolic links, and writes deterministic metadata; `tar_read` refuses absolute names, `..` components and links that could leave the destination with `E_TAR_UNSAFE_PATH`. Inflate bytes written by Python's `gzip` and `zlib` modules, and tar listings by the system `tar -tzf`, are checked in the tests. New instructions `GzipCompress`, `GzipDecompress`, `ZlibCompress` and `ZlibDecompress` and `Fs` function codes 13 to 17; artifacts below format 71 that use them are rejected with `E_ARTIFACT_VERSION`, and a format-70 artifact still loads. The runtime gains the pure-Rust `flate2` and `tar` crates; the browser VM is unchanged. zstd is a named follow-on, not part of this release.
- B10, artifact format 72: `std:yaml` adds `yaml_parse(text) -> Result[Json, StdError]`, a read-only reader for a documented YAML subset (block and flow collections, plain, quoted, literal and folded scalars, comments), for CI workflows, Docker Compose files and similar configuration. A plain scalar is text except lowercase `true`/`false`, `null`/`~` and integers or decimals that read back unchanged, so `NO`, `yes` and `1.10` stay text; quoted scalars are always text. Anchors, aliases, tags, the merge key, complex keys, directives and multi-document streams fail with `YAML_UNSUPPORTED` naming the feature, with the line and column and no partial value; other errors are `YAML_SYNTAX`, `YAML_DUPLICATE_KEY` and `YAML_LIMIT`. ## 0.2.0 — 2026-11-12

- Added a written [stability policy](docs/stability-policy.md): source compatibility within a minor series, the artifact formats the runtime reads (14 through 64), a deprecation period of at least one full minor release, how library packages are distributed and pinned, and what is not promised.
- Matrix multiplication of `f64` and `f32` arrays is much faster: a 512 by 512 multiply takes about 1.5 ms of compute (the old kernel took about 27 ms after start-up), about 2.3 times NumPy's compute on one Apple M1 Pro (2.26 in the committed compute-only run, 1.46 ms against 0.64 ms per multiply), and gives the same result on every run and thread count.
- Fixed calendar parsing from several threads at once: `calendar_parse` called libical, whose time zone tables are not thread-safe, and could return a wrong resolution (a gap where the time is exact); calls are now taken one at a time. A matrix product with a single row or column now equals the matching part of the full product to the last bit, `array_matmul` no longer aborts when the operating system refuses a thread, and `frame_show` aligns every emoji with emoji presentation by its display width. `frame_write_csv` of float columns and `frame_read_jsonl` are faster (about 15 percent and 1.7 times on one Apple M1 Pro).
- Fixed array and frame correctness: `array_i64_range` no longer panics in debug builds on extreme operands; temporary buffers in matmul, sort, argsort, factorize and join_index are charged to the allocation budget, and kernel temporaries and CSV error paths are released; array error messages name the guest operation rather than an internal one, and invalid arguments such as `array_clip` with low above high raise the new `R_ARRAY_ARGUMENT` instead of `R_ARRAY_SHAPE`; the Rust and self-hosted compilers give the same Array element type errors. In `frames`, tables align wide characters and text with newlines, join suffixes avoid a taken `<name>_right` name, `column_from_codes` checks its codes and returns `Result`, very large and very small floats use the shortest exponent form, JSONL reading keeps keys first seen after line 1, a single-column CSV keeps a row whose value is missing instead of skipping its blank line, and written CSV ends every record with a newline.
- Artifact format 64: `csv_read_columns(path, kinds)` reads a CSV file straight into typed columns (`record CsvColumn` in `std:csv`), with kinds inferred or fixed by name, quoted empty text kept in text columns, and the file streamed instead of checked against `max_file_bytes`. `csv_open`, `csv_next` and `file_open_lines` no longer check the whole file against `max_file_bytes` either (each record is still held to it); `read_text` and other whole-file reads keep the check. `R_ALLOCATION_LIMIT` messages now name `allocation_limit_bytes` under `[runtime]` as the setting to raise.
- Artifact format 63: array kernels for gathering, grouping and joining (`array_take`, `array_factorize`, `array_first_index`, `array_count_by`, `array_sum_by`, `array_min_by`, `array_max_by`, `array_mean_by`, `array_join_index`), compiled identically by both compilers. A first-party `frames` library in `packages/frames` builds data frames on them: `i64`, `f64`, `bool` and dictionary-encoded `text` columns with missing values; CSV and JSONL reading, CSV writing and a printed table; select, filter, multi-key stable sort, group-by with `sum`, `mean`, `min`, `max` and `count`, and inner and left joins. `frames` 0.1.0 is now published to the registry (`guion add frames`); it needs this release (artifact format 64).
- Artifact format 62: native n-dimensional arrays, `Array[e]` over `i8` to `u64`, `f32`, `f64` and `bool`, with checked conversion and integer overflow, NumPy-style broadcasting arithmetic, comparisons, float math, exact integer reductions, axis reductions, stable sorting, `dot`/`matmul`, ranges, `linspace`, and seeded random and normal arrays that continue the `std:random` stream. `set a = array_set(a, i, v)` updates a local in place. Both compilers accept, reject and compile array programs identically. Array functions run in the VM; the machine-code tier compiles the functions around them.
- Artifact format 61: `std:random` runs as machine code with unchanged sequences (`random_next_i64` added; ranges wider than 2^64 raise `R_RANDOM_RANGE`), and `std:net` adds mutual TLS (`tls_connect_with_identity`, `tls_accept_verified`). Chained text appends to a local are linear; functions returning `Unit` and functions using `assert` compile natively. `guion update` moves registry packages within their recorded range, `guion token rotate|revoke` and matching registry endpoints retire publisher tokens, and library checks require hosts in URL literals to be declared. `fs_remove` and `fs_rename` act on symlinks themselves, and writing through a dangling symlink is refused (it could create a file outside the granted root).
- Command-line programs are limited by memory in use (256 MiB by default) instead of cumulative allocation, and have no default instruction limit; embedders keep both bounds. Records that hold scalar-only records now run as machine code, and native code no longer lets a record kept from an earlier loop iteration be overwritten by a later call. The registry signs its log with ed25519 and the client verifies it (the default registry's key is built in), `guion check` and `guion inspect` say when a program can write files, and precompiled `.gub` attachments are deferred.
- Added a register form of the VM, translated per function on first call, which falls back exactly to the stack interpreter. `Map` is now a seeded hash table with shared keys; observable order stays sorted by key. `guion run` compiles only functions reachable from `main`, and the VM's local fuel reservation is 4096 instructions.
- Native functions that fail now keep the output they printed first; previously `print(7)` followed by a failure printed nothing. `print` of `Text` now compiles natively in functions with a loop. `csv_next_row` and `text_parse_integer` run as direct host operations, plain CSV records take a faster path, and the VM reads maps and lists without clones. The VM now polls cancellation at frame entry, loop edges and after host operations, so a cancelled program can finish its current straight-line run of instructions before stopping.
- Shrank the runtime `Value` from 88 to 24 bytes, added integer and clone fast paths to the VM, and made packages profile-guided by default (`GUION_PGO=0` opts out). Allocation limits charge the smaller value size, so a given `allocation_limit_bytes` now holds more values.
- Added format-45 `http_response_text` with bounded checked UTF-8 decoding, plus `std:http.http_response_json` for typed JSON parsing and stable error mapping. Existing HTTP request APIs retain their result types.
- Added format-41 stable integer-key sorting and merging plus `JsonSetLocal` bytecode for alias-safe, copy-on-write local JSON-object updates; added a fast artifact-format assertion audit that runs before long validation gates. Format 42 assigns distinct local-time opcode tags so temporal resolution coexists with those format-41 instructions.
- Added pure `std:time` local-time resolution that reports exact times, daylight-saving gaps, and folds with all candidate instants using bundled tzdata 2026c. Calendar events now preserve local endpoint identity and ambiguity instead of selecting an instant; `guion --version` reports the timezone-data version.
