# Changelog

Changes are recorded here. Two preview builds, v0.1.0-preview and v0.1.0-preview.2, were published before this release. 0.2.0 is the first release with a written [stability policy](docs/stability-policy.md).

## 0.9.0 (unreleased)

Artifact format 90 (older artifacts still load; a program that uses anything below needs this runtime). Everything new here is pure, needs no grant and runs in the browser VM too, except the file modes and the peer address below, which are refused in the browser VM (the file modes need a file grant).

- Artifact format 90: `text_lower(value: Text) -> Text` and `text_upper(value: Text) -> Text` in `std:text` change case with the Unicode default case mapping (new `Op::TextLower` and `Op::TextUpper`, tags 225 and 226). `text_upper("Straße")` is `"STRASSE"`, a capital sigma ending a word lowercases to `ς`, and `İ` lowercases to `i` and a combining dot, so a result can be longer than its input; one over the text limit is `R_TEXT_LIMIT`. They are for display; to compare text without regard to case, use `text_casefold`. A function that calls them runs in the VM, not as machine code.
- Artifact format 90: `json_keys(value: Json) -> Result[List[Text], JsonError]` in `std:json` (new `Op::JsonKeys`, tag 227) returns an object's top-level keys in the order `json_stringify` writes them, which is ascending byte order of the key text. A value that is not an object is `Err` with code `R_JSON_TYPE` and a message naming the type found.
- Artifact format 90: `json_stringify_pretty(value: Json, indent: Int) -> Text` in `std:json` (new `Op::JsonStringifyPretty`, tag 228) writes each array element and object member on its own line, indented by `indent` spaces per level (0 to 16, else `R_JSON_INDENT`; 0 puts the lines at the left edge), with `": "` after a key, `,` at the end of every line but the last of a container, `{}` and `[]` for empty containers, no trailing newline and non-ASCII text as it is. Strings and numbers are written as `json_stringify` writes them.
- Artifact format 90: `fs_set_mode(path: Text, mode: Int) -> Result[Unit, FileError]` and `fs_mode(path: Text) -> Result[Int, FileError]` in `std:fs` (new `Fs` function codes 20 and 21) set and read permission bits as an `Int`, following symlinks as `chmod` does: `fs_set_mode("key.pem", 0o600)`, and `int_to_text_radix(fs_mode(path), 8)` to show it as octal. `mode` is 0 to `0o7777` (anything else is `R_FILE_MODE_INVALID`) and `fs_mode` returns the bits including setuid, setgid and sticky. The path resolves against the file root like every other `std:fs` function, not the working directory. `fs_set_mode` needs the file-write grant (effect `filesystem.write`) and `fs_mode` the file-read grant (`filesystem.read`); both are `R_FILE_UNSUPPORTED` on Windows and `R_HOST_UNSUPPORTED` in the browser VM, and are recorded on tapes like the other file operations.
- Artifact format 90: `int_to_text_radix(value: Int, radix: Int) -> Text` and `text_parse_int_radix(text: Text, radix: Int) -> Result[Int, FileError]` in `std:text` (new `Op::IntToTextRadix` and `Op::TextParseIntRadix`, tags 229 and 230) convert an `Int` of any size to and from text in radix 2 to 36. The text has lowercase digits, a leading `-` for a negative value, no prefix and no separators (`int_to_text_radix(255, 16)` is `"ff"`); parsing takes either case and one optional leading `-`, and anything else (empty text, `+`, `0x`, `_`, a space, a digit outside the radix) is `Err` with code `E_INT_PARSE`, as `text_parse_int` gives. A radix outside 2 to 36 is the runtime fault `R_RADIX_RANGE` and a parsed value over the digit limit is `R_INTEGER_LIMIT`. No grant, no effect; they run in the browser VM. The frozen self-hosted compiler cannot encode them (known issue 35).
- Artifact format 90: `tcp_peer(conn: TcpConn) -> Result[PeerAddress, StdError]` in `std:net` (new `Net` function code 10) returns the other end of a TCP or TLS connection as `PeerAddress(host: Text, port: Int)`: the client on an accepted connection (TLS-accepted ones included), the server on one from `tcp_connect`. An IPv6 host has no brackets and an IPv4-mapped IPv6 address is reported as IPv4. It needs no grant beyond holding the connection, reports `network.socket`, is recorded on tapes like the sibling socket operations and is `R_HOST_UNSUPPORTED` in the browser VM; a listener, datagram socket or closed handle is `E_NET_HANDLE`. `std:http_server` adds `http_server_peer(request: HttpServerRequest) -> Result[PeerAddress, StdError]`.
- Breaking, `std:http_response`: the `Request` record has a seventh field `peer: Text` (the client's address as `host:port`, an IPv6 host in brackets as `[::1]:4000`, `""` when unknown). `request_new` sets it to `""` and `http_request_value` fills it from the connection. A `Request(...)` record literal needs the extra argument, e.g. `Request("GET", "/", {}, [], body, {}, "")`; code that only reads requests, or builds them with `request_new`, is unaffected. The `web` package is now 0.3.0: handlers and middleware see `request.peer`, and the router, session and static-file layers pass it on when they rebuild a request. It needs Guion 0.9.0 or later.
- Artifact format 90: `process_stop_requested() -> Bool` in `std:process` (new `Process` function code 9) is true once an `INT`, `TERM` or `HUP` has arrived in a program that polls for signals (one that has called `process_signal_poll`). It stays true, does not take the pending signal, is the same on every thread (`parallel_map` workers and `together:` tasks included) and changes nothing about `process_signal_poll` or `sleep_ms`; a program that never polls is ended by the signal as before and sees false. No grant; effect `process.signals`; recorded on tapes like `process_signal_poll`; always false in the browser VM. The `web` package (still 0.3.0, unreleased) uses it: `serve` and `serve_for` workers accept with a timeout of at most 200 ms and, between connections, stop when it is true. A request being handled is finished first, then `serve` returns `Ok`. To get a clean stop, call `process_signal_poll()` once at the start of `main`; a program that does not is unchanged. `serve_for`'s `idle_ms` is now the time without a connection summed over accepts and starts over after each connection. The frozen self-hosted compiler cannot encode it (known issue 35).
- Integer literals can be written in hexadecimal, octal and binary: `0xFF`, `0o755`, `0b1010` (the prefix in either case), and `_` may separate any two digits of an integer literal in any base (`1_000_000`, `0xDEAD_BEEF`) and of a float (`1_000.5`). They are as large as decimal literals, a negative one is the unary `-`, `007` is still 7, and no artifact format change is involved (they compile to the same constants). A `_` that is not between two digits (`1__0`, `1_`, `0x_F`), a prefix with no digits (`0x`) and a digit outside the base (`0b2`, `0o8`, `0xG`) are `E_NUMBER_LITERAL` with the line and column of the offending character. `guion fmt` keeps a literal exactly as written; the VS Code grammar and the site highlighter know the new forms. The frozen self-hosted compiler does not lex them (known issue 35).
- Known issue 47 (undefined behaviour in the native code arena's raw pointers) is fixed; see "Resolved known issues" below.

## 0.8.0 — 2026-11-23

Additions, plus the artifact format going from 76 to 89 (older artifacts still load; a program that uses anything below needs this runtime). New in `std:crypto`: SHA-512 and SHA3-512, RSA, ECDSA P-256, BLS12-381, tlock, X.509 checks, Ed25519 and RFC 3161 time-stamps, all pure and checked against published vectors; with them the `beacons` package, which checks drand, Twine and CURBy, and NIST beacon pulses and runs in the browser VM too. New in the language: bit operations, `sleep_ms`, indexing `Bytes`, nested `match` patterns and constructors that infer their type from where they are used. Two behaviour changes, both stricter: `crypto_tsa_verify` now requires the `timeStamping` key usage to be marked critical, and `csrf_middleware` in the `web` package refuses a request whose `Origin` or `Referer` does not name its own `Host`. A `Some(Red)` pattern now means the enum variant `Red` where it used to bind a new local. Nothing is removed or re-signed.

- `csrf_middleware` (the `web` package, now 0.2.0) also checks where a request comes from: an unsafe-method request with an `Origin` header (or, without one, a `Referer`) must name its own `Host`, else 403 `Forbidden`, before the token is looked at. `Origin: null`, a non-http(s) value and an Origin with no `Host` header are refused; with neither header the token alone decides. A deployment behind a proxy that rewrites `Host` must pass it through. New `csrf_origin_ok(request)`.
- `crypto_tsa_verify` now requires the TSA certificate's `timeStamping` extended key usage to be marked critical (RFC 3161 section 2.3); a certificate whose extension is not critical gives `None`. The DigiCert, Sectigo and FreeTSA certificates all mark it critical.
- Artifact format 89: `Bytes` can be indexed. `data[i]` is the byte at zero-based `i` as an `Int` from 0 to 255; an index past the end is `R_INDEX_BOUNDS` and a negative one `R_INDEX_INVALID` (new `Codec` function code 20, `bytes_at`). An artifact below format 89 that uses it is `E_ARTIFACT_VERSION`; it also runs in the browser VM.
- `match` takes nested patterns inside `Some`, `Ok` and `Err`: `Ok(Some(x))`, `Ok(None)`, `Err(e)`, `Some(Red)`. Every value must match exactly one arm: a missing combination is `E_MATCH_NONEXHAUSTIVE` naming it, an overlap `E_MATCH_DUPLICATE`. The compiler lowers them to single-level matches, so no new artifact format. The timestamp example uses them (`Ok(Some(stamp))`, `Ok(None)`, `Err(problem)` in one `match`). Behaviour change: a name inside `Some`, `Ok` or `Err` that equals a declared enum variant now means that variant, so `Some(Red)` matches `Red` where before it bound a new local named `Red`. An enum variant pattern on a value that is not that enum (`Err(Red)` where `Err` holds `Text`, or `Red:` in a `match` on a `Text` or on another enum) is now `E_MATCH_TYPE` naming the variant and the type found; before, it was a misleading `E_MATCH_MISSING_VARIANT`, `E_TYPE_FIELD`, or for another enum no error at all. A `Some`/`None` or `Ok`/`Err` pattern on another type now names the type it found.
- `Some`, `None`, `Ok` and `Err` build a value wherever its type is known: a return, an annotated `let`, a `set`, an argument, a record field, a list or map element, or inside another constructor, so `return Ok(None)` and `return Ok(Some(x))` work in a function returning `Result[Option[T], E]`, and `Some(Ok(x))`, `Box(Some(1))` and `[Some(1), None]` work anywhere. `Some(x)` with no expected type takes its type from `x`. Before, they compiled only where the type was exactly the enclosing function's result type, and `E_OPTION_CONSTRUCTOR_CONTEXT` / `E_RESULT_CONSTRUCTOR_CONTEXT` sent you to write a helper function; those codes now mean the type cannot be known (`let value = None`: write `let value: Option[Int] = None`) or another type is expected, and the message says which. No artifact format change: any other constructor is a call to a hidden function the compiler adds once per type. `std:crypto`'s `crypto_tsa_verify` now writes `Ok(None)` and `Ok(Some(TsaToken(...)))` directly and its `tsa_none` / `tsa_some` helpers are gone.
- Artifact format 88: `sleep_ms(ms: Int) -> Unit` blocks for at least `ms` milliseconds unless a polled signal arrives (0 to 86400000, else `R_SLEEP_RANGE`; new `Op::Sleep`, tag 224). No grant; `guion inspect` and `guion doc` report the effect `clock.sleep`. It waits in slices of at most 10 ms, so a stopped task, a `wait_within` deadline and Ctrl-C end it promptly. In a program that polls for signals with `process_signal_poll`, a signal that arrives ends one sleep early on each thread, so `main` and every sleeping task wake once for it; it stays pending for the next poll, and later sleeps on the same thread run their full time. A tape does not record it and a replay does not wait. The browser VM returns `R_HOST_UNSUPPORTED`. A function that calls it runs in the VM, not as machine code.
- Artifact format 87: `std:crypto` adds RFC 3161 trusted timestamps, all pure: `crypto_tsa_request(digest, nonce)` (a DER request for a SHA-512 digest, byte for byte what `openssl ts -query -sha512 -cert` writes), `crypto_tsa_response_token(response)` (a refusal, status 2 to 5, is `E_TSA_STATUS` naming the status, status string and failInfo bits), `crypto_tsa_verify(token, digest, tsa_cert, issuer_cert)` (`Some(TsaToken)` only for a token of this digest signed by the pinned TSA certificate, issued by the pinned issuer, with the `timeStamping` key usage and valid at `genTime`; RSA PKCS#1 v1.5, RSA-PSS and ECDSA P-256 or P-384; the extended key usage must be critical, as RFC 3161 section 2.3 says, and ESS `issuerSerial` is not compared) and `crypto_tsa_certificates(token)`, with `record TsaToken` (Crypto codes 17 to 20; the DER is read by a small strict reader in `guion-crypto`, plus `sha1` 0.10.6 for the ESSCertID hash). Checked against live DigiCert, Sectigo and FreeTSA tokens and a local OpenSSL TSA. New example `language/examples/timestamp`. Runs in the browser VM too. Artifacts below format 87 that use them are `E_ARTIFACT_VERSION`; formats 14 through 86 still load.
- Artifact format 86: `std:crypto` adds pure Ed25519 (RFC 8032, not Ed25519ph, no context): `crypto_ed25519_public_key(seed)`, `crypto_ed25519_sign(seed, message)` and `crypto_ed25519_verify(public_key, message, signature)` (Crypto codes 14 to 16; `ed25519-dalek` 2.2.0 without `rand_core` or `getrandom`). The 32-byte seed is an argument (draw one with `crypto_random_bytes(32)`), so signing is deterministic and needs no grant. Verification is strict: small-order keys and non-canonical `R` or `S` are `Ok(false)`; a wrong length or a key that is not a curve point is `E_CRYPTO_INPUT`. Runs in the browser VM too. Artifacts below format 86 that use them are `E_ARTIFACT_VERSION`; formats 14 through 85 still load.
- Artifact format 85: `std:crypto` adds `crypto_x509_dns_names(der)` (Crypto code 12: the SubjectAltName dNSName entries, or the subject CN only when there is no SubjectAltName extension) and `crypto_x509_validity(der)` (code 13: `[notBefore, notAfter]` as Unix seconds), so a program that pins an issuer can also check whose certificate it is. Hardening from the final review: `crypto_rsa_verify` now accepts moduli up to 8192 bits exactly (it stopped at 4096 before), `crypto_x509_verify_issued_by` returns `Ok(false)` when the outer `signatureAlgorithm` differs from the one inside the `tbsCertificate`, honours the `saltLength` of RSASSA-PSS parameters and rejects a `trailerField` other than 1, `crypto_tlock_round` and `crypto_tlock_chain_hash` refuse a stanza round written as `+1000` or with leading zeros (`E_TLOCK_FORMAT`), and the documentation now says that ECDSA verification accepts both `(r, s)` and `(r, n - s)` and that `"pss-sha256"` means a salt as long as the digest.
- The browser VM runs the beacon checks (`guion-vm-wasm`, no artifact format change, ABI stays 1.0). Every `Crypto` code (0 to 11) and the bit-operation `Codec` codes (15 to 19) already lived in the shared core; a test now runs one set of vectors, including a rejection case for each fallible code, through the wasm ABI and the native runtime and requires identical results and error codes. The check found a real gap: the `Json` instructions were native-only, so `json_parse`, `json_get`, `json_try_*` and the rest failed with `R_HOST_UNSUPPORTED` in the browser, and the beacon package could not read a receipt there. They now run in `PortableHost` with the native limits and error codes (the decoder and the `json_try_*` accessors moved from `guion-runtime` into `guion-vm-core` so both hosts share them; the column and projection instructions stay native-only). New optional request field `limits.allowRaisedSteps` lets a page raise `steps` above the default 10,000 up to a hard ceiling of 50,000,000 (`MAX_RAISED_BROWSER_STEPS`); without it nothing changes, and it moves no other ceiling. Measured: one program that checks a drand round, opens a tlock file, verifies a CURBy-Q pulse and two NIST pulses with their precommitment chain from embedded data is 167,349 bytes of artifact (limit 1 MiB, unchanged) and 34,008 steps, so it runs with a 100,000-step budget. HMAC and random bytes stay native-only, so the `crypto_tlock_encrypt` wrapper is not in the browser (decrypt is, and `native_crypto_tlock_encrypt` takes caller-supplied randomness). `docs/browser.md` lists what is available.
- Printing functions run in machine code again under `guion run`. Native code holds what it prints and writes it out at its next print once 2 ms have passed since the last write (the first print is written at once), at 64 KiB, and when the function returns or leaves native code with the VM carrying on; if it falls back to the VM and the function is run again from its start, the lines already written are skipped in the replay, on stdout and stderr alike. A hot loop that prints and computes ran about 11 times faster in a measurement (2.19 s to 0.19 s); a held line no longer waits for the end of a long loop: functions that print check at their loop back-edges (every 256 turns) and write a line that is 2 ms old, tested with `print; print; long loop; print` (the hot loop above measured 0.19 s with the check). A fallback to the VM compares the replay with the lines already written and, on a difference, stops skipping instead of swallowing later output, and clears the skip after the run. `eprint` in native code is held the same way, which also fixes a repeated `eprint` line when a native function fell back to the VM without streaming. No artifact format change.
- Artifact format 84: `std:crypto` adds `crypto_tlock_chain_hash(armored)` (the chain hash of a tlock file's stanza; Crypto code 10) and `crypto_x509_verify_issued_by(certificate_der, issuer_der)` (code 11: the issuer name matches and the signature verifies under the issuer key; RSA PKCS#1 v1.5 or PSS and ECDSA P-256 or P-384 with SHA-256, SHA-384 or SHA-512; other algorithms are `E_X509_ALG`). New pinned dependency `p384` =0.13.1 (no getrandom). `beacons` uses them: `tlock_open` reads the chain hash with the built-in instead of parsing the stanza, and `nist_verify` checks the pulse certificate was issued by the pinned DigiCert issuer in `fixtures/`.
- `http_get` decodes every frame of a zstd body (skippable frames skipped, one response limit over the total) and refuses bytes after the last frame with `R_HTTP_ENCODING`; before, only the first frame was read and the rest was dropped silently. The runtime's `Json*` instruction arms are gone: the native host calls the one implementation in `guion-vm-core` that the browser host uses, so the two cannot drift. `guion run --json --replay` against a changed program carries the relaxed-replay notice as `tape_notice` in the run report (null for an exact replay). `beacons` hardening: `nist_verify` now requires a known NIST certificate id, the pinned issuer, the name `engine.beacon.nist.gov` and a `timeStamp` inside the certificate's validity (the issuer alone accepted any certificate DigiCert had issued to anyone), and Twine, CURBy, NIST and drand reads return their documented error codes on a malformed answer instead of stopping the program.
- `http_get` now verifies the zstd content checksum when a `Content-Encoding: zstd` frame carries one; a mismatch is `R_HTTP_ENCODING` (ruzstd's `hash` feature, adding `twox-hash` 2.1.4). Additive; no artifact format change.
- Tooling and host fixes from building `beacons` (no artifact format change). `guion test` with no file, or with a directory, runs the directory's `tests.gu` (the file `guion new --lib` writes and every package here uses); an explicit file still wins, and a directory without one is tested as a project as before. The package capability check recognises hosts in every literal form a request is built from: URL literals as before (so a literal base URL that a path is added to counts) and now bare host names such as `"api.example.com"`, `"api.example.com/v2"` and `"api.example.com:8443"` that match a declared host, and it names each declared host no literal mentions instead of one generic warning. `guion run --replay` of a program that has changed since the recording no longer stops at the program hash: each outside call must match the recorded one in kind, arguments (URL, headers, body, path) and order, and a note says the hash differs (a call that moved to another line or has other locals on the stack still matches; a call with other arguments, a call out of order, a missing call or an extra one is `R_TAPE_DIVERGED`). `--replay-strict TAPE` keeps the old refusal; `--replay-changed` still finds the first differing call by place. Tapes now carry a `call_sha256` per call; older tapes lack it and are matched strictly. `http_get` and the other HTTP calls decode a response sent with `Content-Encoding: zstd` (some hosts send it unasked even though the client advertises no encoding), bounded by the response byte limit (`R_HTTP_LIMIT`, `R_HTTP_ENCODING` on bad data); pure-Rust `ruzstd` 0.9.1, native runtime only. `beacons` fetches Twine pulses by CID again and names its hosts as bare names.
- Language and library rough spots from building `beacons` and the MCP server, all additive. `pass` is a statement that does nothing, so a `match` arm can be empty (`E_BLOCK_EMPTY` now names it; `pass` stays usable as a name). New builtins `int_and`, `int_or`, `int_xor`, `int_shift_left` and `int_shift_right` for 64-bit integers (artifact format 83, from 82; older artifacts still load; `R_INTEGER_RANGE` for an operand outside 64 bits, `R_SHIFT_RANGE` for a shift count outside 0 to 63). Every standard-library module that returns `StdError` re-exports it (`pub import "std:http_types"`, as `std:http` did), so `import "std:crypto"` is enough to name `StdError`. `std:json` adds `json_int_list_safe`, and the reference now says which JSON accessors stop the program and which return a `Result`. `packages/beacons` uses the bit operations in its base32, varint and big-endian helpers, and `language/examples/mcp_server` uses `match` for notifications and answers wrong-typed requests with JSON-RPC `-32600` or `-32602` instead of exiting.
- `beacons` package, part 3 (`packages/beacons`): the NIST Randomness Beacon 2.0 in Guion. `nist_verify(pulse, certificate_pem)` serializes fields 1 to 19 of a pulse as the live service signs them (4-byte big-endian length prefixes, 4-byte `external.statusCode`, 8-byte indexes), checks RSA PKCS#1 v1.5 with SHA-512 under the certificate's key, that `certificateId` is SHA-512 of the certificate's DER, and that `outputValue` is SHA-512 of the serialization plus the raw signature; `nist_verify_precommitment(previous, current)` checks `previous.precommitmentValue == SHA-512(current.localRandomValue)`, the chain link and consecutive indexes. A tampered `localRandomValue` gives `false`. `nist_fetch_last`, `nist_fetch` and `nist_fetch_certificate` only fetch. Confirmed against live pulses, including a pair across a UTC day boundary; the live run is recorded in `packages/beacons/tapes` and replays offline. NISTIR 8213 (draft) says 8-byte length prefixes; the live service uses 4.
- `beacons` package, part 2 (`packages/beacons`): Twine and CURBy in Guion. `twine_verify` recomputes a record's CID (DAG-CBOR then SHA3-512 over `data`), checks that the JWS payload is the SHA3-512 multihash of the DAG-CBOR of `data.content`, and verifies the JWS (RS256, PS256 or ES256; other algorithms are `E_TWINE_ALG`) under the chain's JWK; a tampered content, signature or CID is `false` or an error, never `true`. `twine_verify_links` / `twine_verify_links_in` walk back through `links[0]`; `twine_fetch_chain`, `twine_fetch_latest` and `twine_fetch_pulse` only fetch. `curby_q_chain`, `curby_rng_chain`, `curby_randomness` (the 64 bytes of a CURBy-Q randomness pulse) and `curby_rng_randomness` (CURBy-RNG, with the precommitment check). The latest CURBy-Q, CURBy-RNG and a P-256 chain pulse verify, and the bytes match CURBy's own JavaScript client; the live run is recorded in `packages/beacons/tapes` and replays offline.
- `beacons` package, part 1 (`packages/beacons`, not published to the registry): base32, varint and CIDv1 helpers (`base32_lower_encode`, `cid_v1`, `cid_parse`), and drand quicknet in Guion over the new crypto primitives: `drand_fetch` (falls back from `api.drand.sh` to `drand.cloudflare.com`), `drand_verify` (BLS check plus `randomness == SHA-256(signature)`), round arithmetic, and `tlock_seal` / `tlock_open` (refuses another chain with `E_TLOCK_CHAIN` and a future round with `E_TLOCK_TOO_EARLY`). 100 consecutive live quicknet rounds verified; the run is recorded in `packages/beacons/tapes` and replays offline.
- `guion run` writes each `print` and `eprint` as it happens instead of after `main` returns, so a program used as a stdio tool or read through a pipe delivers lines at once. `output_limit_bytes` still counts every byte. A reader that closes the pipe stops the program with the new stable code `R_OUTPUT_CLOSED`. `guion run --json`, `guion test`, `guion serve` and embedders keep buffering; `HostPolicy::with_streaming_output(true)` turns streaming on for an embedder.
- `std:io` reads the program's own standard input (artifact format 77, from 76; older artifacts still load). `stdin_read_line() -> Result[Option[Text], StdError]` gives each line without its line ending and `None` at the end; `stdin_read_all() -> Result[Bytes, StdError]` gives the rest as raw bytes, bounded by `max_file_bytes`. `[runtime] stdin_line_limit_bytes` (default 1048576) bounds a line. Typed errors: `E_STDIN_LINE_LIMIT`, `E_STDIN_UTF8`, `E_STDIN_READ`, `E_STDIN_LIMIT`. Needs no grant; `guion inspect` reports the effect `process.stdin`. `--record` keeps what was read; the browser playground refuses it with `R_HOST_UNSUPPORTED`. New instructions `StdinReadLine` (221) and `StdinReadAll` (222).
- `language/examples/mcp_server` is a Model Context Protocol server written in Guion: newline-delimited JSON-RPC 2.0 over stdio with `initialize`, `ping`, `tools/list` and an `echo` tool. It reads requests with `stdin_read_line`, answers each one as it arrives, and ends at end of input. Its `guion.toml` raises `instruction_limit` and `output_limit_bytes` because a long-running stdio tool would otherwise hit the script-sized defaults.
- `std:encoding` adds `dagcbor_encode(value: Json) -> Result[Bytes, StdError]` (artifact format 82, from 81; older artifacts still load): canonical DAG-CBOR, hand-written in `guion-crypto` with no IPLD crate. Integers use the shortest form, other numbers are 64-bit floats, map keys sort by encoded length then bytes, `{"/": "<cid>"}` is a tag-42 link and `{"/": {"bytes": ...}}` a byte string. `E_DAGCBOR_VALUE` for NaN, infinities, out-of-range integers and nesting past 128 levels; `E_DAGCBOR_LINK` for a malformed link. `Crypto` function code 9, gated on format 82. Pure, so it runs in the browser playground. Checked by recomputing the CIDs of live CURBy chain records (CIDv1, dag-cbor, SHA3-512, over the whole `data` object). Adds `serde_json` to `guion-crypto`.

- `guion add NAME [--version REQ] [--approve-capabilities]` (and `--path`, `--url`): a project may keep an `[approved-capabilities.NAME]` table in `guion.toml`, in the same shape as a package's `[capabilities]`. - F7 (`322fde8`), the `web` package (`packages/web`, not published to the registry): routing, middleware and serving, with every function declaring its effects and none naming a socket or other handle. `route(method, pattern, handler)` and `router(routes) -> Result[Router, HttpFailure]` take patterns with typed parameters (`{id:int}`, `{slug}`); `router_handle(router, request)` dispatches and fills `Request.params`, and `path_param` and `path_param_int` read them. Two routes that can match one path with the same method are `E_ROUTE_CONFLICT` at construction (no precedence rules: `/users/{id}` and `/users/new` conflict, `/users/{id:int}` and `/users/new` do not), and a malformed pattern is `E_ROUTE_PATTERN`. `{id:int}` given `abc` is a 404, an encoded slash (`%2F`) stays inside one parameter, a trailing slash is significant (no redirect) and a bad percent escape is a 400. A path that exists under other methods is a 405 with `Allow`. Function values capture nothing, so there is no `wrap(mw, handler) -> handler`: a `Middleware` is a record of a named `before(request) -> Result[Request, Response]` and a named `after(request, response) -> Result[Response, HttpFailure]`, an `App` holds the router and the layers, and `wrap(app, layer)` makes the layer outermost (outermost first in, last out; tested with three wrappers). ### Standard library

- F3 (`74dd4b8`), no format change: `std:http_response` adds request and response values for HTTP servers. `Response` is a value (status, an ordered list of headers that may repeat a name, and a `Body` of bytes, text or a chunked stream), so a response built in one function can be returned through others, compared with `==`, and serialized for tests with `response_serialize`. `Request` carries `method`, `path`, `query` (name to list of values), `headers`, `body` and a `params` map that is empty until a router fills it. A header name that is not a token, or a value containing CR, LF, NUL or another control character, is refused at construction (`E_HTTP_HEADER_INVALID`) and again at serialization, which includes `Location` from `response_redirect`. `std:http_server` adds `http_request_value` (the only function that reads the connection-bound request) and `http_server_send_response`. A handler is `fn(Request) -> Result[Response, HttpFailure]` and names no socket. Streams are `stream_from_list(chunks)` and `stream_from_file(path)`; a streamed file is read when the response is sent, so it is held in memory then. All additive: `guion doc` effects for the existing `http_server_*` functions are unchanged, and `http_server_respond`, `http_server_reply` and `http_server_send` now build their output through the new code (same bytes; a content type with a line break is now an error instead of being sent). Artifacts and the artifact format are unchanged.
- F4 (`4179555`), no format change: `std:cookie` parses the `Cookie` header into a map (malformed pairs are dropped, never an error) and builds `Set-Cookie` values from a `Cookie` record with `HttpOnly`, `Secure`, `SameSite`, `Path`, `Domain`, `Max-Age` and `Expires`; values are percent-encoded so `;`, `,`, quotes and line breaks cannot inject attributes, and `response_add_cookie` adds the header through the `std:http_response` check. HttpOnly and `SameSite=Lax` are the defaults. `SameSite=None` without `Secure` is a typed error at run time (`E_COOKIE_SAMESITE_NONE_NEEDS_SECURE`), not a build-time error, because a cookie is a value: `cookie_same_site` and `cookie_serialize` refuse it. `cookie_parse_set` reads a `Set-Cookie` line back. All additive.
- F5 (`6914ec9`), no format change: `std:http_body` parses request bodies with explicit limits. `form_parse(body, limits)` reads `application/x-www-form-urlencoded` into `Map[Text, List[Text]]`; `multipart_parse(request, files_root, limits)` reads `multipart/form-data`, treats a part with a `filename` as a file written under `files_root` with a random name (the client name is sanitized to its final component, kept only as `original_name`, and never used as a path) and a part without one as a field. `BodyLimits` (defaults: max_headers 16, max_header_bytes 8192, max_parts 1000, max_part_bytes 8388608, max_total_bytes 16777216) is enforced exactly: over a limit is a 413 naming it, at the limit is accepted. Nothing is written until the whole body parses. A folded part header, a control character in a header and a boundary over 70 characters are 400s. `body_read_limit` and `body_read_failure` pair with `http_server_read_request`, which now names `max_body_bytes` in its 413 body (it already refused a declared oversized body before reading it). Failures are `HttpFailure` values.
- F6 (`97f29e5`), artifact format 73: `std:http_static` serves files from a directory as `Response` values. `static_serve(request: Request, root: Text) -> Result[Response, HttpFailure]` (effect `filesystem.read`) answers GET and HEAD for the file the request path names under `root`, with a content type from a documented extension table (unknown is `application/octet-stream`), a weak `ETag` of the form `W/"<size>-<mtime-ms>"` (cheap, not a content hash), `Last-Modified`, `If-None-Match` and `If-Modified-Since` giving 304 with no body (`If-None-Match` wins when both are sent), and one `Range` giving 206 with `Content-Range` or 416 with `Content-Range: bytes */N`. A suffix range (`bytes=-500`), `bytes=0-0` and an open range (`bytes=500-`) work; more than one range, another unit or a malformed range is ignored and the whole file is sent with 200. HEAD gives the same status and headers as GET, with Range honoured, and no body; other methods are 405. Every path segment is percent-decoded once and a segment that decodes to `..`, holds `/`, a backslash or NUL, or starts with `.` is a 404 (a bad escape is 400); the joined path is resolved through symbolic links and must stay inside `root`, so a link that leaves it is a 404. A directory is served as its `index.html` and is never listed. `static_content_type(path)` and `static_http_date(unix_ms)` are pure. A file body is a stream the server sends in blocks of at most 65,536 bytes, so a large file is never held in memory: `std:http_response` adds `FilePlan`, `response_file_plan`, `response_file_head`, `response_file_block`, `response_file_block_size` and `response_file_end`, and `http_server_send_response` now sends file streams (including `stream_from_file`) block by block instead of reading the file whole. New `Fs` function codes 18 (`read_range`, at most 16 MiB per call) and 19 (`confined_path`) carry the artifact format to 73; an older format that uses either is refused with `E_ARTIFACT_VERSION` and format 72 and earlier artifacts still load. Additions only against the 0.3.0 surface.

### Fixed

- A `Bool` argument (`875aa25`) passed to a function that runs as machine code arrived as `true` whenever the caller ran in the interpreter instead, which is the case for a caller that prints. `a(false)` inside a `main` that also calls `print` took the `true` branch of `a`; with no `print`, or through a helper that does not print, the value was correct. ## 0.3.0 — 2026-11-14 (shipped inside 0.4.0)

0.3.0 was built and verified on its own branch and is released together with 0.4.0: there is no separate 0.3.0 download, and 0.4.0 contains everything below.

Closes the fourteen build gaps an outside evaluation of 0.2.0 found (labelled B1 to B14 below), and adds checks that keep later releases additive. The artifact format goes from 64 to 72; every format 14 through 72 still loads.

### Breaking

- `break` and `continue` are now reserved words at the start of a statement. A program that used either as a variable, parameter or function name no longer compiles. Migration: rename the identifier (for example `break` to `stop` or `brk`, `continue` to `again`) and run `guion check`; a use of either word outside a loop is `E_NO_LOOP`. The corpus shipped with Guion contains no such use. See [compatibility and migrations](docs/compatibility-and-migrations.md).
- Nothing else is removed or re-signed: `language/surface-0.3.0.json` records the 0.3.0 public surface, and `cargo xtask surface-diff` fails on any removal or changed signature against it.

### Language

- B1: `break` and `continue` are new statements for `while` and `for` loops, and they are now reserved words at the start of a statement. Outside a loop they fail with `E_NO_LOOP`. The artifact format is unchanged.
- B2, artifact format 65: `sort(values)` for lists of `Text`, `Int` and `Float64`, and `sort_by(values, key)` with a named `(T) -> K` key function for `K` in `Text`, `Int` or `Float64`. Both are stable and total (`-0.0` before `0.0`, NaN last), `Text` compares by Unicode scalar value exactly as sorted map keys do, `sort_by` calls the key once per item, and native comparisons are charged to the instruction budget as `sort_by_int_key` is. A key of another type, such as `Bool` or `Unit`, fails at check time with `E_SORT_KEY`. `sort_by` with a two-parameter `(T, T) -> Int` function is still the comparator sort, and `sort_by_int_key` and `merge_sorted_by_int_key` are unchanged; artifacts at format 64 and earlier load and run as before. The key is a named function until function values arrive.
- B3, artifact format 66: first-class function values. `fn(Int) -> Int` is a type, `let f = double` binds a named function (own or imported) as a value, a function can be a parameter, a result, a record field or a list or map item, and `f(x)` calls it with the arity and types checked at check time. Function values capture nothing: a lambda or a nested `fn` is `E_FN_NO_CLOSURES`, and `==` on one is `E_FN_COMPARE`. Effects attach where a value is formed, so `guion inspect` and `guion doc --json` attribute a function's effects to the function that writes `let f = writer_fn` or passes `writer_fn`. A type that holds a function is `E_FN_NOT_SERIALIZABLE` at the JSON, CSV, TOML, SQLite, process, HTTP, file and `print` boundaries; it may be passed to `parallel_map` workers. New builtins `map_list`, `filter_list`, `fold_list`, `any_list` and `all_list`; `sort_by`, `sort_by_int_key`, `merge_sorted_by_int_key` and `parallel_map` also accept function values. New operations `MakeFn`, `CallFn` and `HigherOrder` (tags 198 to 200); artifacts below 66 that use them are rejected with `E_ARTIFACT_VERSION`, and format 65 and older artifacts still load and run. Recursion through a function value stops at the call-depth limit; a value that names no function is `R_FN_INVALID`. Functions that form or call function values run in the interpreter, not as machine code. In the browser VM function values work, but the higher-order builtins and the sorts need a host operation the browser VM lacks. Unknown calls named `map` and `filter` now suggest `map_list` and `filter_list`. Closures are listed in known issues.
- B9: an unknown call name still fails with `E_NAME_UNKNOWN`, and now adds up to three `help: did you mean` lines for near misses among the module's functions and the builtins (edit distance at most `max(2, len/3)`). `guion check --json` gains an additive `diagnostic.suggestions` array. Both compilers report the same names.

### Standard library

- B4, artifact format 67: `std:crypto` adds `crypto_sha256(data)`, `crypto_sha256_text(text)` and `crypto_sha256_file(path)`. The first two return the 32-byte digest of a `Bytes` or `Text` value; the file form digests the file in fixed-size blocks (a 50 MiB file peaks near 7 MiB resident on the development machine), needs the file-read grant, and returns a typed `StdError` for a missing or ungranted path. The vectors for empty input and `abc` and a comparison with `shasum -a 256` are tests. Artifacts below 67 that use them are rejected with `E_ARTIFACT_VERSION`; formats 14 through 66 still load.
- B12, artifact format 68: `std:crypto` adds `crypto_random_bytes(count)`, `crypto_random_hex(count)` and `crypto_random_base64url(count)`, each returning `Result[..., StdError]`, with `count` the number of random bytes. They draw from the operating system's cryptographic generator (`getentropy` on macOS, `getrandom` on Linux), at most `crypto_random_max_bytes()` (1 MiB) per call; 0 gives empty output, and a negative or too large count is `E_RANDOM_COUNT` and a failing source `E_ENTROPY_UNAVAILABLE`. No grant is needed. Programs that use them are not reproducible. Embedders can pin the source with `HostPolicy::with_entropy_source` for tests; it is not reachable from guest code or `guion.toml`. `std:random` is unchanged. Artifacts below 68 that use the new instruction (tag 201) are rejected with `E_ARTIFACT_VERSION`; formats 14 through 67 still load.
- B14, artifact format 69: `std:sqlite` adds `sqlite_begin_read(database)`, which opens a `BEGIN DEFERRED` read transaction. A reader no longer waits behind a writer's transaction and no longer fails with `E_SQLITE_BEGIN` while one is held; a write statement inside it returns `E_SQLITE_READ_ONLY` and the transaction stays usable. The busy deadline is now published: 2000 ms per attempt, the runtime constant `SQLITE_BUSY_DEADLINE_MS`, quoted in `language/host-api.md` and checked against the code by a test. `PRAGMA` cannot change it and write transactions still serialize. Artifacts below format 69 that use `sqlite_begin_read` are rejected with `E_ARTIFACT_VERSION`; format 68 and older artifacts still load and run.
- B6, artifact format 70: `std:log` adds `log_open(root, level)`, `log_debug`, `log_info`, `log_warn`, `log_error`, `log_info_at(logger, instant, msg, fields)` and `log_info_now(logger, msg, fields)`. A logger is a value, not global state; each record is one JSON line with `level`, `msg` and the caller's fields in sorted key order, and `ts` first only for the `_at` and `_now` forms. The plain functions never read the clock; `log_info_now` carries `clock.read` and fails with `R_CLOCK_DENIED` without the grant (effects are enforced when the operation runs). `[log] level` in `guion.toml` sets the default level. A record below the logger's level formats nothing. New instructions `LogAppend` and `LogDefaultLevel`; artifacts below format 70 that use them are rejected with `E_ARTIFACT_VERSION`.
- B5, artifact format 71: `std:compress` adds `gzip_compress`, `zlib_compress`, `gzip_decompress(data, max_output)`, `zlib_decompress(data, max_output)`, `gzip_compress_file(source, destination)` and `gzip_decompress_file(source, destination)`; `std:tar` adds `tar_write(directory, archive)`, `tar_read(archive, destination)` and `tar_list(archive)`. Every inflate has an output ceiling, so a small input cannot expand without bound: `max_output` for the in-memory forms, capped by the new `[runtime] decompress_limit_bytes` key in `guion.toml` (default 1 GiB), which alone bounds the file and tar forms; output past it is `E_COMPRESS_LIMIT`. Multi-member gzip decompresses to the members concatenated; bytes after the last member or after a zlib stream are `E_COMPRESS_TRAILING_DATA`. The file forms stream in 64 KiB blocks (a 200 MB gzip round trip peaked at 7,045,120 bytes resident on the development machine, release build) and write through a temporary file renamed on success. `tar_write` gzip-compresses archives named `.gz` or `.tgz`, refuses symbolic links, and writes deterministic metadata; `tar_read` refuses absolute names, `..` components and links that could leave the destination with `E_TAR_UNSAFE_PATH`. Inflate bytes written by Python's `gzip` and `zlib` modules, and tar listings by the system `tar -tzf`, are checked in the tests. New instructions `GzipCompress`, `GzipDecompress`, `ZlibCompress` and `ZlibDecompress` and `Fs` function codes 13 to 17; artifacts below format 71 that use them are rejected with `E_ARTIFACT_VERSION`, and a format-70 artifact still loads. The runtime gains the pure-Rust `flate2` and `tar` crates; the browser VM is unchanged. zstd is a named follow-on, not part of this release.
- B10, artifact format 72: `std:yaml` adds `yaml_parse(text) -> Result[Json, StdError]`, a read-only reader for a documented YAML subset (block and flow collections, plain, quoted, literal and folded scalars, comments), for CI workflows, Docker Compose files and similar configuration. A plain scalar is text except lowercase `true`/`false`, `null`/`~` and integers or decimals that read back unchanged, so `NO`, `yes` and `1.10` stay text; quoted scalars are always text. Anchors, aliases, tags, the merge key, complex keys, directives and multi-document streams fail with `YAML_UNSUPPORTED` naming the feature, with the line and column and no partial value; other errors are `YAML_SYNTAX`, `YAML_DUPLICATE_KEY` and `YAML_LIMIT`. One new instruction, `YamlParse` (tag 209); artifacts below format 72 that use it are rejected with `E_ARTIFACT_VERSION`, and format-71 artifacts still load. The parser is hand-written in the runtime and adds no dependency to the VM. There is no YAML writer. INI is declined and recorded in the language spec.

## 0.2.0 — 2026-11-12

- Added a written [stability policy](docs/stability-policy.md): source compatibility within a minor series, the artifact formats the runtime reads (14 through 64), a deprecation period of at least one full minor release, how library packages are distributed and pinned, and what is not promised.
- Matrix multiplication of `f64` and `f32` arrays is much faster: a 512 by 512 multiply takes about 1.5 ms of compute (the old kernel took about 27 ms after start-up), about 2.3 times NumPy's compute on one Apple M1 Pro (2.26 in the committed compute-only run, 1.46 ms against 0.64 ms per multiply), and gives the same result on every run and thread count.
- Fixed calendar parsing from several threads at once: `calendar_parse` called libical, whose time zone tables are not thread-safe, and could return a wrong resolution (a gap where the time is exact); calls are now taken one at a time. A matrix product with a single row or column now equals the matching part of the full product to the last bit, `array_matmul` no longer aborts when the operating system refuses a thread, and `frame_show` aligns every emoji with emoji presentation by its display width. `frame_write_csv` of float columns and `frame_read_jsonl` are faster (about 15 percent and 1.7 times on one Apple M1 Pro).
- Fixed array and frame correctness: `array_i64_range` no longer panics in debug builds on extreme operands; temporary buffers in matmul, sort, argsort, factorize and join_index are charged to the allocation budget, and kernel temporaries and CSV error paths are released; array error messages name the guest operation rather than an internal one, and invalid arguments such as `array_clip` with low above high raise the new `R_ARRAY_ARGUMENT` instead of `R_ARRAY_SHAPE`; the Rust and self-hosted compilers give the same Array element type errors. In `frames`, tables align wide characters and text with newlines, join suffixes avoid a taken `<name>_right` name, `column_from_codes` checks its codes and returns `Result`, very large and very small floats use the shortest exponent form, JSONL reading keeps keys first seen after line 1, a single-column CSV keeps a row whose value is missing instead of skipping its blank line, and written CSV ends every record with a newline.

- Artifact format 62: native n-dimensional arrays, `Array[e]` over `i8` to `u64`, `f32`, `f64` and `bool`, with checked conversion and integer overflow, NumPy-style broadcasting arithmetic, comparisons, float math, exact integer reductions, axis reductions, stable sorting, `dot`/`matmul`, ranges, `linspace`, and seeded random and normal arrays that continue the `std:random` stream. `set a = array_set(a, i, v)` updates a local in place. Both compilers accept, reject and compile array programs identically. Array functions run in the VM; the machine-code tier compiles the functions around them.

Chained text appends to a local are linear; functions returning `Unit` and functions using `assert` compile natively. `guion update` moves registry packages within their recorded range, `guion token rotate|revoke` and matching registry endpoints retire publisher tokens, and library checks require hosts in URL literals to be declared. `fs_remove` and `fs_rename` act on symlinks themselves, and writing through a dangling symlink is refused (it could create a file outside the granted root).

The registry signs its log with ed25519 and the client verifies it (the default registry's key is built in), `guion check` and `guion inspect` say when a program can write files, and precompiled `.gub` attachments are deferred.
