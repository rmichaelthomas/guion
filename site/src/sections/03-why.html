02 / An ambitious question

Another language?
Only if it earns its place.

New syntax alone isn't enough. The question Guion is built around is practical: when should someone confidently choose it to do real work?

North-star question: when should a builder, or an assistant advising one, pick this over Python for real work? The first release has to say honestly where Python is still better.

{{slot:why-pull-quote}}

  1. Readable without guessing.

    You say what kind of thing a type each function takes and gives back. Everything inside it is worked out for you. You can read a Guion program and know what goes in and what comes out.

    Typed function boundaries, inferred locals. Option[T] for absence, Result[T, E] for recoverable failure, ? to propagate. Records, lists, maps, modules, bounded JSON, files, SQLite, TOML, HTTP.

    Margin note

    “Plain English” is the goal for learning and diagnostics. Free-form natural-language code is not the claim. Authority: language/spec.md.

  2. More than a language.

    One command makes a project, checks it, tidies it, tests it, runs it, packs it up, and tells you what it can do. A person, or an assistant, can ask for a report instead of text.

    {{cli-count}} subcommands in one binary. --json on check, lint, test, run, build, package, verify-package, inspect, doc, doctor and sync returns a versioned report with stable fields and codes.

    Margin note

    Report kinds and schemas are indexed in docs/agents/index.json; the table in section 03 lists each one.

  3. A claim should survive contact.

    Every number on this page says which program it measured, on which machine, and what it does not tell you. Then it points at the file it came from, so you can check.

    {{claim-count}} receipts, each with workload, host, interval, scope limit, and linked report and raw-sample files. A build step fails if a figure on this page is not in the file it cites.

    Margin note

    Files are copied byte for byte to the evidence page with their SHA-256.
