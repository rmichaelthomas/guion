# Guion language contract, current executable subset

This is the current implementation contract for the approved north-star design. It defines the subset implemented in the current candidate; unsupported syntax must produce a source diagnostic instead of being ignored.

## Source and declarations

- Source is UTF-8. Newlines separate statements. Four spaces define one indentation level; tabs and mixed indentation are errors. `#` begins a line comment.
- A source file is a module. It contains one or more `fn name(parameter: Type, ...) -> Type:` declarations and may declare records with `record Name:` followed by indented `field: Type` declarations. `import "relative-path.gu"` loads another source file; `pub import "relative-path.gu"` also re-exports that module's public declarations to downstream importers. The imported module's `pub fn` and `pub record` declarations become available by their declared names. Private declarations remain local to their module. Imports are resolved from the importing file and must stay inside the project root. The graph is limited to 512 files, 128 import levels, 8 MiB per source file, and 64 MiB total source text. Duplicate declaration names and cycles are errors. Types in this executable subset are `Int`, `Float64`, `Bool`, `Text`, `Bytes`, `Unit`, `Json`, `JsonError`, `FileError`, `HttpError`, `TaskError`, `List[T]`, `Map[Text, T]`, `Option[T]`, `Result[T, E]`, `Array[e]` (artifact format 62; see Runtime rules), and declared record names.
- The entry point is `fn main() -> Int:` or `fn main() -> Unit:` in the project entry module. Calls resolve statically to local declarations, explicitly imported public declarations, or host functions such as `print(value)`. A single source file can be compiled without a project only when it has no imports.
- Function parameters and results are annotated. Local types are inferred unless an optional local annotation is supplied, as in `let pending: List[Int] = []`. `let` creates an immutable local; `var` creates a mutable local; `set name = expression` changes only a mutable local. An annotation supplies context for empty collection literals and must exactly match the initializer type.

## Statements and expressions

Statements: `let`, `var`, `set`, `return`, `if`/`else`, `while`, `for name in list`, exhaustive `match` statements for `Option`, `Result` and enums, and a call expression as a statement. A `match` arm may nest patterns inside `Some`, `Ok` and `Err` (no new artifact format: the compiler lowers them to single-level matches): `Ok(Some(x))`, `Ok(None)`, `Err(e)`, `Some(Red)` with an enum variant. A bare name inside a pattern binds the value (`_` binds nothing) unless it is a declared enum variant, which it then means (`Some(Red)` matches `Red`; before 0.8.0 it bound a local named `Red`). An enum variant pattern on a value of another type, such as `Err(Red)` where the `Err` holds `Text`, is `E_MATCH_TYPE`. Every value must match exactly one arm: a combination no arm covers is `E_MATCH_NONEXHAUSTIVE` (`E_MATCH_MISSING_VARIANT` for an enum) naming it, such as `Ok(None)`, and two arms that match the same value, including a name beside a variant at the same place, are `E_MATCH_DUPLICATE`. Enum variant values are scalars or lists, so they take names only. An arm may also be an `Int` (any base, `_` separators, `-` for a negative), `Text` or `Bool` literal, at the top or inside `Some`, `Ok` and `Err`, with `_` or a name as the catch-all: the compiler lowers the arms to an `if` / `else` chain of `==` (no new artifact format). `Int` and `Text` matches need the `_` arm (`E_MATCH_NONEXHAUSTIVE` names it); `Bool` with `true` and `false` is complete; a repeated literal or an arm after the catch-all is `E_MATCH_DUPLICATE`; a literal of the wrong type is `E_MATCH_TYPE`. `if` and `while` conditions must be `Bool`. `break` leaves the innermost enclosing `while` or `for` loop, and `continue` skips the rest of the loop body (in a `for`, it advances to the next item; in a `while`, it re-tests the condition). Each is a statement on its own line, valid only inside a loop body, including inside `if` and `match` arms nested in that loop; in a function with its own loops (such as a `parallel_map` worker) it binds to that function's loop. Outside any loop, `break` and `continue` are rejected with `E_NO_LOOP` ("`break` outside a loop" / "`continue` outside a loop"). `break` and `continue` are reserved words at the start of a statement. `pass` on a line of its own is a statement that does nothing, so a `match` arm (or any block) can be empty on purpose: `None:` then an indented `pass`. A block with no statement is `E_BLOCK_EMPTY`, and its message names `pass`. `pass` is recognised only as the whole line, so it stays usable as a name. Resource handles such as a `FileReader` are not tied to a loop: leaving a loop early does not close one, and the runtime closes any handle still open at the end of the invocation. A function body is indented under its declaration. `else` aligns with `if`.

Everyday forms: see `docs/reference.md`.

- Expressions: arbitrary-precision integer literals (decimal, or `0x`/`0X` hexadecimal, `0o`/`0O` octal and `0b`/`0B` binary, with `_` allowed between any two digits as in `1_000_000` and `0xFF_FF`; a misplaced `_`, a prefix with no digits or a digit outside the base is `E_NUMBER_LITERAL` at that character; a negative value is the unary `-`; `007` is 7), finite `Float64` literals with a decimal point or exponent (digits may be separated with `_` too), booleans (`true`, `false`), double-quoted UTF-8 text with `\u{H...}` Unicode scalar escapes (one to six hexadecimal digits; surrogate values and values above U+10FFFF are invalid), local/function names, calls, record construction/access, list literals, map literals with unique text keys, list/map/text/bytes indexing, parentheses, unary `-` and `not`, and binary `*`, `/`, `//`, `%`, `+`, `-`, comparisons `== != < <= > >=`, and short-circuit `and` / `or`. `Float64` is IEEE 754 binary64; its arithmetic and comparisons require two `Float64` values, reject non-finite literals/results, and never convert `Int` implicitly. `sqrt(Float64)` returns the non-negative square root; a negative input raises `R_MATH_DOMAIN`. Float division by zero raises `R_DIV_ZERO`. Integer `/` truncates toward zero; `//` rounds down; `%` follows the divisor's sign, so `a == (a // b) * b + (a % b)`. All three integer division operators raise `R_DIV_ZERO` on a zero divisor. Map literals infer one homogeneous value type; an empty map needs a `Map[Text, T]` annotation or other expected type, and keys must be text literals. Empty list literals likewise need an expected `List[T]` type. `list_push(List[T], T)` appends and `list_set(List[T], Int, T)` replaces an existing zero-based index; both return immutable copies, and the compiler may use copy-on-write for updates assigned back to the same mutable local while preserving aliases; out-of-range replacement raises `R_LIST_INDEX`. `Map[Text, T]` is immutable, `map_set` returns an updated copy, `map_has` tests membership, keys iterate and display in Unicode scalar lexicographic order, lookup of an absent key raises `R_MAP_KEY_MISSING`, and `len` supports lists, maps, Bytes (byte count), and Text (Unicode scalar count). Text indexing is zero-based by Unicode scalar and out-of-range access is a runtime error. `Bytes` indexing (artifact format 89) `data[i]` gives the byte at zero-based `i` as an `Int` from 0 to 255; an index outside `0` to `len(data) - 1` raises `R_INDEX_BOUNDS` and a negative one `R_INDEX_INVALID`. `text_slice(text, start, end)` returns a copied half-open range by Unicode scalar index, with a non-negative start, an exclusive end, and `0 <= start <= end <= len(text)`; an invalid range raises `R_INDEX_BOUNDS`. Types include `List[T]`, `Map[Text, T]`, `Option[T]`, and `Result[T, E]`; `Some(value)`, `None`, `Ok(value)` and `Err(error)` build a value wherever its type is known from where it goes: a return, an annotated `let`, a `set`, an argument, a record field, a list or map element, or another constructor (`return Ok(None)` in a function returning `Result[Option[T], E]`, `Some(Ok(x))`). `Some(x)` with nothing else to go on takes the type of `x`; where the type cannot be known (`let v = None`) or another type is expected, it is `E_OPTION_CONSTRUCTOR_CONTEXT` or `E_RESULT_CONSTRUCTOR_CONTEXT`, and the fix is to write the type: `let v: Option[Int] = None`. Precedence from low to high: `or`, `and`, comparisons, `+ -`, `* / // %`, unary, calls/indexing/field access/atoms. `+` accepts two Ints, two Float64 values, or two Text values.

## Runtime rules

### Typed map-record access and updates

`map_record_get(map, key, "field")` reads a statically checked field from a `Map[Text, Record]`; `map_record_set(map, key, "field", value)` returns an updated map after replacing that field. For a nested `Map[Text, Map[Text, Record]]`, pass both keys before the field name: `map_record_get(map, outer_key, inner_key, "field")` and `map_record_set(map, outer_key, inner_key, "field", value)`. The field name must be a text literal, and the compiler checks the map's record type, field existence, and value type. Missing keys fail with `R_MAP_KEY`. These expressions preserve map and record value semantics: assigning an update back to the same mutable local may reuse uniquely owned storage; any shared outer map, nested map, or record fields are copied as needed so aliases keep their previous values.

- `Int` is arbitrary precision subject to the configured digit ceiling. Integer `/` truncates toward zero, `//` rounds down, and `%` follows the divisor sign so `a == (a // b) * b + (a % b)`; all report `R_DIV_ZERO` for a zero divisor. `Float64` stores finite IEEE 754 binary64 values. Operations that overflow to infinity or NaN fail with `R_FLOAT_NONFINITE`; division by either signed zero fails with `R_DIV_ZERO`; `sqrt` of a negative value fails with `R_MATH_DOMAIN`. Python interop transports Float64 through round-trippable decimal strings and rejects non-finite values. Lists are homogeneous, immutable value sequences; indexing is zero-based and out-of-range access is a runtime error. `list_push` and `list_set` return immutable lists, and `list_set` requires an existing index. When `set name = list_push(name, value)` or `set name = list_set(name, index, value)` updates a mutable local, the compiler may reuse uniquely owned storage and copies if any alias exists; this is unobservable and preserves immutable value behavior. Maps are immutable `Map[Text, T]` values with unique literal keys, homogeneous values, deterministic key iteration, immutable `map_set` updates, membership checks via `map_has`, and traced errors for missing keys. Map values may be passed between functions, serialized in versioned artifacts, and crossed through the Python bridge as string-keyed dictionaries when `T` is bridge-supported. Empty lists and maps use their expected type from annotations, function results or parameters, enclosing collections, and typed operations; uncontextualized empty literals produce a diagnostic. `Json` is a bounded JSON tree; object keys are text, duplicate keys are rejected, and object encoding sorts keys. JSON values require explicit accessors and do not silently coerce to source types. Records are immutable ordered named fields, constructed positionally (for example, `Point(3, 4)`) and accessed by field name (`point.x`). Construction requires every field with its exact declared type; record and field names are unique; equality is structural for the same record type. Unknown fields/types and malformed schemas are rejected. Records serialize in compiled artifacts, but are not supported through the Python bridge yet. First-class functions remain for subsequent implementation steps. `Option[T]` supports `Some(value)` and `None` inside functions declared to return `Option[T]`; `is_some(option)` tests presence and `unwrap(option)` returns the value or raises `R_OPTION_UNWRAP`. `Result[T, E]` is available for file operations, JSON parsing, and `parallel_map`; inspect results with `is_ok`, `unwrap`, and `error`. `Ok`, `Err`, postfix `?`, and exhaustive `match` statements are available for `Result[T, E]`.
- Integers compare by mathematical value. Text is Unicode scalar sequence data; `+` concatenates text. Equality requires equal runtime types.
- Locals are frame-owned values. `let` cannot be assigned; `var` can. Each invocation owns its locals. Calls have a bounded stack depth, instructions consume a configurable budget, and output is captured per instance. A shared cumulative estimated guest-data allocation budget covers input values, collection and record construction, text/byte/JSON values, host results, and output rendering across nested calls and parallel workers; exhaustion reports `R_ALLOCATION_LIMIT`. The default is 256 MiB. Under the `guion` command line the limit bounds memory the program holds rather than memory ever allocated, and there is no instruction limit unless `[runtime] instruction_limit` sets one (see `host-api.md`). Interpreter/JIT frames, operand stacks, and scalar arithmetic temporaries are excluded so changing execution backend does not change this limit. Integer growth is bounded separately by `max_integer_digits`. This is language-level estimate accounting, not an exact process-memory ceiling; limits for output, file bytes, text size, collection size, integer digits, and source/artifact size are separate.
- `print(value)` writes its display form plus one newline to the instance output buffer; under plain `guion run` (and `HostPolicy::with_streaming_output(true)`) it is instead written to stdout and flushed at once (native code batches its prints in 2 ms steps, at loop back-edges once a held line is 2 ms old and at function end; a fallback to the VM never repeats a line), still counted against `output_limit_bytes`, and a closed pipe is `R_OUTPUT_CLOSED`. `guion run --json` keeps buffering. `args()` returns all CLI arguments as `List[Text]`; `args_from(start)` returns the suffix beginning at a zero-based index and reports `R_ARGUMENT_INDEX` for a negative or past-end index. `env(name) -> Option[Text]` reads one environment variable only when its exact name is granted in `[environment].variables` in `guion.toml` (or by an embedding `HostPolicy`); an ungranted name raises `R_ENV_DENIED`, and an unset granted name returns `None`. `read_text(path) -> Result[Text, FileError]`, `write_text(path, content) -> Result[Unit, FileError]`, `read_bytes(path) -> Result[Bytes, FileError]`, and `write_bytes(path, content) -> Result[Unit, FileError]` are host operations; runtime embedders grant a project root and read/write rights in `HostPolicy`. The CLI grants the source or artifact directory; `guion run --file-root DIRECTORY` adds a further root. Reads search roots in grant order; writes use the last granted root. Relative paths only are accepted, parent traversal is rejected, and canonicalized symlink targets must remain under one granted root. Access/path/filesystem failures return `FileError`; configured size-limit failures remain runtime errors. This is a path policy, not an OS security sandbox. Bytes preserve arbitrary byte sequences and are limited by `max_file_bytes`.
- `http_get(url) -> Result[Text, HttpError]` performs a bounded GET for HTTP or HTTPS text. Network is denied by default. Embedders explicitly grant exact hostnames through `HostPolicy`; CLI projects list them under `[network].hosts` in `guion.toml`. A redirect is followed only when its destination hostname is also granted. A `Content-Encoding: zstd` response is decoded within the byte ceiling. Timeouts, response byte ceilings, and redirect counts are configurable; non-2xx statuses and transport/encoding failures return `HttpError`, inspectable through `http_error_code` and `http_error_message`. Host allowlists do not prevent DNS rebinding or provide OS-level egress confinement.
- `http_request(method, url, headers, body) -> Result[Json, HttpError]` supports GET, POST, PUT, PATCH, DELETE, HEAD, and OPTIONS with `Map[Text]` headers and a UTF-8 text body. Its JSON envelope contains integer `status`, text `body`, and lowercase response headers. `http_request_bytes(method, url, headers, body, timeout_ms) -> Result[HttpResponse, HttpError]` preserves arbitrary request and response bytes; `HttpResponse` has `status: Int`, `headers: Map[Text, Text]`, and `body: Bytes`. Importing `std:http` provides the response type and typed JSON helper; `std:types` re-exports the same type for compatibility. Non-2xx responses remain values. `http_response_text(response) -> Result[Text, HttpError]` checks the body's UTF-8 encoding and text-size limit; `std:http.http_response_json(response) -> Result[Json, StdError]` performs the same checks and parses JSON directly from the response bytes, without an intermediate `Text` allocation. It preserves the stable HTTP and JSON error codes and messages. A shared host client enforces one monotonic deadline through connection and body reads, bounds response accumulation, refuses cross-origin redirects, and interrupts in-flight reads on cancellation. Runtime URL hosts require exact grants in `[network].hosts` or `guion run --allow-http-host HOST`; network remains denied by default.
- `unix_time_ms() -> Int` returns wall-clock milliseconds since the Unix epoch, and `today_local() -> Date` returns the current date in the host process time zone. `format_utc_date(instant) -> Text` formats an `Instant` as its `YYYY-MM-DD` UTC calendar date without formatting the time of day. Clock access is denied unless `[clock].enabled = true` or the caller uses `guion run --allow-clock` / an embedding `HostPolicy` grant. The host supplies local-time and daylight-saving rules; tests and embedders can pin the clock through `HostPolicy::with_clock_unix_time_ms`.
- `sleep_ms(ms: Int) -> Unit` (artifact format 88) blocks the calling thread for at least `ms` milliseconds; `ms` outside 0 to 86400000 (one day) is the runtime fault `R_SLEEP_RANGE`. It needs no grant and is reported as the effect `clock.sleep`. It waits in slices of at most 10 ms, so a task that reaches its `wait_within` deadline or is stopped, and Ctrl-C, end it promptly; in a program that polls for signals with `process_signal_poll`, a signal that arrives ends one sleep early on each thread, so `main` and every sleeping task wake once for it (later sleeps on the same thread run their full time), and stays pending for the next poll. A tape does not record it, and a replay returns at once. In the browser it is `R_HOST_UNSUPPORTED`. A function that calls it runs in the VM, not as machine code.
- `text_lower(value: Text) -> Text` and `text_upper(value: Text) -> Text` in `std:text` (artifact format 90) change case with the Unicode default case mapping, for display: `Straße` uppercases to `STRASSE`, a capital sigma ending a word lowercases to the final form `ς`, and `İ` lowercases to `i` followed by a combining dot, so the result can be longer than the input (a result over the text limit is `R_TEXT_LIMIT`). To compare text without regard to case, use `text_casefold`. They need no grant and run in the browser VM.
- `json_keys(value: Json) -> Result[List[Text], JsonError]` in `std:json` (artifact format 90) lists an object's top-level keys in the order `json_stringify` writes them, which is ascending byte order of the key text; a value that is not an object is `Err` with code `R_JSON_TYPE`. It needs no grant and runs in the browser VM.
- `json_stringify_pretty(value: Json, indent: Int) -> Text` in `std:json` (artifact format 90) writes the value with each array element and object member on its own line, indented by `indent` spaces per level (0 to 16, else the runtime fault `R_JSON_INDENT`; 0 puts the lines at the left edge), `": "` after a key, `,` at the end of every line but the last of a container, `{}` and `[]` for empty containers, no trailing newline, non-ASCII text as is, and strings and numbers written as `json_stringify` writes them. It needs no grant and runs in the browser VM.
- `int_to_text_radix(value: Int, radix: Int) -> Text` and `text_parse_int_radix(text: Text, radix: Int) -> Result[Int, FileError]` in `std:text` (artifact format 90) write and read an `Int` of any size in radix 2 to 36: lowercase digits, a leading `-` for a negative value, no prefix, no separators; parsing accepts either case and one optional leading `-` and gives `Err` with code `E_INT_PARSE` for anything else. A radix outside 2 to 36 is `R_RADIX_RANGE`, a parsed value over the digit limit `R_INTEGER_LIMIT`. Pure, no grant; the browser VM runs them.
- `fs_set_mode(path: Text, mode: Int) -> Result[Unit, FileError]` and `fs_mode(path: Text) -> Result[Int, FileError]` in `std:fs` (artifact format 90) set and read permission bits as an `Int`, as `chmod` does and following symlinks. `mode` is 0 to `0o7777` (`0o600`, `0o755`, `0o4755`); anything else is `R_FILE_MODE_INVALID`. `fs_mode` returns the bits as an `Int` (`0o600` is 384), so `int_to_text_radix(mode, 8)` shows `"600"`. The path resolves against the granted file root like every other `std:fs` function, never the working directory, so it cannot leave the root; `fs_set_mode` needs the file-write grant and is reported as `filesystem.write`, `fs_mode` needs the file-read grant and is reported as `filesystem.read`. A missing path is `R_FILE_NOT_FOUND` and a refusal by the operating system is `R_FILE_PERMISSION`. Where the host has no permission bits (Windows) both are `R_FILE_UNSUPPORTED`, and the browser VM refuses them with `R_HOST_UNSUPPORTED`. A recording keeps them on the tape like the other file operations.
- `parallel_map(items, worker, limit)` calls a named unary function on immutable list items in worker-local VM instances and returns `Result[List[U], TaskError]`. `is_ok(result)` tests the variant; `unwrap(result)` returns the list from `Ok`; `error(result)` returns the `TaskError` from `Err`. `task_index`, `task_code`, and `task_message` read its failed input index and failure details. Workers preserve result order, use a bounded shared worker instruction allowance, stop scheduling and poll cancellation after failure, join running tasks, and merge completed output by input index. An instruction-limit failure inside a worker is a `TaskError`; host setup errors still fail the invocation.
- Numeric conversion and math (artifact format 52): `int_to_float(Int) -> Float64`, `float_to_int(Float64) -> Int` (truncates toward zero), `int_to_text(Int) -> Text`, and `float_to_text(Float64) -> Text` (the same shortest round-trip text `print` shows). `std:math` provides `math_sin`, `math_cos`, `math_tan`, `math_asin`, `math_acos`, `math_atan`, `math_atan2`, `math_sinh`, `math_cosh`, `math_tanh`, `math_exp`, `math_ln`, `math_log10`, `math_log2`, `math_log`, `math_pow`, `math_hypot`, `math_abs`, `math_floor`, `math_ceil`, `math_round` (half away from zero), `math_floor_int`, `math_ceil_int`, `math_round_int`, `math_radians`, `math_degrees`, and the constants `math_pi()`, `math_tau()`, `math_e()`. A domain error raises `R_MATH_DOMAIN`, zero to a negative power raises `R_DIV_ZERO`, and a non-finite result raises `R_FLOAT_NONFINITE`. Results use the platform's IEEE 754 libm, so they can differ in the last digit between targets. `std:random` is a deterministic SplitMix64 generator over immutable `Rng` values: `random_new(seed)`, `random_next_u64` (in `[0, 2^64)`), `random_next_i64` (the same 64 bits read as a signed integer), `random_next_float` (in `[0, 1)`), and `random_next_range(rng, low, high)` (uniform over `low <= value < high`, by rejection sampling; a range of more than 2^64 values raises `R_RANDOM_RANGE`); each returns the value together with the next `Rng`. The same seed gives the same sequence on every target. It reads no clock; seed it from `unix_time_ms()` when a changing sequence is wanted. From artifact format 61 the generator state in `Rng.state` is the 64-bit state read as a signed integer, and every function except `random_next_u64` runs on the machine-code path; the sequences are the same as in format 52.
- Bytes, encodings and URLs (artifact format 53): `bytes_to_ints(Bytes) -> List[Int]`, `bytes_slice(Bytes, start, end) -> Bytes` (raises `R_INDEX_BOUNDS` outside `0 <= start <= end <= len`), `text_from_bytes(Bytes) -> Option[Text]` (strict UTF-8) and `text_from_bytes_lossy(Bytes) -> Text`. `std:encoding` provides `base64_encode`/`base64_decode` and `base64url_encode`/`base64url_decode` (padded; decoding is strict about alphabet, length and padding and returns `E_BASE64_INVALID`), `hex_encode`/`hex_decode` (lowercase output; either case accepted; `E_HEX_INVALID`), and `encoding_utf8_encode`, `encoding_utf8_decode` (`E_UTF8_INVALID`) and `encoding_utf8_decode_lossy`. `std:url` provides `url_parse(Text) -> Result[Url, StdError]` (an RFC 3986 split into `scheme`, `userinfo`, `host`, `port` (`-1` when absent), `path`, `query` and `fragment`, with no normalization; bracketed IPv6 hosts; `E_URL_INVALID`), `url_to_text`, `url_encode_component` (everything except `A-Z a-z 0-9 - . _ ~` is percent-encoded as UTF-8), `url_decode_component`, `url_query_parse` (`+` decodes to a space) and `url_query_build`.
- Filesystem and paths (artifact format 54): `std:fs` adds `fs_exists`, `fs_kind` (`"file"`, `"directory"`, `"other"` or `"missing"`), `fs_size`, `fs_modified_ms`, `fs_list_dir` (sorted names), `fs_make_dir` (creates missing parents; succeeds if the directory exists), `fs_remove` (a file or an empty directory), `fs_remove_all`, `fs_rename`, `fs_copy` (returns the bytes copied) and `fs_temp_dir`/`fs_temp_file` (a unique entry under `.guion-tmp/` in the granted root; the prefix is 1 to 64 ASCII letters, digits, `-` or `_`). All return `Result[T, FileError]`. Each path is relative to a granted file root, may not contain `..`, and is confined after symlink resolution, as for `read_text`; mutating operations need the file-write grant. `fs_remove`, `fs_remove_all` and `fs_rename` act on the named entry itself: removing or renaming a symlink removes or moves the link, never its target, and only the directory holding the entry must lie inside the root (so a link pointing outside the root can still be removed). Other operations follow symlinks to a confined target. Writing through a symlink whose target does not exist is refused with `R_HOST_DENIED`, since it would create the target wherever the link points. The granted root itself cannot be removed or renamed. `std:path` provides POSIX path text functions that never touch the disk: `path_normalize`, `path_join`, `path_dirname`, `path_basename`, `path_extension`, `path_stem`, `path_with_extension`, `path_components` and `path_is_absolute`. Static inspection now reports `filesystem.read` for `fs_walk`, `file_open_lines` and CSV opening as well.
- Regular expressions (artifact format 55): `std:regex` provides `regex_is_match`, `regex_find` (the first match as a list of capture groups, group 0 first, unmatched groups as `""`), `regex_find_all`, `regex_replace`, `regex_replace_first` (replacement text expands `$1`, `${name}`; `$$` is a literal `$`), `regex_split` and `regex_escape`. Patterns use the Rust `regex` crate syntax: Unicode-aware, RE2-style, matching time linear in the subject, with no backreferences and no lookaround. An invalid or unsupported pattern, a pattern over 4,096 bytes, or one that compiles to more than 1 MiB of program returns `Err` with code `E_REGEX_INVALID`; no grant is required. Compiled patterns are cached per thread.
- Processes and signals (artifact format 56): `std:process` provides `process_run(command, arguments, stdin)` returning `Result[ProcessResult, StdError]` with `exit_code`, `stdout` and `stderr` (a child killed by signal N reports `128 + N`; output is decoded as lossy UTF-8), `process_pid()`, `core_count()` (artifact format 76; the number of processor cores, for sizing `parallel_map` on computing work) and `process_signal_poll()` and `process_stop_requested() -> Bool` (artifact format 90: true once an `INT`, `TERM` or `HUP` has arrived in a program that polls for signals; it stays true, does not clear the pending signal, is the same on every thread and is always false in the browser VM; no grant, effect `process.signals`). Starting a program is denied by default: the command name must be listed exactly in `guion.toml` `[process].commands` or passed with `guion run --allow-command NAME`; a grant for one command never covers another. The command starts without a shell from an argument list, with a cleared environment holding only `PATH` and the variables granted in `[environment]`, the project file root as working directory, and its own process group. `[process].timeout_ms` (default 30,000) and `[process].max_output_bytes` (default 16 MiB per stream) bound each call; exceeding either kills the whole group and returns `E_PROCESS_TIMEOUT` or `E_PROCESS_OUTPUT_LIMIT`. Other error codes are `E_PROCESS_DENIED`, `E_PROCESS_ARGUMENT` and `E_PROCESS_SPAWN`. `process_signal_poll()` installs `INT`, `TERM` and `HUP` handlers on first use, so those signals no longer end the program by themselves; it returns and clears the pending signal name, or `""`. Calls are synchronous: there is no way to leave a child running after the call returns. Static inspection reports `process.spawn` and `process.signals`, with a `process_grant` section.
- Background work (artifact format 76): `together:` is a block statement; inside it `start(function, argument)` runs `function(argument)` on its own thread and returns a task, `wait(task)` and `wait_within(task, ms)` return `Result[T, TaskError]` (`R_DEADLINE` and the task is stopped when `ms` passes), and when the block ends every task not waited for is stopped. `start` outside a block is `E_START_OUTSIDE_TOGETHER`; `return`, `break`, `continue` and `?` cannot leave a block (`E_TOGETHER_EXIT`); a task or channel cannot be returned, printed or kept in a variable declared outside its block (`E_SCOPE_ESCAPE`). Tasks have exactly the parent's grants and share its budgets. Channels: `let c: Channel[Int] = channel(8)` inside a block, `send(c, value)` (waits while full; `Result[Unit, TaskError]`), `receive(c)` (`Option[T]`; `None` once closed and empty), `close(c)`; a started function can take a `Channel[T]` parameter; `first_ready(tasks)` and `first_value(channels)` (they need `import "std:process"`) return `Ready(index, value)`: the position of the first ready item and its result, taken in the same step. For a task the value is what `wait` gives; for a channel it is what `receive` gives (`None` once the channel is closed and empty). The `_within` forms return `Option[Ready[T]]`. Background commands (`std:process`): `start_process(command, arguments)` returns `Result[Process, StdError]` (the same grant as `process_run`), `process_line(p)` gives `Option[Text]` (the next line of its output), `process_write(p, text)` and `process_close_input(p)` feed its input, and `process_wait(p)` gives `Result[ProcessResult, StdError]`; each command runs in its own process group and is stopped with everything it started when its `together:` block ends, when the program ends, or when `guion` is interrupted; a `Process` cannot be returned from its block (`E_SCOPE_ESCAPE`). `try_parallel_map(list, f, Workers(at_once=50, each_ms=5000, all_ms=30000))` (`Workers` from `std:process`) runs `f` over a list with per-item results and deadlines (`R_DEADLINE`). The `parallel_map` worker limit defaults to 64 and `[runtime] max_parallelism` raises it to 1024.
- Sockets (artifact format 57): `std:net` provides blocking TCP and UDP over integer-handle records `TcpConn`, `TcpListener`, `UdpSock`: `tcp_connect`, `tcp_listen`, `tcp_listener_port`, `tcp_accept`, `tcp_send`, `tcp_send_text`, `tcp_recv`, `tcp_close`, `tcp_listener_close`, `udp_bind`, `udp_port`, `udp_send_to`, `udp_recv_from` (a `Datagram` with `data`, `host`, `port`) and `udp_close`. `tcp_peer(conn: TcpConn) -> Result[PeerAddress, StdError]` (artifact format 90, `Net` function code 10) returns the other end of a connection as a `PeerAddress` with `host` and `port`: the client on an accepted connection, the server on one from `tcp_connect`, and for a TLS connection the same. An IPv6 host has no brackets and an IPv4-mapped IPv6 address (a dual-stack listener) is reported as the IPv4 address; a handle that is not a connected TCP or TLS socket is `E_NET_HANDLE`. It needs no grant beyond holding the connection, reports `network.socket`, is recorded on tapes like the sibling socket operations and is `R_HOST_UNSUPPORTED` in the browser VM. Everything else here is denied by default. Connecting and sending datagrams need an exact `host:port` (or `host:*`) entry in `guion.toml` `[sockets].connect` or `guion run --allow-connect`; listening and binding need one in `[sockets].bind` or `--allow-bind` (`127.0.0.1:0` allows an ephemeral port on loopback). The host name is matched as written, before resolution, so grant IP literals when the name could resolve elsewhere. Every connect, accept, receive and datagram receive takes a timeout of 1 ms up to `[sockets].timeout_ms` (default 30,000); reads are capped at `[sockets].max_read_bytes` (default 1 MiB) and at most 64 sockets may be open. A zero-length receive on TCP means the peer closed. Error codes: `E_NET_DENIED`, `E_NET_ARGUMENT`, `E_NET_RESOLVE`, `E_NET_REFUSED`, `E_NET_TIMEOUT`, `E_NET_IO`, `E_NET_HANDLE`, `E_NET_LIMIT`. Handles are shared between `parallel_map` workers: a handle opened by the program or by one worker can be used by another, several workers can wait in `tcp_accept` on one listener, and calls on the same socket from two workers take turns; sockets still open when the program ends are closed by it, not by a worker's end. Calls block the calling task until they finish or time out; a cancelled sibling task is noticed at the next call boundary, so cancellation latency is bounded by the timeout. Static inspection reports `network.socket` with a `socket_grant` section. TLS is not part of this module.
- TLS (artifact format 58): `std:net` adds `tls_connect(host, port, timeout_ms, extra_ca_pem)` and `tls_accept(listener, timeout_ms, certificate_chain_pem, private_key_pem)`, which return a `TcpConn` that `tcp_send`, `tcp_send_text`, `tcp_recv`, `tcp_close` and the port functions accept. TLS 1.2 and 1.3 only, through rustls with the ring provider. The client always verifies the server certificate and name against the bundled Mozilla roots plus any PEM certificates passed as `extra_ca_pem`; there is no option to skip verification. A rejected certificate returns `E_TLS_CERTIFICATE`, other handshake failures `E_TLS_HANDSHAKE`, bad PEM or a key that does not match `E_TLS_ARGUMENT`; timeouts and grants behave as for TCP (`E_NET_TIMEOUT`, `E_NET_DENIED`). A peer that closes without a TLS close notification surfaces as `E_NET_IO` on receive. Session resumption control and ALPN are not offered. Certificates and keys are PEM text, normally read with `read_text` under the file grant. Mutual TLS (artifact format 61): `tls_connect_with_identity(host, port, timeout_ms, extra_ca_pem, certificate_chain_pem, private_key_pem)` presents a client certificate, and `tls_accept_verified(listener, timeout_ms, certificate_chain_pem, private_key_pem, client_ca_pem)` requires one and verifies it against the PEM certificates in `client_ca_pem` only; a missing or untrusted client certificate fails the handshake on the server.
- HTTP server and WebSockets (artifact format 59): `std:crypto` adds `crypto_sha1` (SHA-1, kept for the WebSocket handshake and legacy interchange, not for new security uses) and `bytes_xor_key(data, key)`. `std:http_server` is written in Guion over `std:net`: `http_server_listen`, `http_server_accept`, `http_server_read_request(conn, timeout_ms, max_body_bytes)` returning an `HttpServerRequest` (`conn`, `method`, `target`, `path`, `query`, lowercase-named `headers`, `body`), `http_server_header`, `http_server_respond`, `http_server_respond_text` and `http_server_send`. `http_server_read_request` reads the first request on a connection and `http_server_respond` answers it and closes (`Connection: close`). For keep-alive, answer with `http_server_reply` or `http_server_reply_text`, which keep the connection open when the client asked for that (HTTP/1.1 does by default; `Connection: close` or HTTP/1.0 without `keep-alive` closes), and read the next request with `http_server_read_next(previous, timeout_ms, max_body_bytes)` or `http_server_read_request_from(conn, pending, ...)`; bytes that arrived after a request (pipelined requests) are carried in its `pending` field. `Transfer-Encoding: chunked` request bodies are decoded; a request that names both `Content-Length` and chunked framing, or any other transfer encoding, is refused. A client that closes between requests returns `E_HTTP_CLOSED`. The request head is limited to 16,384 bytes and 100 headers, and the body to the caller's limit; a protocol fault sends 400, 413, 431 or 501 and returns `E_HTTP_REQUEST_INVALID`, `E_HTTP_BODY_TOO_LARGE`, `E_HTTP_HEADER_TOO_LARGE` or `E_HTTP_UNSUPPORTED`. A connection from `tls_accept` works the same way, which gives HTTPS. `std:websocket` implements RFC 6455: `ws_server_accept(request)`, `ws_client_handshake(conn, host, path, timeout_ms, seed)`, `ws_receive(ws, timeout_ms, max_message_bytes)`, `ws_send_text`, `ws_send_binary`, `ws_send_ping`, `ws_send_close` and `ws_close`, with errors `E_WS_HANDSHAKE`, `E_WS_PROTOCOL`, `E_WS_TOO_LARGE` and `E_WS_CLOSED`. Client masks are derived from the connection seed and the payload, so pass an unpredictable seed. Socket handles are shared between `parallel_map` workers, so several workers can accept on one listener and serve connections at the same time; the HTTP server has no HTTP/2 and no `Expect: 100-continue` handling.
- Native arrays (artifact format 62): `Array[e]` is an n-dimensional, row-major array whose element type `e` is one of `i8`, `i16`, `i32`, `i64`, `u8`, `u16`, `u32`, `u64`, `f32`, `f64` or `bool`. These element types exist only inside `Array[...]`; elsewhere they are `E_TYPE_UNKNOWN` (``unknown type `f64`; element types are only valid inside Array[...]``). Inside `Array[...]`, a name that is not a type at all (`Array[i128]`) is `E_TYPE_UNKNOWN` (``unknown type `i128` ``), and a type that is not an element type (`Array[Int]`, `Array[Array[f64]]`) is `E_TYPE_ANNOTATION`. Both compilers report the same code and message for each of these errors. When one program has several type errors, each compiler reports the first one it finds and the two may find them in a different order (for `fn f(x: Array[i128]) -> Array[Int]`, the Rust compiler reports `E_TYPE_ANNOTATION` for the result first and the self-hosted compiler reports `E_TYPE_UNKNOWN` for `i128` first), so the first error reported can differ; once the errors are fixed one at a time the two agree. Every array has a runtime shape (a `List[Int]` of up to 32 extents); rank is not part of the type. Reading an element gives its scalar type (`Int` for integer elements, `Float64` for `f32`/`f64`, `Bool` for `bool`); writing takes that scalar type and checks that it fits. Conversion is explicit and checked: building from a list, storing, `array_to_<e>` and decoding bytes raise `R_ARRAY_CONVERSION` for a value outside the element type (float to integer truncates toward zero; `f64` to `f32` rounds to nearest; number to `bool` requires 0 or 1), and integer arithmetic outside the element range raises `R_ARRAY_OVERFLOW`, never wrapping. Float arrays never hold NaN or infinity; a kernel that would produce one raises `R_FLOAT_NONFINITE`. Arrays are values: `array_set` returns an updated array and `set a = array_set(a, i, v)` updates an unshared local in place. Arrays are limited by the allocation budget, not by `max_collection_items`. Builders, for each element type `<e>`: `array_<e>(List[S])` (rank 1), `array_<e>_full(shape, value)`, `array_<e>_zeros(shape)`, `array_to_<e>(array)` and `array_<e>_from_bytes(Bytes)` (little endian); plus `array_i64_range(start, stop, step)`, `array_f64_linspace(start, stop, count)` (both ends included), and `array_f64_random(seed, shape)` / `array_f64_normal(seed, shape)`, which continue the `std:random` SplitMix64 stream (`array_f64_random(s, [n])` gives the same values as `n` successive `random_next_float` calls from `random_new(s)`; normal values use Box–Muller over that stream). Inspection and access: `array_shape`, `array_ndim`, `array_size`, `array_equal`, `array_get(a, flat_index)`, `array_get_at(a, [i, j, ...])`, `array_set`, `array_set_at` (`R_ARRAY_INDEX` out of range). Shape: `array_reshape` (one extent may be -1), `array_flatten`, `array_transpose` (reverses the axes), `array_slice(a, start, end)` (axis 0), `array_concat` and `array_stack` over a `List[Array[e]]`, `array_to_list` (flat), `array_to_bytes`; a shape that does not fit raises `R_ARRAY_SHAPE`. A value the function does not accept (`array_clip` with `low` above `high`, `array_i64_range` with step 0) raises `R_ARRAY_ARGUMENT`; runtime messages name the guest function, such as `array_add overflows u8`. Arithmetic on numeric arrays of the same element type broadcasts by NumPy rules: `array_add`, `array_sub`, `array_mul`, `array_div` (integer floor division, as `//`; a zero divisor raises `R_DIV_ZERO`), `array_minimum`, `array_maximum`, the `_scalar` forms of the first four, `array_neg`, `array_abs` and `array_clip(a, low, high)`. Float arrays add `array_sqrt`, `array_exp`, `array_log`, `array_log10`, `array_log2`, `array_sin`, `array_cos`, `array_tan`, `array_asin`, `array_acos`, `array_atan`, `array_sinh`, `array_cosh`, `array_tanh`, `array_floor`, `array_ceil`, `array_round` and `array_pow(a, exponent)`, with the `std:math` domain errors; `f32` math is computed in `f64` and rounded. Comparisons `array_eq`, `array_ne`, `array_lt`, `array_le`, `array_gt`, `array_ge` and their `_scalar` forms return `Array[bool]`; `array_and`, `array_or`, `array_not`, `array_any`, `array_all` and `array_count` work on `Array[bool]`; `array_where(mask, a, b)` selects between arrays of one shape and `array_filter(a, mask)` keeps the masked elements as a rank-1 array. Reductions on numeric arrays: `array_sum` and `array_prod` (exact `Int` for integer elements, so they never overflow), `array_min`, `array_max`, `array_argmin`, `array_argmax` (first occurrence), `array_mean`, `array_var` and `array_std` (population; `Float64`, pairwise summation); `R_ARRAY_EMPTY` for an empty array except `sum` (0) and `prod` (1). By axis: `array_sum_axis`, `array_min_axis`, `array_max_axis` (same element type, checked) and `array_mean_axis` (`Array[f64]`). Ordering: `array_sort` and `array_argsort` (rank 1, stable; `argsort` gives `Array[i64]`) and `array_cumsum` (flat, checked). Linear algebra: `array_dot(a, b)` (rank 1, equal length; exact `Int` for integer elements) and `array_matmul(a, b)` (2-D by 2-D or 2-D by 1-D). Operands of a binary function must have the same element type; convert explicitly. `print` shows nested brackets by shape and summarises arrays of more than 1,000 elements; `==` compares element type, shape and contents. Arrays cross `parallel_map` workers but not the Python bridge. Grouping and joining (artifact format 63), all rank 1: `array_take(a, indices)` gathers by `Array[i64]` index (`R_ARRAY_INDEX` out of range); `array_factorize(a)` gives dense `Array[i64]` codes in first-seen order (floats compare by value, so `-0.0` and `0.0` share a code); for codes in `0..groups`, `array_first_index(codes, groups)` gives each group's first row (-1 for none), `array_count_by(codes, groups)` its row count, `array_sum_by`, `array_min_by` and `array_max_by(values, codes, groups)` its checked sum (0 for an empty group), minimum and maximum, and `array_mean_by` its `Array[f64]` mean; min, max and mean of an empty group raise `R_ARRAY_EMPTY`, a code outside `0..groups` raises `R_ARRAY_INDEX`, and a group count outside `0..2^32-1` or a length mismatch raises `R_ARRAY_SHAPE`. `array_join_index(left, right, keep_unmatched)` pairs rows with equal codes and returns one `Array[i64]` of length `2n`: the first `n` are left rows in left order, the last `n` the matching right rows in right order; negative codes never match, and with `keep_unmatched` a left row without a match pairs with -1. Strided views, fancy indexing, complex numbers, operator syntax on arrays and BLAS are not provided.
- General sorting (artifact format 65): `sort(values: List[T]) -> List[T]` for `T` in `Text`, `Int` or `Float64` and `sort_by(values: List[T], key: fn(T) -> K) -> List[T]` for `K` in `Text`, `Int` or `Float64` return a new list in ascending order and leave the input unchanged. Both are stable. `Text` compares by Unicode scalar value, the order in which `Map` keys iterate, so lists and maps agree for every scalar including those above U+FFFF. `Int` compares numerically. `Float64` uses a total order: `-0.0` sorts before `0.0` and a NaN, which the language never produces, would sort last. `sort_by` evaluates the key once per item, in input order, and orders by the saved keys. The key is a function value (see below). When it is the name of a function declared in the program it must be pure (`E_SORT_EFFECT`). Either way it takes one parameter of the list's item type and returns `Text`, `Int` or `Float64`; any other key type, such as `Bool` or `Unit`, and a `sort` of a list of any other item type, is `E_SORT_KEY`. A named function with two parameters passed to `sort_by` is the format-36 comparator `(T, T) -> Int`, unchanged. Each native comparison costs one instruction of the guest budget, as in `sort_by_int_key`. `sort_by_int_key` and `merge_sorted_by_int_key` keep their format-41 operations.
- Function values (artifact format 66): a function type is written `fn(Int) -> Int`, `fn(Text, Int) -> Result[Text, StdError]` or `fn() -> Unit`, and is valid anywhere a type is: a parameter, a `let` annotation, a record field, the item of a list or map, an `Option` or `Result` payload, a result type. A bare name in value position that is not a local denotes the function of that name (own module or imported), so `let f = double` has type `fn(Int) -> Int`; a local or parameter of the same name wins. A function value is called by name, `f(x)`; the arity and the argument types are checked against the type at check time (`E_CALL_ARITY`, `E_TYPE_ARGUMENT`). A function value is a named top-level function or a closure (format 74). `==` and `!=` on a function value, or on a list, record, map, option or result that holds one, is `E_FN_COMPARE`. A function value is an index into its artifact's function table, so a call through one uses the ordinary call frame and the call-depth and instruction limits apply (recursion through a value stops at the call-depth limit); an index that names no function of the running artifact is the runtime error `R_FN_INVALID`.
- Maps keyed by `Int` (artifact format 75): `Map[Int, T]` is a type distinct from `Map[Text, T]`, written `let m: Map[Int, Text] = {}` or as a literal with `Int` keys. `map_get`, `map_has`, `map_set`, `m[k]` and `len` take an `Int` key, and `for k in m` yields `Int` keys in ascending numeric order. It is stored under each key's decimal text, is not a `Map[Text, T]`, and `map_record_get`, `map_record_set` and the host and JSON boundaries refuse it. Any other key type is `E_TYPE_MAP_KEY`.
- Generic records (no format change): `record Pair[A, B]:` declares a record with type parameters, written `Pair[Int, Text]`. A constructor call infers the arguments from its fields, `Pair(1, "one")`, or you write them, `Box[Int](...)`; wrong or missing arguments are `E_GENERIC_ARITY`, and an argument the fields do not fix is `E_GENERIC_INFER`. Each set of arguments compiles to an ordinary record named `Pair<Int, Text>`, so generic functions may take and return them and nothing changes at run time.
- Named record arguments (no format change): a record constructor takes its fields by position, by name, or both: `Box(1, 2)`, `Box(height=2, width=1)`, `Box(1, height=2)`. Positional arguments come first and fill the first fields; the rest are `field=value` in any order. An unknown field, a field given twice or too many positional arguments is `E_CALL_KEYWORD` or `E_CALL_ARITY`, and a missing field is `E_CALL_ARITY` that names it. Values are evaluated in field order, not in the order written.
- Effects of function values: effects attach where a function value is formed. Writing `let f = writer_fn`, or passing `writer_fn` by name, adds the effects of `writer_fn` to the function that contains that expression, so `guion doc --json` and `guion inspect` report them for that function and for everything that calls it, and the effects stay visible across packages. Calling through a value adds nothing further, so a function that only receives a function-typed parameter and calls it reports no effects of its own. For example, `fn former() -> Int` containing `let f = writer_fn` reports `output.write` when `writer_fn` prints, although `former` never calls `f`; `fn caller(f: fn(Int) -> Int) -> Int` containing `return f(1)` reports none, and the function that passes `writer_fn` to `caller` reports `output.write`. A sort key that is a named function is still checked to be pure at the call site (`E_SORT_EFFECT`); a function-typed variable passed as a key is accepted and its effects belong to the place the value was formed.
- Serialization boundaries: a type holds a function if it is a function type or a record, list, map, option or result that holds one. Such a type is rejected at check time with `E_FN_NOT_SERIALIZABLE`, naming the boundary, when it reaches a builtin or standard-library function that converts or transports typed values: JSON, CSV and TOML conversion, SQLite parameters and results, process arguments and the environment, HTTP requests and responses, file reads and writes, and `print` and `eprint`. A function value never becomes an artifact constant. `parallel_map` is deliberately not a boundary: workers run the same artifact and function table, so an index means the same function in every worker, and the VM checks the index in the worker (`R_FN_INVALID`). An index cannot be written in source, so a program cannot forge one.
- Higher-order builtins (artifact format 66): `map_list(values: List[T], f: fn(T) -> U) -> List[U]`, `filter_list(values: List[T], f: fn(T) -> Bool) -> List[T]`, `fold_list(values: List[T], initial: A, f: fn(A, T) -> A) -> A`, `any_list(values: List[T], f: fn(T) -> Bool) -> Bool` and `all_list(values: List[T], f: fn(T) -> Bool) -> Bool` call the function once per item in order (`any_list` and `all_list` stop at the first deciding answer). A `Result` returned from the function is an ordinary value, so `map_list(xs, parse)` with `parse: fn(Int) -> Result[Int, Text]` gives a `List[Result[Int, Text]]`; a runtime error inside the function carries the callee's span first, then the builtin's call site. Each call is charged as a normal call. `sort_by`, `sort_by_int_key`, `merge_sorted_by_int_key` and `parallel_map` also take function values. A function of the wrong shape is `E_TYPE_ARGUMENT`.
- Logging (artifact format 70): `std:log` writes one JSON object per line to a file. `log_open(root: Text, level: Text) -> Result[Logger, StdError]` returns a `Logger` value holding the log file path (`root`, inside a granted file root, created if missing, appended to) and the minimum level; there is no global logger. Levels are `debug` < `info` < `warn` < `error`; an unknown level is `E_LOG_LEVEL`, a path outside the file grant is the file error `R_HOST_DENIED`, and an empty level takes `[log] level` from `guion.toml` (`info` when absent; any other value or key under `[log]` is a manifest error). `log_debug`, `log_info`, `log_warn` and `log_error(logger, msg: Text, fields: Map[Text, Json]) -> Result[Unit, StdError]` write `{"level":..,"msg":..,<fields in sorted key order>}`; a field named `ts`, `level` or `msg` is written as `field.ts`, `field.level` or `field.msg`. These never read the clock, so the record has no `ts` and its schema does not depend on grants. `log_info_at(logger, instant, msg, fields)` puts `"ts"` first from a caller-supplied `Instant`; `log_info_now(logger, msg, fields)` reads the clock and so carries the effect `clock.read`. Effects are enforced when an operation runs, not before the program starts: without the clock grant `log_info_now` fails with `R_CLOCK_DENIED` at the call and writes nothing, and `guion inspect --json` reports `clock_grant.required_for_entry`. A record below the logger's level returns `Ok` without reading or formatting its fields. Field values are `Json`, so newline, quote, NUL and other control characters are escaped and a record is always one line; a lone surrogate cannot reach a field because `json_parse` rejects it. Two instructions, `LogAppend` and `LogDefaultLevel`, are new; artifacts below format 70 that use them are rejected with `E_ARTIFACT_VERSION`.
- Compression and archives (artifact format 71): `std:compress` has `gzip_compress(data: Bytes) -> Bytes` and `zlib_compress(data: Bytes) -> Bytes`, `gzip_decompress(data: Bytes, max_output: Int) -> Result[Bytes, StdError]` and `zlib_decompress(data: Bytes, max_output: Int) -> Result[Bytes, StdError]`, and the streamed file forms `gzip_compress_file(source: Text, destination: Text) -> Result[Int, StdError]` (the compressed size) and `gzip_decompress_file(source: Text, destination: Text) -> Result[Int, StdError]` (the decompressed size); the file forms need the file-read and file-write grants (effects `filesystem.read` and `filesystem.write`), follow the `std:fs` path rules, stream through 64 KiB buffers and write the destination through a sibling temporary file renamed on success. Every inflate has an output ceiling: `max_output` for the in-memory forms, capped by `[runtime] decompress_limit_bytes` (default 1 GiB, a positive integer in `guion.toml`), which is the only ceiling of the file and tar forms. Output past the ceiling is `E_COMPRESS_LIMIT` after at most the ceiling has been produced, never a crash or an unbounded allocation; a negative `max_output` is `E_COMPRESS_ARGUMENT`; short or empty input is `E_COMPRESS_TRUNCATED`; a bad header, checksum or deflate data is `E_COMPRESS_CORRUPT`. A gzip input may hold several members and the output is their concatenation (the ceiling counts them together); bytes after the last gzip member that do not begin another member (zero padding included), or after a zlib stream, are `E_COMPRESS_TRAILING_DATA`, never ignored. `std:tar` has `tar_write(directory: Text, archive: Text) -> Result[Int, StdError]`, `tar_read(archive: Text, destination: Text) -> Result[Int, StdError]` and `tar_list(archive: Text) -> Result[List[Text], StdError]`. `tar_write` archives the directory's contents with names relative to it, sorted, with fixed metadata (so the same tree gives the same archive), gzip-compressed when the archive name ends in `.gz` or `.tgz` (what `tar -tzf` reads) and plain otherwise; a symbolic link in the tree, or an archive path inside the directory, is `E_TAR_UNSAFE_PATH`. `tar_read` and `tar_list` detect gzip by its magic number. `tar_read` applies the `std:fs` confinement rules to every entry: an absolute name, a `..` component, or a link whose target is absolute or contains `..` is `E_TAR_UNSAFE_PATH`, device and FIFO entries are `E_TAR_UNSUPPORTED_ENTRY`, and a damaged archive is `E_TAR_CORRUPT`; entries before a refused one stay extracted. The bytes extracted and inflated are capped by the same ceiling. The crates behind it are `flate2` (its pure-Rust `miniz_oxide` backend) and `tar`, in the runtime only; the browser VM gains nothing. New instructions `GzipCompress`, `GzipDecompress`, `ZlibCompress` and `ZlibDecompress` and `Fs` function codes 13 to 17; artifacts below format 71 that use them are rejected with `E_ARTIFACT_VERSION`. zstd is not part of this release.
- Standard input (artifact format 77): `std:io` has `stdin_read_line() -> Result[Option[Text], StdError]` and `stdin_read_all() -> Result[Bytes, StdError]`, which read the program's own standard input. `stdin_read_line` returns the next line without its `\n` or `\r\n` as `Some(line)`, and `None` at the end of input; a final line with no terminator is returned. A line longer than `[runtime] stdin_line_limit_bytes` (a positive integer in `guion.toml`, default 1048576, counted without the line ending) is `E_STDIN_LINE_LIMIT` and a line that is not UTF-8 is `E_STDIN_UTF8`; either one consumes the whole offending line, so the next call reads the line after it. A failing read is `E_STDIN_READ`. `stdin_read_all` returns everything left as raw `Bytes`, at most `[runtime] max_file_bytes`; more is `E_STDIN_LIMIT`. Both calls wait for input or for the stream to close, share one buffered stream (a line read and a later `stdin_read_all` never read a byte twice), need no grant, and are reported by `guion inspect` as the effect `process.stdin`. `guion run --record` keeps what was read, so `--replay` needs no stdin. The browser VM refuses both with `R_HOST_UNSUPPORTED`.
- Pure crypto (format 78 to 87; format 82 adds `dagcbor_encode` to `std:encoding`): `std:crypto` adds SHA-512 and SHA3-512 and, from format 79, `crypto_rsa_verify`, `crypto_ecdsa_p256_verify`, `crypto_x509_rsa_public_key`, `crypto_pem_decode` and `crypto_bls12381_verify_g1` and, from format 81, drand timelock encryption in age format (`crypto_tlock_encrypt`, `crypto_tlock_decrypt`, `crypto_tlock_round`) and, from format 84, `crypto_tlock_chain_hash` and `crypto_x509_verify_issued_by` (one X.509 issuer link: RSA PKCS#1 v1.5 or PSS, ECDSA P-256 or P-384, SHA-256, SHA-384 or SHA-512; any other algorithm is `E_X509_ALG`) and, from format 85, `crypto_x509_dns_names` and `crypto_x509_validity` and, from format 86, pure Ed25519 as in RFC 8032: `crypto_ed25519_public_key(seed)`, `crypto_ed25519_sign(seed, message)` (deterministic; the 32-byte seed comes from `crypto_random_bytes(32)`) and `crypto_ed25519_verify(public_key, message, signature)` (strict: small-order keys and non-canonical `R` or `S` are `Ok(false)`; a wrong length or a key that is not a curve point is `E_CRYPTO_INPUT`) and, from format 87, RFC 3161 trusted timestamps: `crypto_tsa_request(digest, nonce)` (a DER request for a 64-byte SHA-512 digest and an optional nonce of at most 32 bytes whose first byte is 0x01 to 0x7f; `E_TSA_DIGEST`, `E_TSA_NONCE`), `crypto_tsa_response_token(response)` (the token of a granted response; a refusal is `E_TSA_STATUS`, an unreadable one `E_TSA_FORMAT`), `crypto_tsa_verify(token, digest, tsa_cert, issuer_cert) -> Result[Option[TsaToken], StdError]` (`Some` only for a token of this digest signed by exactly the pinned TSA certificate, issued by the pinned issuer, with the `timeStamping` key usage and valid at the token's `genTime`; otherwise `None`; `E_TSA_ALG` for an algorithm or TSA key outside RSA PKCS#1 v1.5, RSA-PSS and ECDSA P-256 or P-384 with SHA-256, SHA-384 or SHA-512; `E_TSA_DIGEST` for a digest that is not 64 bytes) and `crypto_tsa_certificates(token)`, with `record TsaToken: gen_time_ms, accuracy_ms, serial, policy, nonce` (`Result[_, StdError]`; a bad signature is `Ok(false)`). No grant.
- Bit operations and visible errors (artifact format 83): `int_and`, `int_or`, `int_xor`, `int_shift_left` and `int_shift_right`, each `(Int, Int) -> Int`, work on 64-bit two's-complement values (they ride on the `Codec` instruction, codes 15 to 19, and run in the browser VM too). An operand outside the signed 64-bit range is `R_INTEGER_RANGE`; a shift count below 0 or above 63 is `R_SHIFT_RANGE`. `int_shift_right` is arithmetic (it copies the sign bit); `int_shift_left` does not wrap, so its result is the exact product with a power of two. An artifact below format 83 that uses one is `E_ARTIFACT_VERSION`. `StdError` (declared in `std:http_types`, no format change) is visible wherever a standard-library module returns it: each such module has `pub import "std:http_types"`, as `std:http` always did, so `import "std:crypto"` is enough to write `StdError` in a signature (`import "std:types"` still works, and importing it through two routes is not a clash). `std:types` still holds `std_error(code, message)`.
- Request and response values: `std:http_response` (no format change) holds `Header`, `Request`, `Response`, `Body` and `Stream` values with the constructors and accessors listed in the signatures below; a header name that is not an HTTP token or a value with a control character other than tab is refused with `E_HTTP_HEADER_INVALID`. `Request` has a seventh field `peer: Text` (artifact format 90): the client's address as `host:port`, an IPv6 host in brackets (`[::1]:4000`), and empty when unknown; `request_new` sets it to `""`. `std:http_server` adds `http_request_value(request) -> Result[Request, HttpFailure]` (which fills `peer` from the connection), `http_server_peer(request: HttpServerRequest) -> Result[PeerAddress, StdError]` and `http_server_send_response(request, response) -> Result[Unit, HttpFailure]`, so a handler `fn(Request) -> Result[Response, HttpFailure]` names no socket. Details are in `docs/reference.md`. No new function names a handle type.
- Cookies: `std:cookie` (no format change): `cookie_parse(header) -> Map[Text, Text]` never fails (malformed pairs dropped, values percent-decoded, first repeat wins). `Cookie(name, value, http_only, secure, same_site, path, domain, max_age: Option[Int], expires: Option[Instant])` comes from `cookie_new` (HttpOnly, `SameSite=Lax`, Secure off) and the setters `cookie_http_only`, `cookie_secure`, `cookie_same_site`, `cookie_path`, `cookie_domain`, `cookie_max_age`, `cookie_expires`; `cookie_serialize`, `cookie_parse_set` and `response_add_cookie(response, c)` finish the round trip. Bad names, attributes or a negative `Max-Age` are `E_COOKIE_*` `HttpFailure` values; `SameSite=None` without `Secure` is `E_COOKIE_SAMESITE_NONE_NEEDS_SECURE` at run time.
- Request bodies: `std:http_body` (no format change): `form_parse` and `multipart_parse` with exact `BodyLimits` (over is a 413 naming the limit); uploads get random names under a caller root, never the client name.
- YAML (artifact format 72): `std:yaml` has `yaml_parse(text: Text) -> Result[Json, StdError]`, a read-only reader for a small subset of YAML, written for configuration files such as CI workflows, Docker Compose files and Kubernetes manifests; there is no writer, and `std:toml` and `std:json` cover output. It reads one document: block mappings and block sequences, plain, single-quoted and double-quoted scalars, literal `|` and folded `>` block scalars (with the `+`/`-` chomping and indentation-digit indicators), flow sequences and mappings, comments, and nesting up to 64 levels, with an optional leading `---` and trailing `...`. Mapping keys are always text. A plain scalar is text except the lowercase `true` and `false` (booleans), `null` and `~` (null), and an integer or decimal that reads back unchanged (`42`, `-7`, `2.75`); `NO`, `yes`, `on`, `Null` and `1.10` (which would lose a digit as a number) stay text, as do `007`, `1e3`, `0x1F` and integers beyond 64 bits, and every quoted scalar is text. Anchors, aliases, tags, the merge key `<<`, complex `?` keys, directives and multi-document streams are rejected with `YAML_UNSUPPORTED`, the message naming the feature, and no partial value is returned. Other errors are `YAML_SYNTAX` (bad indentation, a tab used for indentation, an unterminated quote or flow collection, an invalid escape), `YAML_DUPLICATE_KEY` and `YAML_LIMIT`; every error carries the 1-based `line` and `column` in its `StdError`. The reader needs no grant and is a single new instruction, `YamlParse`; artifacts below format 72 that use it are rejected with `E_ARTIFACT_VERSION`, and formats 14 through 71 still load.
- INI is declined. `std:toml` reads and writes the same kind of configuration better, INI is a declining format whose dialects (comment characters, quoting, repeated keys, sections without values) cost more to pin down than they repay, and no measured task class needs it. The decision is recorded here so it is not reopened without new evidence of such a task.
- CSV into columns (artifact format 64): `csv_read_columns(path: Text, kinds: Map[Text, Text]) -> Result[List[Record[CsvColumn]], FileError]` reads a whole CSV file into typed columns and needs the `files` read capability, as `csv_open` does. `std:csv` declares `record CsvColumn` with `name: Text`, `kind: Text` (`"i64"`, `"f64"`, `"bool"` or `"text"`), `ints: Array[i64]`, `floats: Array[f64]`, `flags: Array[bool]`, `codes: Array[i64]`, `dictionary: List[Text]` and `valid: Array[bool]`. Only the storage for the column's kind has the column's length (for text, `codes` and `dictionary`); the other arrays are empty. `valid` is true where a value is present; a missing row holds 0, 0.0, false or code 0. The first record is the header; a leading UTF-8 byte-order mark is dropped and blank lines are skipped, except that in a file whose header has one column a blank line is a missing value; fields are split and quoted exactly as `csv_next` does, and a record with the wrong number of fields fails with `R_CSV_MALFORMED` and its line. A column not named in `kinds` takes the first of `i64`, `f64`, `bool`, `text` that holds every present value: `i64` is an integer within the i64 range (a larger one makes the column `f64`), `f64` is what `text_parse_float` accepts, `bool` is exactly `true` or `false`, and a column with no present value is `text`. An unquoted empty field is missing; a quoted empty field (`""`) is missing in a numeric or `bool` column and is the empty text in a `text` column, and does not force a column to `text`. `kinds` fixes a column's kind by name; a value that does not fit fails with `E_CSV_VALUE`, its line and 1-based column, and the message ``column `NAME`: `VALUE` is not KIND``; a name in `kinds` that is not in the header, or an unknown kind, fails with `E_CSV_VALUE` on line 1. Text codes are dense, in first-seen order. The file is streamed and is not checked against `max_file_bytes`; each record is held to that limit, and every array, list and text produced, including transient buffers, is charged to the allocation budget. `csv_open`, `csv_next` and `file_open_lines` stream the same way and no longer check the whole file against `max_file_bytes`; `read_text`, `read_bytes` and other whole-file reads still do. An `R_ALLOCATION_LIMIT` message ends with the setting that raises it, `allocation_limit_bytes` under `[runtime]` in `guion.toml`.
- Runtime and compile errors preserve source spans. Format-17 artifacts add Bytes values and byte file operations; format-18 artifacts add source-level Python keyword calls; format-19 artifacts add HTTP GET and `HttpError`; format-38 artifacts add byte HTTP; format-39 artifacts add explicitly granted clock access; format-16 metadata carries source and dependency-lock provenance; format-15 metadata and format-14 artifacts remain readable. Runtime combines recorded ceilings with host policy by taking the stricter value. The bytecode is an implementation detail apart from the versioned artifact boundary.

## Contracts for planned surfaces

These rules are design commitments for the approved build; the source compiler must continue to reject unsupported constructs. A surface becomes available only when it has parser/type/runtime and acceptance coverage.

- Arbitrary-precision integer arithmetic remains exact subject to a configured digit ceiling. Division by zero is currently a traced runtime error; a future checked division API may expose this as a typed `Result`.
- Text is UTF-8. Length and indexing count Unicode scalar values, not bytes or grapheme clusters. Indexing is zero based and out of range is an error. `text_slice` uses half-open Unicode scalar ranges with checked bounds. `text_find(text, needle, start)` returns the scalar index of the first match at or after `start`, or -1. Byte-oriented operations use `Bytes` explicitly. Normalization is not implicit; equality compares exact scalar sequences.
- Lists and maps are immutable values. `list_push`, `list_set`, and `map_set` return updated copies; `list_set` addresses an existing zero-based index. `Map[Text, T]` is the initial map form; iteration is in Unicode scalar lexicographic key order. Updating a collection returns a new value. Records have declared named fields, exact field types, and structural equality; unknown fields are errors at construction/deserialization. Mutable sharing across workers is not supported.
- `Option[T]` has `None` and `Some(value)`; `Result[T, E]` has `Ok(value)` and `Err(error)`. Absence and failure are distinct. `Some(value)`, `None`, `Ok(value)` and `Err(error)` build a value wherever its type is known from where it goes: a function's return, an annotated `let` or `var`, a `set`, a function or record argument, a list or map element, or another constructor (`return Ok(None)` and `return Ok(Some(x))` in a function returning `Result[Option[T], E]`, `Some(Ok(x))`, `Box(Some(1))`, `let held: List[Option[Int]] = [Some(1), None]`). `Some(value)` with nothing else to go on takes its type from the value (`let s = Some("hi")` is `Option[Text]`). Where the type cannot be known, such as `let value = None` or `let value = Ok(1)`, it is `E_OPTION_CONSTRUCTOR_CONTEXT` or `E_RESULT_CONSTRUCTOR_CONTEXT`, and the message says to write the type where the value is bound (`let value: Option[Int] = None`); a constructor where another type is expected (`return None` in a function returning `Int`) is the same code, naming the expected type. No artifact format change: a constructor of the enclosing function's own result type is one instruction as before, and any other is a call to a small hidden function the compiler adds once per type. Inspect options with `is_some` and `unwrap`, which reports absence as a runtime error. Postfix `?` unwraps an `Ok` or returns its `Err` from the current function; the error type must match the function's declared `Result` error type. A function still writes `Ok(value)` around a successful return expression. A `match` statement must cover exactly one `Some` and one `None` arm for an `Option`, or one `Ok` and one `Err` arm for a `Result`. The bound name is visible only in that arm; arm order is unrestricted. Nested patterns are described under statements above; a wildcard arm at the top level, other type matches and match expressions are not implemented. A name inside `Some`, `Ok` or `Err` that equals a declared enum variant is that variant, not a binding. An enum variant pattern on a value of another type is `E_MATCH_TYPE`. No implicit exception-to-Result conversion occurs. Current host results cover file operations, JSON parsing, and `parallel_map`; inspect them with `is_ok`, `unwrap`, and `error`.
- The executable import forms are `import "relative-path.gu"` and `pub import "relative-path.gu"`. Every imported module contributes its `pub fn` and `pub record` declarations to its direct importer; `pub import` also exposes those declarations through the importing module to downstream importers. Private declarations can still call their own module's private functions and direct imports. Names are imported unqualified. Ambiguous public names from multiple direct imports are rejected at the conflicting import; private declarations are qualified internally and remain module-local, even when different modules use the same helper name. Absolute paths, `.`/`..` components, missing files, root escapes and cycles fail before execution. CLI project builds resolve one module graph from the entry file and store per-file source identifiers in artifacts; diagnostics and runtime traces point to the originating module. External declarations specify a Python module/callable and typed signature; calls are dynamically validated and remain opaque effects. Calls may use positional arguments followed by named arguments matching the declaration's parameter names; positional calls to Guion functions remain positional. Omitted external parameters are passed through as omitted for Python defaults. Details of the Python wire boundary are in [python-abi.md](python-abi.md).
- Public functions and externally visible records require annotations. Locals infer from their initializer and cannot silently change type. Besides `List`, `Map`, `Option` and `Result`, user code has generic functions (`fn first[T](...)`) and generic records (`record Pair[A, B]:`), written `Pair[Int, Text]`: a constructor call infers the arguments from its fields or you write them, wrong or missing arguments are `E_GENERIC_ARITY`, an argument the fields do not fix is `E_GENERIC_INFER`, and each set of arguments is compiled to an ordinary record named `Pair<Int, Text>`, so there is no run-time or artifact-format change.

`json_parse(text) -> Result[Json, JsonError]`, `json_stringify(json) -> Text`, `json_stringify_pairs(groups, key_field, value_field) -> Text`, `json_get(json, key) -> Json`, `json_index(json, index) -> Json`, `json_has(json, key) -> Bool`, `json_len(json) -> Int`, `json_as_text/int/float/bool(json)`, and `json_is_null(json)` are available. `json_stringify_pairs` streams a `Map[Text, List[Text]]` into a JSON array of two-field objects in sorted map-key order and list order, escaping field names, keys, and values without constructing an intermediate JSON tree. It requires distinct field names and observes the configured row, text, and allocation limits. JSON construction in artifact format 20 adds `json_null()`, `json_bool(Bool)`, `json_int(Int)`, `json_float(Float64)`, `json_text(Text)`, `json_array()`, `json_object()`, `json_push(Json, Json)`, and `json_set(Json, Text, Json)`. These APIs build immutable JSON values; push and set return updated copies and reject a value of the wrong container kind. Constructors enforce the same nesting, collection, text and integer limits as parsed JSON. `json_as_float` explicitly converts a JSON number to finite `Float64`. Malformed JSON and duplicate object keys return `Err(JsonError)` with a stable code, message, line, and byte column, inspectable through `json_error_code/message/line/column`. Use `unwrap(json_parse(...))` when invalid input should stop the program. Resource-limit failures and invalid typed access still raise runtime errors. The Result-returning accessors that do not stop the program are `json_try_get`, `json_try_index`, `json_try_get_text`, `json_try_get_int`, `json_try_text`, `json_try_int`, `json_try_bool` and `json_try_float`, with the `_safe` names in `std:json`, plus `json_int_list_safe(value) -> Result[List[Int], JsonError]` there (`E_JSON_SHAPE` for a non-array or non-object, `E_JSON_MISSING` for an absent key, `E_JSON_TYPE` for a wrong-typed value).

Artifact format 29 adds `json_int_column(rows: Json, field: Text) -> List[Int]`, `json_text_categories(rows: Json, field: Text) -> Json`, and `json_as_int_list(values: Json) -> List[Int]`. Format 30 adds `json_project_columns(source: Text, rows_path: List[Text], field_names: List[Text]) -> Result[Json, JsonError]`, which streams through a JSON document and retains only the requested row fields as column arrays, plus `json_text_categories_values(values: Json) -> Json` for stable first-seen categorization of a projected text column. The projection still validates JSON and duplicate keys throughout ignored data, checks collection, integer and nesting limits, requires an array of row objects at the selected path, and reports missing or duplicate requested fields as `JsonError`. Projected values remain JSON values; use `json_as_int_list` or normal JSON accessors to convert them. Bulk conversion and projection remove per-row source-level JSON access work, but do not imply that Guion is faster than Python for every workload.

The CLI uses the value returned from `main`: `Int` becomes the process exit status and must be between 0 and 255; `Unit` exits successfully with status 0. Runtime failures and invalid exit values produce a nonzero status. `write_text_atomic(path, content) -> Result[Unit, FileError]` is available in artifact format 21. It writes a temporary sibling file and renames it over the target, preventing readers from seeing a partial replacement. Missing reads return `R_FILE_NOT_FOUND`; permission failures return `R_FILE_PERMISSION`. Atomic replacement does not lock read-modify-write sequences, and it does not promise that a completed rename survives sudden power loss.

Host capability signatures and operational limits are recorded in [host-api.md](host-api.md). Unimplemented signatures and types are proposals, not working APIs.

## Product profiles, imports, resources and lock migration

- The default `core` profile contains the Guion compiler, runtime and shipped standard library. Core commands do not discover, install, launch or bundle Python or `uv`. Existing external declarations remain representable in source, but a core build reports a requested external call as unavailable. Python interoperability is an explicit optional `python-interop` profile and is never selected by default.
- Relative imports resolve within the project or package root. `std:<name>` resolves only to the verified, version-matched standard library shipped with the selected compiler. `pkg:<name>/<path>` resolves only through the project's dependency lock and managed package cache; it never falls back to the Guion development checkout or the caller's current directory. Import resolution preserves the existing file, depth, size and root-escape limits.
- Native resources such as `FileReader`, `Db`, `Transaction` and `TomlDocument` are opaque runtime-owned handles. Programs cannot forge, serialize, bridge or pass them to parallel workers. A handle is valid only for its creating runtime invocation and resource kind. Closed, stale or foreign handles return typed errors. The runtime closes remaining resources at invocation end and rolls back open transactions on failure or cancellation.
- Existing Python-profile `guion.lock` files remain readable and are not silently reinterpreted or overwritten. `guion update --migrate-python-lock` is the explicit migration path to the versioned profile-aware lock format. Migration validates the complete old lock and resolves the resulting graph before publishing an atomic replacement; any failure preserves the old lock and runnable environment. The migrated profile remains `python-interop` until the project explicitly selects `core` and removes dependencies that require Python interoperability.
- Core and `python-interop` profile identity, compiler identity, standard-library identity and resolved package content identities are recorded in locks and artifacts. A build that requests an unavailable profile or package fails with a diagnostic before execution; it does not substitute another compiler, standard library or dependency source.
